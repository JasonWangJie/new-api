## 跨平台图片混合调度（2026-10-23，待提交，未发布）

后台图片策略和渠道池新增“混合调度”，在同一授权分组、公开模型和池绑定内，将具备 `openai_images` 适配能力的图片渠道统一加权，已取消火山 45／NewAPI 60 的类型白名单。OpenAI、Ali 等其他已注册渠道可以手动入池，仍按实际模型、请求参数、参考图和数量能力筛选；Gemini 原生协议、视频和未声明生图能力的渠道不会仅凭同名模型入池。公开生图 API 不新增字段：显式 `provider` 保持固定平台；省略 `provider` 且命中启用的混合池才进入混池，没有绑定时继续旧路由，空绑定或全部成员不可用时不越池回退。历史池和任务不迁移；混合任务可对明确未受理失败、符合[同步 502 失败条件](wiki/03-异步图像系统.md#image-sync-upstream-502-retry-20261024)的响应，以及符合[终态失败重试条件](wiki/03-异步图像系统.md#image-reference-timeout-retry-20261024)的失败进行原池安全重选，受理未知时保留预扣等待核对，仍在执行的上游任务固定原渠道。

混合任务的公开别名价格、表达式和分组倍率保持冻结，Ali 等供应商的数量及提示词扩展倍率不额外改写用户价格；按张价和表达式仍按实际结果数量结算，普通固定平台请求保留原计费规则。`openai_images` 是网关图片适配链路类型，上游可以同步返回图片，也可以提交异步任务。新增取消白名单的验证见[本月台账](wiki/10-2026年10月代码变更台账.md#mixed-image-unrestricted-20261023)。

混合请求在选择渠道前冻结公开别名价格，按该计费表达式实际需要的用量字段筛选成员；不能返回所需真实用量的渠道不会参与本次请求的加权。遮罩编辑只进入支持并能保留遮罩的渠道，预检与发送复用 JSON 参数准备及 Ali 编辑投影，避免参数在转换或覆盖后丢失。仍在运行的上游任务及完成快照继续恢复原渠道，不重新准入或重提；确认失败后的窄例外见上述终态失败重试条件。修复验证见[本月台账](wiki/10-2026年10月代码变更台账.md#mixed-image-smoke-fixes-20261023)，仍未发布。

## 功能概览

### 异步图像、图库与图像广场

- 任务详情记录实际重试动作、停止原因、预算和下次执行时间；管理员可按需查看默认保留 24 小时的加密失败请求诊断。每个渠道可覆盖参考图传输方式，账号瞬时失败默认冷却 60 秒，同一供应商来源共享容量 10、60 秒从空补满的重提交令牌桶。等待不消耗任务尝试，已受理任务继续轮询。管理员任务中心按完整筛选范围展示首次提交、重试、换号和本机参考图回退的恢复样本，完整菜单路径、逐项保存步骤、JSON 字段、权限、排查与接口见[重试决策、失败请求与恢复统计](wiki/03-异步图像系统.md#重试决策失败请求与恢复统计)。当前修改未部署，实际线上收益需运行后观察。
- 异步图片精确识别参考图网络失败、供应商明确服务超时和渠道池暂不可用；瞬时失败优先换到健康兼容账号，无备用时保留原账号的有限退避。上游任务只有明确终态失败才可解除旧绑定重提；轮询异常不消耗提交预算，整体期限或无法确认的查询错误保留资金等待核实。
- 成功响应先写入现有加密请求信封，后续下载和账单使用独立上下文；进程中断、本地处理失败及人工恢复复用原结果、真实用量、冻结价格和首次成功计价时间，不重新生图或重复预扣。恢复记录最多 32 MiB，MySQL 同时按当前会话报文上限的一半收紧；更大响应仍可在当前调用完成，未保存且本地处理失败时按未知执行处理。详情见[异步图像系统](wiki/03-异步图像系统.md)。
- 明确的参考图拉取失败即使没有 Google `INVALID_ARGUMENT` 字段，也按已配置的回退模式安排一次同账号本机下载重试；之后保留原重试与换号预算。上游提示词长度超限归入 `604` 并保留实际限制说明，不自动截断提示词。派发前未知错误保留脱敏准备诊断，真实上下文/网络超时执行有限重试。

- 新增兼容多种图像请求格式的异步提交与查询接口。
- 新增图像工作台、用户及管理员任务中心、任务详情和结果展示。
- 图像工作台使用受视口约束的纵向布局；选择模型后动态展开的质量、输出格式、背景和图片数量等参数保持在页面滚动区内，生成按钮不会被页面底部裁掉。
- 新增图像对象存储、签名 URL、清理、失败处理、渠道路由和计费衔接。
- 异步生图 outbox 按秒级节拍投递到 Redis；上游已接单后保持“处理中”展示，轮询间隔会释放执行租约，不再等待完整租约超时。
- Gemini 异步上游失败会在读取兼容层归一化结果前提取并脱敏原始 `error.message`，据此区分 611–613；供应商错误码、状态和 request ID 随管理员可见的渠道尝试记录保存，普通用户仍只看到安全的失败说明。
- 新增个人图库、图像广场、发布申请、举报、内容审核及管理员清理能力。
- 新增 Token 图像平台分组配置、图像运行配置、存储配置和权限资源。
- 图片平台策略在模型能力输入区提供当前平台的 JSON 配置示例；Gemini、Vertex AI 及其他已注册图片平台使用对应模板，示例可在弹窗中一键复制且不会覆盖当前表单。
- 渠道池按分组和平台加载可执行模型及已启用渠道，模型与渠道 ID 通过下拉多选配置；编辑已有绑定时自动回填模型、渠道和权重，服务端会拒绝能力不匹配的渠道。
- 图片和视频的显式渠道池改用池内“权重”分配请求，覆盖渠道页面的全局优先级和权重。10、9、8 分别约占 37.0%、33.3%、29.6%；当前可用候选全部为 0 时平均随机分配，有正权重时排除零权重候选。旧配置数值直接作为权重，历史负值按 0 处理；新保存范围为 0–1000000，没有新增数据库字段。
- 已保存的图片策略与渠道池绑定支持确认删除，删除期间禁止重复提交，失败保留配置。删除策略保留渠道池；删除绑定移除其中所有渠道行并恢复自动选择，停用绑定仍应保存空渠道列表。
- 生图渠道可在路由策略中声明最大参考图数量；参考图超过 8 张时优先选择容量覆盖请求的渠道，未配置的旧渠道继续按 8 张处理。全局默认上限和模型策略示例均为 14 张。
- 图像运行设置将全局最大参考图数量作为普通表单项；工作台只展示模型策略与全局上限的较小值，具体模型上限由平台策略声明，不再按 Flash 模型名隐藏固定为 3 张。Gemini 的“上游拉取失败后转本地”会在首次请求直接传递外部 URL，只有 SC/内嵌引用、本地模式或上游拉取失败后的重试才由服务器下载。参考图不再受合计字节数/像素数限制，但单图字节数、单图像素数和数量上限仍保留；短小尾随数据只在完整解析终止标记并再次解码后被安全裁剪，格式/超限错误会指出第几张参考图且不再重试。
- 部分 Gemini 兼容渠道在无法拉取远程参考图时只返回 `400 / INVALID_ARGUMENT`，甚至复用安全策略文案。启用“上游拉取失败后转本地”且首次请求确实包含远程 `fileData` 时，这类模糊响应会保留原始脱敏诊断并最多追加一次本地下载重试；明确的数量超限、缺图和参数错误仍直接失败。重试成功后会清空任务顶层的旧错误，首次失败诊断继续保留在管理员尝试审计中。高级运行配置继续保存严格 JSON，不接受注释；编辑器下方的可折叠字段说明表覆盖全部运行字段、用途和当前值，并支持七种前端语言。
- OpenAI 异步编辑保留新提交请求的 multipart 文件传输格式，按图片真实格式填写文件扩展名和 MIME，不再把上传文件统一改成 JSON 或标记成 PNG；旧 `_oa` multipart 入口正确保留 `watermark=false`，掩码不占参考图数量上限。JSON URL 请求继续发送标准 `images[].image_url`。OpenAI 异步 HTTP 失败保留脱敏后的供应商错误说明、错误码和 request ID；渠道状态码映射仍控制重试分类，尝试审计记录真实 HTTP 状态。具体范围与验证见[异步图像说明](wiki/03-异步图像系统.md)。
- 渠道可选配置 `upstream_async.profiles`，按映射后的上游模型、图片/视频类型和生成/编辑/延长操作动态提取任务号、构造 GET/POST 查询并解析状态、进度、失败原因、结果 URL 和实际用量。图片异步接口支持多个结果，命中规则的同步图片请求不会误把任务回执当作结果。
- 上游异步规则的提交请求可选择沿用渠道适配器或任务插件，也可在 `submit.request` 指定同源 POST 路径、查询参数、请求头与 JSON 模板；图片任务可由此映射至供应商的非标准提交端点，例如 Mai Token 的 `/v1/videos`。模型能力、计费和任务调度仍须正常配置。
- 上游提交返回任务号后，图像 worker 会从当前租约中的任务读取最新版本再保存上游任务号，避免提交前的版本快照使任务错误进入 `execution_unknown`；带参考图的生成请求会保持客户端的 `generate` 操作以命中渠道规则。异步图片结果传输短暂中断时继续查询已保存的上游任务并在原重试预算内重试下载，公开查询地址使用 GET。
- 异步图片结果下载遇到 HTTP 408、429、5xx 或传输中断时，继续轮询已保存的上游任务并在瞬时失败预算内重试；同源鉴权下载端点跳转到公网 CDN 时，后续请求清除渠道凭据并重新校验目标地址。
- 动态上游图片下载重试耗尽后，未配置下载头且全部结果为公网匿名链接时，按任务冻结的价格、分组倍率和实际结果张数结算，成功后返回原链接并标记 `result_source=upstream`、`status=succeeded`。Token 计费仍要求真实用量；余额不足或消费日志失败时暂不公开链接，恢复不会重复生成或扣费。未知实际尺寸使用原请求规格计价，本站图库归档仍要求媒体落盘并校验。
- 上游已接单图片任务的重复轮询不再逐次添加相同阶段和渠道尝试；收到结果只保留一条结果里程碑，后续更新链接复用该记录，同时清理已投递的旧轮询命令。历史任务详情会折叠重复阶段，历史数据库记录不自动清除。
- 动态上游查询只允许相同协议、主机和有效端口的 HTTP 跳转，同时保留原 HTTP 客户端的访问限制，跨源跳转停止以保护渠道凭据。模板变量值按一次替换写入，不会再次解释值中的占位符；已结束且过期的图片任务详情不再展示上游回退链接。
- 管理员任务详情的参考图区域提供「全部复制」：一次性把全部可访问的参考图 URL 按行复制到剪贴板；内嵌图不会进入复制内容。

- 工作台根据渠道能力明确提交 `resolution` 与 `aspect_ratio`，避免把 1K 横图按像素长边误归档为 2K，或把近似像素尺寸当作精确比例。本次已保存「测试异步」图片配置：渠道 30 使用 1K、31 使用 2K，并开启兼容字段；代码未发布，新兼容链路尚未在生产生效。步骤见[天悦图像配置](wiki/03-异步图像系统.md#tianyue-image-compatibility)。
- 新增独立 `tianyue` 视频任务插件，通过 type 61 渠道使用。当前仅登记上游文档的实际示例型号 `L-sd2-video`，按 `requests` 与 `resolution` 配置服务方价格。视频按用户要求暂不在线配置；当前 Key 的模型列表仅返回图片型号，视频权限与型号可用性未核实，未完成真实视频生成验收。待另行授权发布后，按[视频手动配置](wiki/05-异步视频与统一媒体任务.md#tianyue-video-configuration)操作。
