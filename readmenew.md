## 功能概览

### 异步图像、图库与图像广场

- 新增兼容多种图像请求格式的异步提交与查询接口。
- 新增图像工作台、用户及管理员任务中心、任务详情和结果展示。
- 图像工作台使用受视口约束的纵向布局；选择模型后动态展开的质量、输出格式、背景和图片数量等参数保持在页面滚动区内，生成按钮不会被页面底部裁掉。
- 新增图像对象存储、签名 URL、清理、失败处理、渠道路由和计费衔接。
- 异步生图 outbox 按秒级节拍投递到 Redis；上游已接单后保持“处理中”展示，轮询间隔会释放执行租约，不再等待完整租约超时。
- Gemini 异步上游失败会在读取兼容层归一化结果前提取并脱敏原始 `error.message`，据此区分 611–613；供应商错误码、状态和 request ID 随管理员可见的渠道尝试记录保存，普通用户仍只看到安全的失败说明。
- 新增个人图库、图像广场、发布申请、举报、内容审核及管理员清理能力。
- 新增 Token 图像平台分组配置、图像运行配置、存储配置和权限资源。
- 图片平台策略在模型能力输入区提供当前平台的 JSON 配置示例；Gemini、Vertex AI 及其他已注册图片平台使用对应模板，示例可在弹窗中一键复制且不会覆盖当前表单。
- 渠道池按分组和平台加载可执行模型及已启用渠道，模型与渠道 ID 通过下拉多选配置；编辑已有绑定时自动回填模型、渠道和优先级，服务端会拒绝能力不匹配的渠道。
- 生图渠道可在路由策略中声明最大参考图数量；参考图超过 8 张时优先选择容量覆盖请求的渠道，未配置的旧渠道继续按 8 张处理。全局默认上限和模型策略示例均为 14 张。
- 图像运行设置将全局最大参考图数量作为普通表单项；工作台只展示模型策略与全局上限的较小值，具体模型上限由平台策略声明，不再按 Flash 模型名隐藏固定为 3 张。Gemini 的“上游拉取失败后转本地”会在首次请求直接传递外部 URL，只有 SC/内嵌引用、本地模式或上游拉取失败后的重试才由服务器下载。参考图不再受合计字节数/像素数限制，但单图字节数、单图像素数和数量上限仍保留；短小尾随数据只在完整解析终止标记并再次解码后被安全裁剪，格式/超限错误会指出第几张参考图且不再重试。
- 部分 Gemini 兼容渠道在无法拉取远程参考图时只返回 `400 / INVALID_ARGUMENT`，甚至复用安全策略文案。启用“上游拉取失败后转本地”且首次请求确实包含远程 `fileData` 时，这类模糊响应会保留原始脱敏诊断并最多追加一次本地下载重试；明确的数量超限、缺图和参数错误仍直接失败。重试成功后会清空任务顶层的旧错误，首次失败诊断继续保留在管理员尝试审计中。高级运行配置继续保存严格 JSON，不接受注释；编辑器下方的可折叠字段说明表覆盖全部运行字段、用途和当前值，并支持七种前端语言。
- OpenAI 异步编辑保留新提交请求的 multipart 文件传输格式，按图片真实格式填写文件扩展名和 MIME，不再把上传文件统一改成 JSON 或标记成 PNG；旧 `_oa` multipart 入口正确保留 `watermark=false`，掩码不占参考图数量上限。JSON URL 请求继续发送标准 `images[].image_url`。OpenAI 异步 HTTP 失败保留脱敏后的供应商错误说明、错误码和 request ID；渠道状态码映射仍控制重试分类，尝试审计记录真实 HTTP 状态。具体范围与验证见[异步图像说明](wiki/03-异步图像系统.md)。
- 渠道可选配置 `upstream_async.profiles`，按映射后的上游模型、图片/视频类型和生成/编辑/延长操作动态提取任务号、构造 GET/POST 查询并解析状态、进度、失败原因、结果 URL 和实际用量。图片异步接口支持多个结果，命中规则的同步图片请求不会误把任务回执当作结果。
- 上游异步规则的提交请求可选择沿用渠道适配器或任务插件，也可在 `submit.request` 指定同源 POST 路径、查询参数、请求头与 JSON 模板；图片任务可由此映射至供应商的非标准提交端点，例如 Mai Token 的 `/v1/videos`。模型能力、计费和任务调度仍须正常配置。
- 上游提交返回任务号后，图像 worker 会从当前租约中的任务读取最新版本再保存上游任务号，避免提交前的版本快照使任务错误进入 `execution_unknown`；带参考图的生成请求会保持客户端的 `generate` 操作以命中渠道规则。异步图片结果传输短暂中断时继续查询已保存的上游任务并在原重试预算内重试下载，公开查询地址使用 GET。
- 异步图片结果下载遇到 HTTP 408、429、5xx 或传输中断时，继续轮询已保存的上游任务并在瞬时失败预算内重试；同源鉴权下载端点跳转到公网 CDN 时，后续请求清除渠道凭据并重新校验目标地址。
- 动态上游图片下载重试耗尽后，未配置下载头且全部结果为公网匿名链接时，按任务冻结的价格、分组倍率和实际结果张数结算，成功后返回原链接并标记 `result_source=upstream`、`status=succeeded`。Token 计费仍要求真实用量；余额不足或消费日志失败时暂不公开链接，恢复不会重复生成或扣费。未知实际尺寸使用原请求规格计价，本站图库归档仍要求媒体落盘并校验。
- 上游已接单图片任务的重复轮询不再逐次添加相同阶段和渠道尝试；收到结果只保留一条结果里程碑，后续更新链接复用该记录，同时清理已投递的旧轮询命令。历史任务详情会折叠重复阶段，历史数据库记录不自动清除。
- 动态上游查询只允许相同协议、主机和有效端口的 HTTP 跳转，同时保留原 HTTP 客户端的访问限制，跨源跳转停止以保护渠道凭据。模板变量值按一次替换写入，不会再次解释值中的占位符；已结束且过期的图片任务详情不再展示上游回退链接。
- 管理员任务详情的参考图区域提供「全部复制」：一次性把全部可访问的参考图 URL 按行复制到剪贴板；内嵌图不会进入复制内容。

- 内置 xAI 视频任务插件，支持 Grok Imagine Video 1.5、预览/日期别名和经典模型的提交、轮询、结果归档及官方美元计费表达式。
- 新增 `/v1/videos/edits_async` 与 `/v1/videos/extensions_async` 持久化接口，以及 `/v1/videos/edits` 与 `/v1/videos/extensions` 任务插件兼容端点；任务操作、幂等域、能力校验、渠道选择、落盘、结算和 `execution_unknown` 防重提均沿用统一媒体任务链路。
- xAI 经典 `grok-imagine-video` 支持 HTTPS MP4、`data:video/mp4` 或 `file_id` 编辑与向后延长，并可使用上游 cost ticks 结算；Seedance 2.0、Fast、Mini、2.5 支持 URL/`asset://` 主视频、多模态参考及前后延长。
- 渠道级上游异步规则命中视频任务时，会冻结无密钥配置快照、持久化上游任务号并由后台 Worker 轮询；优先下载、校验并返回本站签名结果地址。未命中规则时继续使用 xAI、Seedance 等内置插件解析。
- 异步视频本地保存失败按媒体存储重试预算处理；动态上游任务重试时按冻结规则重新查询已完成的任务，刷新结果 URL。同源鉴权下载跳转到公网 CDN 时不转发渠道凭据。耗尽重试后，符合公网匿名访问条件的动态上游任务可标记 `storage_status=upstream` 并返回上游链接；统一媒体查询、产物列表和视频内容接口均支持该回退，链接未经过本站媒体校验或签名。
- 视频任务可对已由任务插件识别的模型选择默认提交或渠道自定义 POST 提交；自定义提交不会新增视频模型能力，已有插件校验和计费仍生效。
- 视频自定义提交的时长校验兼容 JSON 数值与数字字符串，并保留原 JSON 类型；时长必须有限、大于零、不超过宿主上限且与已校验的原请求一致，不能通过模板改变计费时长。
- 视频渠道规则可选配置 `poll.response.actual_seconds_path` 读取成功响应的实际秒数。模型或插件专属计费表达式使用 `u("seconds")` 设置美元每秒单价，任务插件声明秒数与预扣上限；完成时按冻结表达式重算并退回差额。缺失或无效秒数会按轮询失败预算重试，超预扣秒数或额度的结果会失败并全额退款；未配置路径的渠道保持既有计费行为。
- 媒体运行设置保存成功后立即显示“已保存”反馈，并刷新服务端配置。

## 文档维护规则

1. 每次新增、移除或修改功能时，同一变更必须更新本文件中的功能索引或变更记录。
2. 同一变更必须同步更新 `wiki/` 下对应的详细页面；没有对应页面时应新增页面并加入 `wiki/01-首页.md`。
3. `wiki/` 目录下的 Markdown 文件必须使用“二位序号 + 连字符 + 中文名称”的格式，例如 `07-功能名称.md`；新增、重命名或删除页面时必须同步更新全部引用和目录页。
4. 每个 Git 提交应在对应月份的 Wiki 代码变更台账中保留提交时间、提交哈希、变更范围和实际行为摘要。
5. 不修改原有 `README*.md`、`docs/` 或其他既有说明文件，除非用户明确指定要修改其中某个文件。
6. 文档必须描述最终实际行为、权限、配置、接口、数据迁移、验证结果和仍存在的限制，不能记录已放弃的实现方案。
7. 功能代码、测试和文档应在同一提交或拉取请求中保持一致。
