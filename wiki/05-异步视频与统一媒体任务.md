### Drama 上游排队与真实进度

2026-10-17 本地修复（待提交、未部署）：Drama 上游受理后仍为 `queued` 时，用户与管理员任务中心、详情和 `GET /v1/media/tasks_async/:task_id` 均显示 `status=queued`、`stage=queued`；上游执行后再进入处理中。状态、阶段筛选和列表统计遵循相同分类，避免详情排队但筛选或统计仍计为处理中。普通 `GET /v1/videos/:task_id` 沿用标准 `queued / in_progress / completed / failed` 状态。

| 字段 | 含义 |
| --- | --- |
| `progress` | 保留现有总进度，包含生成和本地保存阶段；不改成供应商百分比 |
| `upstream_progress` | 可选数值，表示上游实际返回的 `0–100` 百分比，保留 `0` 和小数；缺失或非法时省略 |

两类公共视频查询、媒体任务列表和详情均可返回 `upstream_progress`；桌面列表、手机卡片和任务详情单独标注“上游进度”。该值只从已保存的上游响应读取，不能用内部任务的默认 `10% / 20% / 30%` 占位进度补齐，也不根据等待时间估计。标准 Drama 使用响应的数值 `progress`；若渠道启用了上游异步覆盖，则按提交时冻结的进度路径读取私有响应快照，兼容数值和合法数值/百分比字符串，统一返回数值。不把整份供应商响应、结果链接或账单返回给查询者。

| 本机文件上传 | `-F 'input_reference=@reference.png;type=image/png'` | 本例为 Sora；由 curl 设置 multipart，不加 JSON Content-Type |
| 单张图片 URL | `"image": "https://cdn.example.com/first.png"` 或 `"image": {"url":"https://cdn.example.com/first.png"}` | xAI、Drama G 的首帧模式；由型号决定支持范围 |
| 多张普通参考图 URL | `"reference_images": ["https://cdn.example.com/a.png", "https://cdn.example.com/b.png"]` | Drama A / E / F / H3 普通参考；A 还需在 prompt 引用 `@图1`、`@图2`；xAI 1.5 也支持普通参考数组及 URL 对象 |
| 首尾帧 | 同时填写 `image`、`last_frame` | Drama A 2.0 使用 `Auto`，G 2.5 使用 `adaptive`；均不混普通参考素材 |

当前 Drama 与官方 Doubao Seedance 不接收 multipart 图片上传；图片先放到自己的公网可读存储，再按 JSON 传入 URL。`@` 是 curl 上传文件的符号，不放在 JSON URL 前；多个 URL 是数组，不用逗号拼成一个字符串。Gemini SC 临时上传接口不是通用视频素材服务。

标准 `/v1/videos/edits`、`/extensions` 示例返回 `id`，使用 `/v1/videos/{id}` 查询；持久化 `_async` 示例返回 `task_id/query_url`，使用统一媒体查询。两套示例已明确标注，不能交叉使用查询地址。

图像工作台中的视频工作区支持提交异步视频任务。提交后页面保存任务 ID，轮询统一媒体查询接口，并在任务完成后展示可访问的视频结果。

任务中心统一展示图像和视频任务。用户可以查看任务详情、恢复可恢复任务，或终止尚未派发、仍在排队且无有效执行租约的视频任务。管理员使用相同的数据结构查看全站任务，并通过已有异步任务管理权限执行操作。

任务归属由提交时的 API Key 所属账号决定。浏览器需登录该账号才能在普通用户任务中心查看；管理员可以跨用户查询。若公共查询 API 能查到、管理员能查到、普通页面查不到，先核对浏览器登录账号与提交 Key 的所属账号，再检查日期和其他筛选条件；换用另一个账号的 Key 不会将历史任务转给当前登录账号。

两个任务页面的“搜索任务”可按完整或部分任务 ID、模型名称匹配图像和视频；管理员还可按渠道名称模糊搜索两类任务。图像规格和提示词继续在图像任务中匹配，高级模型筛选支持部分名称。搜索去除首尾空白、忽略英文大小写，并按字面处理通配符；日期、状态、用户范围、分页及统计仍共同生效。入口与示例见[任务中心](03-异步图像系统.md#任务中心)。

## 公共 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/v1/videos/generations_async` | 提交异步视频生成任务 |
| `POST` | `/v1/videos/edits_async` | 提交持久化视频编辑任务 |
| `POST` | `/v1/videos/extensions_async` | 提交持久化视频延长任务 |
| `GET` | `/v1/media/tasks_async/:task_id` | 查询统一媒体任务状态和结果 |
| `GET` | `/v1/videos/tasks_async/stats` | 查询当前用户当天的持久化异步视频统计 |
| `GET` | `/v1/media/tasks_async/stats` | 查询当前用户当天的持久化异步图片与视频合计 |
| `GET` / `HEAD` | `/v1/media/objects/:object_id` | 通过签名链接读取媒体对象 |

创建任务沿用 API Token 鉴权、渠道筛选和分发逻辑。接口接收任务后返回任务标识，由后台 worker 完成上游提交、状态轮询、结果下载、对象归档和计费结算。

### 当日视频与媒体统计

`GET /v1/videos/tasks_async/stats` 返回 `object: "async_video.stats"`；`GET /v1/media/tasks_async/stats` 返回 `object: "async_media.stats"`。两者与图片统计 `/v1/images/tasks_async/stats` 共用 `date`、`timezone`、`balance`、`today_requests`、`success_count`、`failure_count`、`success_rate` 字段，完整约定见[异步生图 API 接口文档第 10 节](../异步生图API接口文档.md#10-当日异步生图统计与异步视频扩展)。

统计按 Bearer API Key 的用户身份读取主库，包含该用户所有 Key 和工作台提交的持久化视频生成、编辑与延长任务。视频以异步媒体任务为计数单位，其关联上游任务不重复计数；只有通用任务记录的旧视频或音乐等任务不纳入。当天按任务创建时间和服务器时区计算，配置的 `TZ` 优先于系统本地时区，客户端参数不能改变用户、日期或时区范围。

排队和处理中任务计入请求数；上游成功但媒体任务尚未成功时仍属处理中。视频任务的 `failed`、`expired`、`execution_unknown`、存储失败或计费失败，以及关联上游任务失败均计入失败；失败优先于成功，避免未完成计费的结果计入成功。任务恢复或完成既有上游链接回退后，下一次查询按持久化新状态统计。成功率为成功数除以成功与失败数之和，没有成功或失败时为 `0`。

Key 额度或用户余额耗尽可继续查询；Key 过期、禁用、删除、用户不可用及 IP 限制仍在服务端执行。统计不依赖视频提交开关、worker 或存储就绪。响应使用 `Cache-Control: no-store`，钱包余额读取当前额度账本并除以 `QuotaPerUnit` 返回，不应用前端货币显示汇率；优先读取有效的 Redis 实时额度，Redis 未启用时读取主库。Redis 与批量更新同时开启时，额度缓存缺失或不可用返回 `500`；未开启批量更新时可回退读取主库，本接口不重建或写入额度缓存。鉴权失败返回 `401 authentication_error`，已配置的全局 API IP 限流返回 `429 rate_limit_exceeded` 和 `Retry-After`，查询失败返回 `500 stats_unavailable`，数据库能力未提供返回 `503 stats_unavailable`。

### 生成、查询与下载示例

先完成下方配置，并使用属于已配置分组、有对应模型权限的 API Token。以下命令适用于 Bash；站点地址和 Token 都要替换成自己的值。在 `/system-settings/site/system-info` 保存对外地址（`ServerAddress`），例如 `https://your-new-api.example`，应与用户能够访问的地址一致，避免返回错误的查询或签名链接。

```bash
NEW_API_BASE="https://your-new-api.example"
NEW_API_KEY="sk-your-api-token"

curl -i "$NEW_API_BASE/v1/videos/generations_async" \
  -H "Authorization: Bearer $NEW_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: seedance-demo-001" \
  -d '{"provider":"doubao","model":"doubao-seedance-2-0-260128","prompt":"一只纸船缓缓穿过霓虹灯映照的河面","seconds":5,"resolution":"720p","aspect_ratio":"16:9"}'
```

`provider` 用于限制任务插件，本例为 `doubao`；`model` 是客户端模型名，若有映射，渠道规则匹配的是映射后的上游模型。`seconds` 与 `duration` 是二选一的请求写法，不要同时传。该请求期望输出 5 秒视频；请求参数仍受插件能力和平台策略限制，最终时长以有效的完成用量为准。

受理响应为 **HTTP 202**，响应体只有以下两个字段（ID 为示例）：

```json
{
  "task_id": "task_0123456789abcdef0123456789abcdef",
  "query_url": "https://your-new-api.example/v1/media/tasks_async/task_0123456789abcdef0123456789abcdef"
}
```

响应头还包含 `Location` 与 `Retry-After: 3`。202 表示本地任务已受理，不代表上游生成或最终结算已完成。保存返回的 **本地 `task_id`**，使用提交时相同的 Token 查询；不要使用上游任务号或数据库主键替换它：

```bash
TASK_ID="task_0123456789abcdef0123456789abcdef"
curl "$NEW_API_BASE/v1/media/tasks_async/$TASK_ID" \
  -H "Authorization: Bearer $NEW_API_KEY"
```

查询响应字段摘录示例，完整响应还包含模型、时间和用量等信息：

```json
{
  "id": "task_0123456789abcdef0123456789abcdef",
  "task_id": "task_0123456789abcdef0123456789abcdef",
  "media_type": "video",
  "status": "succeeded",
  "stage": "completed",
  "progress": 100,
  "billing_status": "settled",
  "storage_status": "succeeded",
  "result_count": 1,
  "data": [
    {
      "key": "video",
      "url": "https://your-new-api.example/v1/media/objects/example-object?expires=示例到期时间&access=示例签名",
      "content_type": "video/mp4"
    }
  ]
}
```

成功后使用真实响应中的 `data[0].url` 下载，不自行拼接对象 ID 或签名。查询字段 `duration_ms` 表示任务耗时，不是计费使用的输出视频秒数。若 `storage_status` 为 `upstream`，`data[].source` 为 `upstream`，链接来自上游且可用期由供应商决定。

```bash
RESULT_URL="从查询响应复制的完整data[0].url"
curl -L "$RESULT_URL" -o video.mp4
```

Windows PowerShell 可把生成请求 JSON 保存为 UTF-8 的 `video-request.json`，使用 `curl.exe` 避免 Windows PowerShell 的同名别名。例如：

```powershell
$videoBase = 'https://your-new-api.example'
$videoToken = 'sk-your-api-token'
curl.exe -i "$videoBase/v1/videos/generations_async" -H "Authorization: Bearer $videoToken" -H 'Content-Type: application/json' -H 'Idempotency-Key: seedance-demo-001' --data-binary '@video-request.json'
```

网络超时后重试相同提交时复用原 `Idempotency-Key`；响应头 `X-Idempotency-Replayed: true` 表示复用已受理任务。新一轮生成、更改请求内容或更换生成/编辑/延长操作，应使用新的键，否则可能返回 409。

## 数据和后台处理

- `async_media_jobs` 保存本地公共任务 ID、队列与存储状态、计费状态、错误信息、租约和重试数据；上游真实任务 ID 与冻结渠道规则保存在关联任务的 `Task.PrivateData` 中。
- 媒体对象记录保存对象归属、存储位置、内容类型、大小、过期时间及访问所需信息。
- worker 使用租约避免多个实例重复处理同一任务，并按配置执行轮询、下载和失败重试。
- 媒体队列按下次可执行时间、创建时间和主键排序，处理中的老任务延后后会把机会让给新提交或其他已完成任务，避免下载并发较小时队首长期占满。
- 任务轮询按持久化任务主键定位，同一平台不同渠道、不同账号返回相同上游 ID 不会串任务。普通视频任务也保存实际提交密钥；批量轮询按该密钥分组，不把渠道内整组密钥作为鉴权值发送。历史多账号任务若未保存原密钥，需要管理员核对供应商记录，不自动猜测账号或自动超时退款。轮询与超时清理分别按 ID 分页轮转，待核实记录不会一直占据最旧查询窗口而阻挡后续任务。
- Sora Remix 保留 `remix` 操作，并把本地公共原任务 ID 转换为该任务真实上游 ID，复用原视频所属账号；原视频必须属于请求用户且已成功完成。可用的原任务时长、规格和冻结倍率用于编辑估值，避免被图生视频验证或后续价格初始化覆盖。
- 统一媒体任务列表的 `request_type=video` 返回全部视频类型；`text_to_video`、`image_to_video`、`remix`、`extend`、`video_to_video` 可按具体操作筛选，仍受用户所有权限制。
- 本地媒体存储使用临时文件和原子替换，避免未写完的对象被读取。
- 结果链接采用签名和过期时间控制；后台清理任务按保留期删除过期对象。

## 配置

### 1. 准备运行依赖

在 new-api 服务的环境变量中配置可用 Redis、任务载荷加密密钥和稳定的媒体签名密钥，然后重启读取这些环境变量的服务进程。以下是格式示例，尖括号内容必须替换：

```dotenv
REDIS_CONN_STRING=redis://<redis-host>:6379/0
TASK_PLUGIN_ENABLED=true
ASYNC_IMAGE_ACTIVE_KEY_ID=media-1
ASYNC_IMAGE_PAYLOAD_KEYS=media-1:<32字节随机密钥的标准Base64值>
CRYPTO_SECRET=<独立生成并持久保存的随机字符串>
```

配置文件放在哪里取决于启动方式：

| 启动方式 | 配置位置与生效方法 |
| --- | --- |
| 直接运行二进制或 `go run` | 程序启动时读取**进程工作目录**下的 `.env`；也可由服务管理器注入环境变量。启动环境已有同名变量时优先使用已有值。保存后重启 new-api 进程。 |
| 根目录 `docker-compose.yml` | 在实际部署目录的 `.env` 保存变量，再在 `services.new-api.environment` 中引用。仅放到 Compose 的 `.env`，未引用的变量不会自动注入容器。使用下方片段补充现有服务配置后重建该服务。 |
| Fork 部署模板 | `deployment/fork-docker/compose.fork.yml` 已引用 Redis 与上述两类密钥；在部署目录的 `.env` 核对这些变量。操作实际部署副本，完整部署步骤见[首页与部署](04-首页与部署.md)。 |

根 Compose 的环境变量使用列表格式。下面是需要**合并进现有 `services.new-api.environment`** 的条目示例，不是完整 Compose 文件；保留现有数据库、Redis 和其他配置，已有同名项只保留一个：

```yaml
environment:
  - TASK_PLUGIN_ENABLED=true
  - ASYNC_IMAGE_ACTIVE_KEY_ID=${ASYNC_IMAGE_ACTIVE_KEY_ID}
  - ASYNC_IMAGE_PAYLOAD_KEYS=${ASYNC_IMAGE_PAYLOAD_KEYS}
  - CRYPTO_SECRET=${CRYPTO_SECRET}
```

在包含该 `docker-compose.yml` 和 `.env` 的实际部署目录执行 `docker compose up -d --no-deps new-api`，使容器读取新的环境变量；`docker compose restart` 不会重新注入修改后的 Compose 环境变量。Fork 模板使用映射格式，应沿用它原有的引用，无需追加上面的列表片段。

`ASYNC_IMAGE_*` 的名称沿用图片模块，视频载荷也使用这套密钥。`ASYNC_IMAGE_ACTIVE_KEY_ID` 必须对应 `ASYNC_IMAGE_PAYLOAD_KEYS` 中一个键名；值解码后必须恰好为 32 字节，不能直接写 32 个普通字符。多实例应使用同一套稳定密钥；轮换时先保留旧键，例如 `old:<旧值>,media-1:<新值>`，直到旧任务不再需要解密。

可以在本机生成所需的 32 字节随机值。Bash 环境示例：

```bash
openssl rand -base64 32
```

Windows PowerShell 示例：

```powershell
$mediaKeyBytes = New-Object byte[] 32
$mediaKeyGenerator = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$mediaKeyGenerator.GetBytes($mediaKeyBytes)
$mediaKeyGenerator.Dispose()
[Convert]::ToBase64String($mediaKeyBytes)
```

两次独立生成可分别用于载荷密钥和 `CRYPTO_SECRET`。已有服务不要为了套用示例覆盖正在使用的密钥；缺少显式 `CRYPTO_SECRET` 时程序会使用现有 `SESSION_SECRET`，应确保所有处理任务和读取结果的实例一致。视频配置中的就绪检查用于确认运行状态，不会展示密钥值。

### 2. 开启视频并保存存储参数

原“图片设置”在保持 `/system-settings/operations/images` 路由及 `/api/option/images` 接口兼容的前提下显示为“媒体设置”，固定提供“图片运行”“图片存储”“图片策略”“视频配置”“渠道池”五个页签。媒体运行配置包含：

- 是否启用异步视频。
- 本地媒体存储目录。
- 媒体保留天数。
- 签名链接有效期。
- 单个媒体对象最大字节数。
- 下载超时、并发数和重试次数。

默认本地目录为 `data/media`，默认保留 90 天，签名链接默认有效 3600 秒，单个对象默认上限为 1 GiB，下载默认超时 900 秒、并发数 2、重试次数 5。管理员修改配置后，新的后台处理流程使用最新配置。

在“视频配置 → 异步视频与本地存储”中勾选“启用异步视频生成”，逐项填写并点击该卡片的“保存”。`data/media` 相对于服务工作目录；容器部署应把对应目录挂载到持久卷，并保证执行 worker 的进程有读写权限。它与“图片存储”中的图片存储配置不是同一个表单。

仓库 Dockerfile 的工作目录为 `/data`，根 Compose 与 Fork 模板均挂载 `./data:/data`。新部署可将页面“本地媒体存储目录”明确填为 `/data/media`，此时文件保存在宿主部署目录的 `./data/media`；若保留相对默认值 `data/media`，容器中实际为 `/data/data/media`。已有任务关联自己的存储路径，修改配置不等于迁移旧文件，应保留旧目录供在途任务及历史结果访问。

下列 JSON 是该卡片对应的 `PUT /api/option/images/media` **完整请求体**，用于说明字段和自动化配置；界面中应逐项填写，不要粘贴进平台策略或渠道规则编辑框。管理接口使用已获授权的管理请求方式，示例不包含登录凭据。

```json
{
  "video_async_enabled": true,
  "local_path": "data/media",
  "retention_days": 90,
  "signed_url_expiry_seconds": 3600,
  "max_file_bytes": 1073741824,
  "download_timeout_seconds": 900,
  "download_concurrency": 2,
  "storage_retry_attempts": 5
}
```

| 参数 | 示例及单位 | 允许范围或说明 |
| --- | --- | --- |
| `video_async_enabled` | `true` | 是否接受异步视频；默认关闭 |
| `local_path` | `data/media` | 非空本地目录；可换成容器内挂载路径 |
| `retention_days` | `90` 天 | 1–36500；过期清理与 URL 的短期签名有效期不同 |
| `signed_url_expiry_seconds` | `3600` 秒 | 1–604800；结果签名链接的有效期 |
| `max_file_bytes` | `1073741824` 字节 | 1–17179869184；示例为 1 GiB |
| `download_timeout_seconds` | `900` 秒 | 1–86400 |
| `download_concurrency` | `2` | 1–32 |
| `storage_retry_attempts` | `5` 次 | 0–100；0 表示不追加存储重试 |

这里的 `storage_retry_attempts` 只负责已生成文件的保存，不控制上游生成失败次数或实际秒数字段缺失的重试预算。

“视频配置”集中展示全局视频开关、任务插件、Redis、载荷加密密钥和媒体 URL 签名密钥的就绪状态。`GET /api/option/images` 只返回检查结果和失败原因，不返回 Redis 地址或任何密钥值；同时返回已注册视频插件的模型及 `videoProfiles` 模板，便于导入平台策略。

### 3. 配置视频平台策略

以下以已启用的 `doubao` 插件、分组 `default` 和模型 `doubao-seedance-2-0-260128` 为例。先在 `/channels` 保存同一分组、包含此模型且可以执行该插件的渠道，再在“视频配置 → 视频平台策略”选择服务方 `doubao`，填写分组 `default`，启用媒体平台及异步执行，把渠道池绑定方式设为“模型和分辨率”。

把以下 **JSON 数组** 粘贴到该策略的模型能力输入框，保存平台策略。它允许插件原本支持的模式和参数；想缩小范围时再填写 `video_overrides`，不要为了启用文生视频而复制只含 `edit_video`/`extend_video` 的编辑示例。

```json
[
  {
    "id": "doubao-seedance-2-0-260128",
    "label": "Seedance 2.0",
    "media_type": "video",
    "video_overrides": {}
  }
]
```

平台策略的 `models` 现在是图片与视频联合目录。视频模型应显式声明 `media_type: "video"`，并可通过 `video_overrides` 缩小时长、模式、分辨率、比例、默认值和参考素材数量。服务端拒绝超出任务插件声明的扩大配置。没有 `media_type` 的旧条目仍按历史图片或手工视频策略兼容，数据库中的既有 JSON 不会被批量改写。

```json
[
  {
    "id": "grok-imagine-video-1.5",
    "label": "Grok Imagine Video 1.5",
    "media_type": "video",
    "video_overrides": {}
  }
]
```

图片和视频继续共用现有渠道池及数据表。视频路由将 `480p`、`720p` 映射到 `1K`，`1080p` 映射到 `2K`，`4K` 映射到 `4K`；模型选择项会标明图片或视频能力。本次没有新增数据库列、表或迁移。

### 4. 绑定渠道池并配置价格

在“媒体设置 → 渠道池”选择同一分组和服务方，新增绑定。模型、渠道应从联动选项中选择：没有出现在选项中的渠道应先检查启用状态、分组、模型列表及插件身份。

| 字段 | 一条 720p 示例绑定 | 说明 |
| --- | --- | --- |
| 分组 | `default` | 与 API Token 实际使用的分组一致 |
| 平台/服务方 | `doubao` | 插件 key，不是任意供应商显示名称 |
| 模型 | `doubao-seedance-2-0-260128` | 与平台策略和请求匹配；使用别名时同步检查模型映射 |
| 尺寸档位 | `1K` | 视频 `480p`、`720p` 都使用该池档位；不是把输出改成 1K |
| 渠道 | 选择已配置的渠道，例如 ID `12` | `12` 只是示例，不能直接用于另一套部署 |
| 权重 | `0` | 池内相对权重；可用候选全为 0 时平均随机分配，有正权重时排除零权重候选 |

2026-10-12 起，显式视频渠道池按池内权重随机分配，`10`、`9`、`8` 对应约 `10:9:8` 的调用比例，渠道页面的全局优先级和权重不影响该池的抽选。旧配置数值直接作为权重；未配置渠道池时保留原全局调度。详见[渠道池权重规则与 API 兼容](03-异步图像系统.md#渠道池权重分配)。

若策略选择“模型”绑定方式，按该方式填写，不必套用上表的尺寸档位。渠道池负责能选到哪个账号，价格仍在“模型定价 → 模型价格”保存。例如纯按秒 `tier("base", u("seconds") * 0.10)` 表示示例售卖价 0.10 美元/秒；操作步骤、服务方覆盖和预扣计算见[视频计费配置](09-视频计费配置.md)。需要非标准提交或响应格式时，再按[渠道扩展设置](08-渠道扩展设置.md)添加规则。

## 渠道和插件

统一媒体任务通过能力描述判断渠道是否支持异步视频及对应动作。相关适配器负责生成上游请求、解析任务标识、查询进度和标准化结果。提交同时扩展了阿里云、Google、Vertex 等任务插件，并复用 Replicate 等现有异步任务链路。

任务插件 API v1 新增可选 `meta.videoProfiles`。每个 profile 把模型绑定到文生视频、图生视频、参考素材生成视频或首尾帧模式，并声明时长范围或枚举、分辨率、比例、输入来源与数量以及音频、水印、返回尾帧选项。宿主在注册时校验模型归属、默认值、时长上限、输入数量和来源，并对策略覆盖取能力交集；旧插件未声明该字段时继续使用通用视频表单。契约说明、JSON Schema、TypeScript 声明及注册表快照深拷贝已同步。

### 渠道级上游异步覆盖

完整的 `ChannelOtherSettings`、`upstream_async` 字段说明和图片/视频配置示例见 [渠道扩展设置](08-渠道扩展设置.md)。

- 渠道可在原有 `settings.upstream_async.profiles` 中按 `media_type: "video"`、映射后的上游模型及 `generate`/`edit`/`extend` 操作配置动态解析。命中时，规则覆盖提交任务号提取、轮询请求、状态映射和主结果提取；提交请求可继续使用插件默认构造，也可由 `submit.request` 指定同源 POST 路径、查询参数、请求头和 JSON 模板。模型仍需由任务插件认领并通过其能力、计费校验；未命中时 xAI、Seedance、Ali、Replicate 等内置逻辑保持不变。
- 自定义视频提交的时长校验兼容 JSON 数值和数字字符串，例如 `4` 或 `"4"`，转发时保留模板生成的原 JSON 类型。原请求与提交体的有效时长必须一致、有限、大于零且不超过宿主上限；零、负数、非数字、`NaN`、无穷大及模板改写后的时长均拒绝。
- 提交响应中的任务号会立即写入现有私有任务数据，同时冻结一份不含渠道密钥的规则快照。渠道配置随后发生变化也不会改变在途任务的轮询语义；后台 Worker 使用冻结渠道、模型身份与凭据构造查询，本地查询接口不会临时访问上游。
- 查询状态按 JSON 类型精确匹配到排队、处理中、成功或失败。未知状态、缺失字段和临时 HTTP 错误沿用现有失败计数；配置为失败的状态会进入既有失败退款链，成功但没有单个有效 HTTP(S) 视频 URL 则视为解析失败。
- 动态查询 HTTP 跳转限于渠道 Base URL 的相同协议、主机和有效端口，保留原客户端的跳转限制并最多允许 10 次；跨源跳转停止，避免转发渠道凭据。模板占位符只替换一次，变量值中的类似占位符文本保持原样。
- 上游原始响应和结果 URL 保存在 `Task.PrivateData`，不写入公开 `Task.Data`。插件没有产物声明时，宿主自动生成一个视频产物，优先经过安全下载、媒体校验、现有存储和签名流程；带渠道凭据的下载头仅允许同源结果，跨域签名 URL 必须可匿名访问。
- 本地下载或保存失败会在媒体存储预算内重试，默认允许 5 次重试并采用递增等待。动态上游任务在恢复或重试时按冻结的 `poll.request` 重新查询已完成任务，刷新结果 URL，不重新提交生成或重复计费。仅网络下载中断/超时、HTTP 429/5xx、明确的本地文件 I/O 故障在重试耗尽后允许公网直链回退；还须满足 URL 可匿名访问且未配置下载头。此时任务以 `storage_status: "upstream"` 完成，并在统一查询、任务详情、产物列表中返回原上游 URL；`/v1/videos/:task_id/content` 和视频产物内容入口使用 307 跳转。HTML、损坏视频、超出大小限制、下载鉴权/404/410、规则解析和数据库错误不会被兜底成成功，仍显示保存失败供排查。
- 上游回退链接过期但本站任务尚未过期时，任务所有者可在“任务中心 → 详情”的视频结果区域点击“刷新链接”；有管理权限的管理员可在管理任务详情操作。确认后暂时隐藏旧链接，worker 重新查询同一上游任务并尝试下载保存。操作只恢复产物，不修改已结算费用、不创建新的生成任务；任务已过期、处于有效处理租约或底层任务未成功时拒绝恢复。刷新仍可能因上游任务已清理或渠道凭据失效而失败，不保证旧任务永远可恢复。
- 同源鉴权结果端点若跳转到公网 CDN，跨域请求会清除渠道凭据并使用受保护的公网下载连接；初始跨域结果 URL 仍须匿名可下载。直接链接回退不经过本站媒体校验、存储和签名；上游链接的可用期由上游决定，任务的访问权限与展示仍受本站任务过期时间限制。本地保存成功时仍优先返回本站签名链接。
- 同一渠道最多保存 32 条规则，重叠的媒体类型、模型和操作会被拒绝；受限 GJSON 路径、请求模板占位符、GET/POST 方法、Usage 目标和状态集合均在保存时严格校验。本功能复用现有任务、渠道设置、Worker 和共享渠道池，不新增表、列或迁移。
- 视频规则可选设置 `poll.response.actual_seconds_path`，在成功响应中读取大于 0 且不超过 3600 的 JSON 数字，允许小数。`usage_paths` 仍只映射 Token。任务提交前，插件须把 `seconds` 声明为 `number`/`second`，给出本次请求的最大可计费秒数；模型或插件专属定价表达式须引用 `u("seconds")`，例如 `tier("base", u("seconds") * 0.05)`，系数单位是美元/秒。已有模型定价界面可配置该表达式。
- 视频任务在主库同步持久化预扣，并冻结生效价格；命中实际秒数路径的任务另外冻结路径与秒数上限。终态、实际用量和钱包/订阅、令牌、用户、渠道用量在一次主库事务提交。事务失败会留在非终态供后续轮询重试，并发轮询只有一方能结算。普通插件路径允许有效实际费用补扣，补扣不足则失败退款、隐藏结果。严格路径缺少或非法秒数按轮询失败预算重试后失败退款；实际秒数或费用超上限也失败退款。订阅跨周期退款不冲减新周期用量。独立日志库沿用既有记录方式，主库任务快照保留可对账的最终事实。
- 两种时长来源共用同一冻结表达式：没有配置 `actual_seconds_path` 时沿用插件实际用量（包括 Seedance 1.3.0 的输出秒数）；配置后渠道秒数覆盖插件同名字段，其他插件事实保留，不再追加一次插件结算。两者的缺值策略与预扣上限差异见[视频计费配置](09-视频计费配置.md)。
- Redis 与批量额度更新同时启用时，此类视频预扣会立即落主库并同步缓存余额；预扣读取到额度缓存丢失或不可用时直接拒绝，不用本节点队列为空推断主库余额已同步。普通请求提前从未同步主库重建缓存的情形仍受现有批量更新架构限制，应关注额度告警。
- 若进程恰在预扣后、任务落库前中断，旧版异步媒体任务会进入 `execution_unknown`；2026-10-23 本地修改统一按 `failed` 停止执行，账务保持 `unknown` 待核对，不自动重新生成或重复退款。历史行只在查询中呈现失败，不批量迁移；这类请求仍需人工对账。详见[提交失败退款与未知账务规则](#video-submit-refund-20261023)，本次修改未发布。
- Mai Token 附件描述的是异步图片接口，不能从中推断视频结果秒数字段；接入具体视频供应商时，应依据其视频接口文档填写路径并编写对应任务插件。

### xAI Grok 视频

- 内置 `xai` 视频任务插件，绑定 xAI 渠道类型，覆盖 `grok-imagine-video-1.5`、`grok-imagine-video-1.5-preview`、`grok-imagine-video-1.5-2026-05-30` 与经典 `grok-imagine-video`。
- 插件向 `/v1/videos/generations` 提交任务并轮询 `/v1/videos/{request_id}`，把 `pending`、`done`、`failed`、`expired` 归一为统一任务状态；临时结果继续经过现有媒体存储流程落盘。
- 1.5 支持文生、图生、最多 7 张参考图、最多 3 个预设声音以及固定首尾帧；`last_frame` 可以单独使用，也可以把 `image`、参考图片、预设声音和尾帧组合为带固定帧的参考生成。参考和固定帧模式最高 720p，普通文生/图生最高 1080p，时长为 1–15 秒。JSON 素材接受 HTTPS URL、data URI 或 `file_id`，multipart 图片会转换为 data URI。
- 用量事实包含 `seconds`、`resolution`、`input_images`。内置表达式按官方美元价格计算：1.5 的 480p/720p/1080p 分别为 `$0.08`/`$0.14`/`$0.25` 每秒，输入图片 `$0.01` 每张；经典模型 480p/720p 分别为 `$0.05`/`$0.07` 每秒，输入图片 `$0.002` 每张。管理员已有插件表达式、模型表达式、per-call 或 ratio 配置继续优先。

### Seedance

- `doubao` 插件会把顶层 `image`/`input_reference`、`last_frame`、`reference_images`、`reference_videos` 和 `reference_audios` 转换为 Ark `content`，修复图生视频已识别但首帧未发送的问题；原有 `metadata.content` 和复杂角色仍可继续使用。
- Seedance 1.x、1.5、2.0、Fast、Mini、2.5 分组声明各自模式、时长、分辨率和参考素材上限，插件解码阶段会再次校验；2.x 常用表单支持同步音频、水印和返回尾帧。
- 工作台不为 Seedance 展示文件上传，引用素材必须使用公网 HTTP(S) URL 或 `asset://`，错误信息会给出可操作提示。
- Seedance 不内置美元价格；能力接口显示“需要配置计费表达式”并链接现有模型价格设置。管理员已有 per-call、ratio 或插件表达式仍可使用，未配置价格不会新增硬阻断。
- `doubao` 插件 1.3.0 新增 `seconds`（输出视频秒数），与原有 `tokens`、`resolution`、`video_input` 一起提供给任务表达式。按秒可使用 `tier("base", u("seconds") * 0.10)`，按次可使用 `tier("base", 0.50)`；这些金额仅为配置示例，单位为美元。原有 Token 估算、实际上游 Token 结算及管理员价格均保留，不自动切换计费方式。
- 按秒预扣使用请求输出时长，原生 `frames` 按 24 fps 换算并保留小数秒；Seedance 2.5 编辑继承源视频时长，预扣采用 30 秒输出上限。完成后优先使用上游顶层 `duration`，或 `frames / framespersecond`；缺失、非法、非正数或超过宿主 3600 秒上限时保留冻结估值。输入参考视频不额外累加到 `seconds`；编辑、延长的输入预留仍只参与原 Token 估算。最终秒数指上游返回的输出视频时长。
- 管理端任务价格表、计算器、公开价格和用量日志复用既有用量 Schema 展示，新秒数描述为“视频生成单价” / “Video generation unit price”，单位为 `second`。可视化条件表支持每个分辨率填写不同秒价；同一分辨率的 `none` / `video` 参考视频输入行需各自定价，纯按秒时 Token 单价和加收费用均设为 0。配置步骤、四档独立秒价表达式、美元与显示货币、分组倍率和服务方覆盖规则见[视频计费配置](09-视频计费配置.md)。

### 异步编辑与延长

视频编辑和延长同时提供任务插件兼容端点与持久化媒体端点：

| 操作 | 标准任务插件端点 | 持久化异步端点 |
| --- | --- | --- |
| 编辑 | `POST /v1/videos/edits` | `POST /v1/videos/edits_async` |
| 延长 | `POST /v1/videos/extensions` | `POST /v1/videos/extensions_async` |

持久化端点返回 HTTP 202、`task_id` 和 `query_url`，继续通过 `GET /v1/media/tasks_async/:task_id` 查询。请求只接受 JSON；编辑需要 `model`、`prompt`、`video`，延长另接受 `seconds` 或 `duration`（二者不能同时出现）以及 `extension_direction`。方向默认为 `backward`。不支持视频 multipart 上传或 `source_task_id`。

`video` 可以是字符串，也可以是 `{ "url": "..." }` 或 `{ "file_id": "..." }`。xAI 经典模型接受 HTTPS MP4、`data:video/mp4` 和 `file_id`；Seedance 只接受公网 HTTP(S) URL 或 `asset://`。`grok-imagine-video-1.5` 及其预览、日期别名不声明编辑或延长能力；Seedance 1.x 和 1.5 同样不会绑定这两个端点。

例如，编辑 Seedance 2.0 的已有视频，把下面 JSON 作为 `POST /v1/videos/edits_async` 请求体；用自己的可访问素材替换示例 URL，并沿用上述 Authorization、Content-Type 请求头，使用新的幂等键：

```json
{
  "provider": "doubao",
  "model": "doubao-seedance-2-0-260128",
  "prompt": "把人物的外套改成红色，保留镜头运动",
  "video": "https://cdn.example/source.mp4",
  "seconds": 5,
  "resolution": "720p"
}
```

向后延长的示例请求体发送到 `POST /v1/videos/extensions_async`：

```json
{
  "provider": "doubao",
  "model": "doubao-seedance-2-0-260128",
  "prompt": "镜头继续向后拉，展现更广阔的城市",
  "video": "https://cdn.example/source.mp4",
  "seconds": 5,
  "resolution": "720p",
  "extension_direction": "backward"
}
```

这两个示例都返回同样的 202 任务结构，使用同一统一查询接口。`seconds` 在请求中描述该操作的输出要求；最终计费按照插件/渠道成功响应中的输出时长规则执行，不能把输入素材时长和输出秒数自行相加。平台策略必须保留相应的 `edit_video` 或 `extend_video` 模式。

xAI 编辑继承源视频时长和比例并固定最高 720p；延长部分为 2–10 秒、默认 6 秒，且只支持向后延长。预扣使用 8.7 秒编辑输入/输出上限或 15 秒延长输入上限；轮询结果包含 `usage.cost_in_usd_ticks` 时，以 `10^10 ticks = 1 USD` 归一为实际上游费用覆盖估值。经典模型的内置兜底表达式另计视频输入 `$0.01/秒`，管理员显式模型或插件表达式保持优先。

Seedance 会把顶层 `video` 作为第一个 `reference_video` 写入 Ark `content`，保证提示词中的 `@视频1` 指向主视频，再追加图片、视频、音频参考和原生 `metadata.content`。2.0、Fast、Mini 的编辑和延长输出时长为 4–15 秒；2.5 编辑固定 `duration=-1`，延长为 4–30 秒。操作固定自适应比例，带额外参考图片时最高 720p。2.0 系列最多包含 3 段视频、9 张图片和 3 段音频；2.5 最多包含 10 段视频、30 张图片和 10 段音频。配置页的 2.5 延长示例通过 `metadata.output_format="mov"` 展示官方建议的 MOV 高级参数，插件不会强制覆盖管理员的原生配置。

任务插件 `videoProfiles` 增加 `edit_video`、`extend_video` 模式及延长方向声明。时长、分辨率和比例现在均可在模式中省略：省略代表由源素材继承或由供应商固定，客户端传入相应字段会被服务端拒绝。平台策略只能对插件已经声明的维度和方向取子集，不能为锁定模式新增配置项。

持久化载荷会加密保存 `create`、`edit` 或 `extend` 操作；旧载荷缺少该字段时按 `create` 恢复。Worker 按原操作重新执行插件版本、平台策略、能力、渠道池和计费校验。相同 `Idempotency-Key` 仍按令牌、公开路径和原始请求隔离，跨生成、编辑和延长路径复用会返回 409；一旦上游提交结果不确定，任务进入 `execution_unknown`，不会自动再次调用上游。

兼容视频请求仍使用 `POST /v1/videos/generations_async`，并继续接受 `seconds`/`duration`、`size`、`image`/`input_reference` 及供应商原生高级参数；新增统一字段包括 `resolution`、`aspect_ratio`、`generate_audio`、`last_frame`、`reference_images`、`reference_videos`、`reference_audios`。直接 API 请求和工作台请求都会经过同一服务端能力校验。

## 配置完成后的验收与排错

| 现象 | 先看哪里 | 处理方式 |
| --- | --- | --- |
| 视频就绪检查未通过 | 视频配置顶部 | 分别检查总开关、有效视频插件、Redis、载荷密钥和签名密钥；保存或重启对应配置后刷新 |
| 已就绪但没有可选模型/渠道 | 视频平台策略、渠道池、渠道编辑 | 分组、平台、模型须匹配；渠道须启用并支持插件；720p 查 `1K` 池绑定 |
| 有模型但提示价格未配置 | 模型价格、当前服务方页签 | 保存匹配模型和插件的表达式；普通按次/Token 价格不要强行启用 `actual_seconds_path` |
| 202 后仍在生成 | 任务详情与管理任务中心 | 按返回的查询地址继续轮询；检查后台阶段、上游状态映射及失败计数，避免重复提交新任务 |
| 上游成功但本地仍在保存 | `stage`、`billing_status`、`storage_status` | 生成、计费、文件保存是不同状态；检查目录权限、文件大小、下载超时、下载头和重试预算 |
| `storage_failed` 且允许恢复 | 任务中心的 `can_resume` | 修复存储或下载问题后恢复文件保存；不会重新调用生成或重复计费 |
| `execution_unknown` | 管理员任务详情和对应上游账号 | 表示是否已提交无法确认，先对账，不自动重提；不要把它当普通下载失败恢复 |
| 配置路径后缺失实际秒数/超出预扣 | 渠道规则与计费用量 | 对照[渠道响应示例](08-渠道扩展设置.md)检查字段类型和路径，再看[预扣结算说明](09-视频计费配置.md) |
| 本地结果链接已失效 | `expires_at` 和任务查询 | 任务本身未过期时重新查询取得当前签名链接；任务或对象保留期已到不能靠重签恢复已清理文件 |

建议先以一个渠道、一个模型、5 秒和 720p 完成一次生成：核对任务 ID、最终状态、可播放结果、冻结价格和实际用量，再扩展到其他模式或多个渠道。就绪检查通过不等于上游账号、文件落盘及结算都已验收。

## 天悦视频插件与发布后的手动配置（2026-10-22，未发布）

变更日期：2026-10-22（Asia/Shanghai）；提交哈希：未提交（基线 `03a96cd071f63d7d7f8e754a1dd7d3c923290266`）。上游协议见[天悦视频创建文档](https://ai.tianyue.xyz/docs/tianyue-api.html#video-create)。视频按用户要求暂不在线配置；当前 Key 的模型列表仅返回图片型号，视频权限与型号可用性未核实，未进行真实视频提交、轮询、下载和结算验收。以下步骤供包含插件的版本另行获准发布后手动执行，保存图像渠道开关不能替代视频插件部署。

1. 确认运行版本已包含并启用 `tianyue` 任务插件。在渠道管理新建独立「任务插件」（type 61）渠道，绑定插件 `tianyue`，使用账号实际的视频 API 地址及具备视频权限的 Key；插件默认 Base URL 为 `https://api.tianyue.xyz`。允许「测试异步」分组，只添加已核实的型号。渠道 30、31 保持图像用途，不直接改成视频类型。
2. 当前插件仅登记官方文档的实际示例型号 `L-sd2-video`。在「媒体设置 → 视频配置」启用运行所需能力和存储，在「视频平台策略」创建分组「测试异步」、服务方 `tianyue` 的策略，声明该模型为 `media_type: "video"`。按账号和型号实际能力缩小模式、时长、比例与分辨率；代码中的 3600 秒与 64 个参考素材是宿主安全上限，不能当作已验证的厂商能力。
3. 在同分组、服务方和模型下绑定新视频渠道。采用「模型和分辨率」绑定时，视频 `480p`/`720p` 使用 `1K` 池，`1080p` 使用 `2K` 池；该池键只用于路由，输出仍保持请求的视频分辨率。首次验收只开放账号确认的一个档位与模式。
4. 进入「模型定价 → 模型价格」，选择客户端模型并打开 `tianyue` 服务方页签，启用单独价格，按本服务方用量字段保存。`L-sd2-video` 的 Schema 是 `requests`（每条视频数量，成功为 `1`）及 `resolution`；「视频生成单价」应填每条视频的实际 USD 售价，不引用 `u("seconds")`。原始表达式语法示例为 `tier("base", u("requests") * 0.50)`，其中 `0.50` 仅演示语法，须替换为管理员确定的售价。服务方覆盖保存在 `billing_setting.plugin_billing_expr`，键为 `tianyue::<客户端模型>`；现有管理员价格不会自动改写。详细保存入口见[视频计费配置](09-视频计费配置.md#配置入口与保存)。
5. 使用对应分组、模型权限和余额足够的令牌，向本站 `POST /v1/videos/generations_async` 提交 `provider: "tianyue"`、实际客户端模型、提示词、`seconds`、`resolution` 与 `aspect_ratio`，保存任务号并查询返回的 `query_url`。参考图片、音频和视频目前须为可访问的公网 HTTP(S) URL，使用 `reference_images`、`reference_audios`、`reference_videos` 数组；单张首帧也可用 `image` URL。该视频插件不接受 Base64 或直接文件上传，图像渠道的签名参考图转换不自动应用到视频。

插件向上游 `POST /v1/videos` 提交，并由 `GET /v1/videos/{id}` 轮询 `queued`、`in_progress`、`completed`、`failed`；成功结果从 `url`、`video_url` 或 `metadata.url` 读取，再进入现有视频下载与保存流程。实际播放、`storage_status`、冻结价格和消费日志都须在账号开放视频后核验。

上游约定普通型号按次请求的 `duration` 固定为 `1`，实际视频秒数单独放在 `video_duration`；只有以 `-se` 结尾的按秒型号使用相同的 `duration` 和 `video_duration`。当前未登记任何真实 `-se` 型号，不根据命名规则虚构可用模型或套用按秒价格。插件账务描述按 API v1 明确写为「视频生成单价」，单位由 Schema 提供，协议限制和结算规则保留在本节及代码中。
