# 视频计费配置

本页说明当前视频任务价格的配置入口、按秒、按次、按分辨率分别设置秒价与 Token 定价，以及 Seedance 的时长结算规则。媒体运行开关、存储和渠道配置见[异步视频与统一媒体任务](05-异步视频与统一媒体任务.md)，变更与验证记录见[本月变更台账](02-2026年09月代码变更台账.md)。

## 配置入口与保存

1. 以超级管理员账号进入“系统设置 → 计费与支付 → 模型定价 → 模型价格”。页面路径为 `/system-settings/billing/model-pricing`；普通管理员不具备模型价格保存权限。
2. 搜索并选中客户端使用的视频模型名，例如 `doubao-seedance-2-0-260128`。没有价格的模型可在“未设置价格模型”页签查找，也可在模型价格表中新增。
3. 确认要修改的是“默认”价格还是某个服务方的价格。默认页签用于模型级定价；只对 `doubao` 定价时，打开该插件对应的服务方页签并启用“为此服务方单独设置”。已有服务方覆盖时，应在该页签修改；只改默认价格不会覆盖它。关闭这个开关并保存后，该服务方才恢复继承模型级价格。
4. 打开“计费表达式”，选择“可视化编辑器”或“表达式编辑器”。以下可视化示例先将定价货币选择为 USD；原始表达式始终使用美元。
5. 配置价格并检查预览，点击“保存模型价格”，看到“模型定价已保存”后生效。重新打开同一模型和服务方，确认表达式已保存；仅修改编辑草稿或切换页签不会保存到服务端。如提示配置已被他人修改，先重新加载价格，再核对并重新保存。

视频模型的价格由表达式决定。媒体设置中的“视频配置”负责运行能力与就绪状态，模型价格在上述统一入口配置。旧“按次（已弃用）”和“按 Token（已弃用）”页签保留兼容功能；视频的新价格使用任务计费表达式。

## Seedance 可用计费字段

内置 `doubao` 插件 **1.3.0** 同时提供以下字段。使用管理员上传的同名覆盖插件时，以实际激活版本的 Schema 为准。

| 表达式字段 | 可视化名称与单位 | 含义 |
| --- | --- | --- |
| `u("seconds")` | 视频生成单价，美元/秒 | 输出视频时长；可用于按秒收费 |
| `u("tokens")` | 计费 Token 单价，美元/百万 Token | 上游计费 Token；保留已有 Token 定价 |
| `u("resolution")` | 输出视频分辨率 | `480p`、`720p`、`1080p`、`4k` 条件 |
| `u("video_input")` | 参考视频输入 | `none` 或 `video` 条件 |

此前插件只公开了 Token 字段，所以计费引擎无法读取 `u("seconds")`。1.3.0 将输出时长单独提供给计费引擎，管理员可以自行选择按秒售卖，同时保留上游 Token 用量。不会自动改写现有价格或把模型切换到按秒模式。

Sora、xAI、Veo 等插件也提供 `seconds`；其他插件的字段名可能不同，例如 Vidu 使用 `duration`，可灵使用资源包单位 `units`。以编辑器显示的用量参数为准，表达式引用未声明的字段会在保存时被拒绝。

## 路径一：普通 Seedance 插件按秒计费

适用于内置 `doubao` 插件能够正常解析的 Seedance 渠道。启用按秒价格无需添加渠道响应路径。

1. 确认当前激活的 `doubao` 插件为 1.3.0 或更新兼容版本，价格编辑器显示“视频生成单价”。管理员上传的同名覆盖插件应以其实际版本和字段为准。
2. 在 `/channels` 编辑目标渠道，确认其提供 `doubao-seedance-2-0-260128`，并允许测试请求所在分组。普通内置解析保持不配置 `upstream_async`；已有其他规则时，确认没有匹配本次视频模型与操作的 `actual_seconds_path`，不要清空无关规则。
3. 按上节入口打开 `doubao-seedance-2-0-260128` 的模型价格，确认默认价或 `doubao` 服务方覆盖的生效位置，再填写下列秒价。
4. 保存模型价格并重新打开核对。用该模型提交一条合法的 5 秒生成请求，查看提交预扣和成功后的差额日志；使用的平台入口与运行配置见[异步视频与统一媒体任务](05-异步视频与统一媒体任务.md)。

### 填写每秒价格

以下单价都是操作示例，供管理员自行确定售卖价格，不代表供应商官方价格。

在可视化编辑器中：

- “视频生成单价”填 `0.10`，即每秒 0.10 美元。
- “计费 Token 单价”填 `0`，其他用量单价也填 `0`。
- “加收费用”填 `0`。
- 有分辨率或参考视频条件表时，填写需要启用的各行；未定价且为零的组合会按零价计费。

原始表达式可直接填写：

```text
tier("base", u("seconds") * 0.10)
```

分组倍率为 1 时，5 秒费用为 0.50 美元，10 秒费用为 1.00 美元。只需按秒收费时，把 Token 单价置零；同时配置秒数和 Token 单价会累加两项费用。

这条路径提交时按插件估值预扣，成功后再读取实际输出秒数。实际时长缺失时保留估值；有效实际时长比估值长时可补扣差额。需要“成功必须返回秒数，并且不能超过预扣上限”时，使用下文路径二。

## 按次配置

在同一个任务可视化编辑器中：

- 所有用量单价填 `0`，包括秒数与 Token。
- “加收费用”填每次成功任务的固定价格，例如 `0.50`。
- 条件表的各行可以填相同固定价格，也可以按分辨率设置不同固定价格。

统一每次价格的原始表达式为：

```text
tier("base", 0.50)
```

分组倍率为 1 时，每个成功任务收费 0.50 美元，时长和 Token 变化不增加费用。这里的“加收费用”在其他单价均为零时就是完整的按次价格。

任务表达式直接返回美元费用，按次使用普通常数即可。不要写 `fixed(0.50)`：`fixed()` 属于普通 HTTP/SSE 请求定价，任务用量表达式会拒绝它。

## 保留 Token 定价

已有 Token 表达式继续生效。可视化编辑器的 Token 单价按**每百万 Token**填写，例如填写 `10`，同时把秒数单价和加收费用设为 `0`：

```text
tier("base", u("tokens") * 10 / 1000000)
```

示例中 216,000 Token 的基础费用为 2.16 美元。任务表达式本身返回美元，因此 Token 项需要显式除以 `1000000`；秒数和按次项不需要这个缩放。

## 分辨率分档与基础费用

### 每个分辨率分别设置秒价

在“系统设置 → 计费与支付 → 模型定价 → 模型价格”选择视频模型，打开“计费表达式 → 可视化编辑器”。以 Seedance 为例：

1. 定价货币选 USD。
2. 将“计费 Token 单价”和“加收费用”各列全部设为 `0`，可使用列头的“填充整列”。
3. 在每个分辨率对应行的“视频生成单价”中填写该分辨率的每秒价格。例如：

| 分辨率 | 视频生成单价（美元/秒） | 计费 Token 单价 | 加收费用 |
| --- | --- | --- | --- |
| `480p` | `0.05` | `0` | `0` |
| `720p` | `0.10` | `0` | `0` |
| `1080p` | `0.20` | `0` | `0` |
| `4k` | `0.30` | `0` | `0` |

4. 如果同一分辨率还分为参考视频输入 `none` 和 `video` 两行，且两种输入使用相同价格，两行都填该分辨率的秒价；需要区分输入价格时分别填写。留为零的行会按零价计费。
5. 点击“保存模型价格”，在计算器中切换分辨率和时长，核对金额。

以上均为售卖价格示例。分组倍率为 1 时，10 秒的 `1080p` 视频费用为 `10 × 0.20 = 2.00` 美元；10 秒的 `720p` 视频为 `1.00` 美元。同一分辨率的秒价不需要乘上整段时长再填写，时长由用量自动相乘。

也可以切换到“表达式编辑器”，直接填写以下表达式；它按分辨率选择秒价，两种参考视频输入使用相同价格：

```text
u("resolution") == "4k"
  ? tier("4k", u("seconds") * 0.30)
  : u("resolution") == "1080p"
    ? tier("1080p", u("seconds") * 0.20)
    : u("resolution") == "720p"
      ? tier("720p", u("seconds") * 0.10)
      : tier("480p", u("seconds") * 0.05)
```

Seedance 的分辨率字段使用小写 `4k`。各模型和生成模式支持的分辨率不同，填写价格不会扩大插件能力或平台策略；实际请求只能使用该模型及模式允许的规格。已有服务方专属价格时，应在该服务方页签修改对应表格，默认模型价格不会覆盖它。

### 固定基础费加秒价

也可以收取固定基础费再加秒数费：

```text
tier("base", 0.20 + u("seconds") * 0.10)
```

分组倍率为 1 时，本例生成 10 秒收费 1.20 美元。

## 预扣、实际时长与结算

- 提交时按请求的 `seconds`、`duration`、原生 `metadata.duration` 或默认时长估算；支持帧数参数的原生模型提供有效 `metadata.frames` 时，优先按 24 fps 换算输出秒数，保留小数。默认输出估值为 5 秒；模型请求仍经过既有能力与时长校验。
- Seedance 2.5 编辑继承源视频时长，提交时按输出上限 30 秒预扣。其他编辑/延长以请求输出秒数估算；Token 计费原有输入时长预留保持不变，输入参考素材不会额外累加到新的 `seconds`。
- 成功后，插件优先读取查询响应的顶层 `duration`；该字段没有提供数值或字符串时，再尝试 `frames / framespersecond`。数值和数值字符串均可转换，合法小数秒会保留。已提供但内容非法的 `duration` 不会再用帧数兜底，而是保留提交估值。
- 上游没有有效输出时长，或者时长为非正数、非有限值、非法类型、超过宿主 3600 秒上限时，不覆盖提交估值。Token 实际用量仍独立读取。
- 宿主用冻结的表达式和价格参数叠加实际用量后结算差额。按次常数不随时长变化；任务失败沿用既有退款链。修改价格不会改写已经受理任务的账单快照。

官方字段依据：[火山引擎查询视频生成任务 API](https://api.volcengine.com/api-docs/view?action=GetContentsGenerationsTask&serviceCode=ark&version=2024-01-01)。这些字段指输出视频；延长任务以查询响应报告的最终输出时长结算。

## 路径二：渠道实际秒数必填，并按冻结上限结算

此路径适用于需要自定义任务提交回执、轮询响应，或要求实际秒数必须存在的渠道。它仍使用同一套模型/服务方价格；渠道响应路径不包含单价。

### 配置步骤

1. 先按路径一保存模型 `doubao-seedance-2-0-260128` 的表达式 `tier("base", u("seconds") * 0.10)`。确认插件声明 `seconds` 为 `number`、单位为 `second`；预扣费用必须大于零。纯按次、纯 Token、旧倍率或零费用配置不能直接启用此路径。
2. 进入 `/channels`，编辑目标渠道，打开“路由与映射 → 上游异步任务 → 配置上游异步”。需要具有渠道敏感设置编辑权限；界面只读时应由有权限的管理员操作。
3. 在“结构化编辑”中添加或编辑规则，媒体类型选择“视频”；“映射后的上游模型”填写 `doubao-seedance-2-0-260128`，操作先只选择生成 `generate`。若渠道存在模型映射，这里填写映射后的真实上游名，价格页仍先按客户端使用的计费名核对。
4. 按实际接口填写提交任务号路径、轮询方法/地址/请求体，以及“轮询响应”的状态路径、状态映射和结果 URL 路径。在“实际视频秒数路径”填写成功响应中表示**输出秒数**的字段路径，例如 `task.output.duration`。完整 JSON、示例响应和字段映射见[渠道扩展设置第 7.7 节](08-渠道扩展设置.md#upstream-async-video-example)；其中自定义响应路径是演示，不能当作 Seedance 官方字段直接照抄。
5. 点击弹窗“保存更改”，回到渠道编辑页，再点击“更新渠道”。前一次只更新渠道表单草稿，后一次才提交服务器。重新打开渠道，确认规则及秒数路径已保存。
6. 发起新的 5 秒生成请求，核对本次提交冻结的 `seconds=5` 和预扣金额，再检查成功回包的秒数及最终账单。改动渠道规则或模型价格不追溯修改已受理任务，验证新配置必须使用新任务。

**预扣秒数上限来自本次插件提交用量的 `seconds`，没有单独的“最大预扣秒数”配置项。** 该事实由合法请求时长、插件默认值或特定模式的估算产生；本例请求 5 秒且插件报告 5，冻结上限就是 5 秒。3600 秒是宿主校验上界，不表示每个模型都支持 3600 秒，也不表示每次按 3600 秒预扣。若供应商可能输出超过请求时长的视频，应先确认插件给出的估算确实能够覆盖输出，不能靠修改响应路径扩大上限。

匹配规则后，任务号、轮询、状态和主结果解析一并采用这条渠道规则，因此必须填写完整规则；不是只增添一个计费字段。对未命中规则的模型和操作仍采用原有插件逻辑。

### 同一笔账单的计算示例

下例统一使用 `doubao-seedance-2-0-260128`、`tier("base", u("seconds") * 0.10)`、提交 5 秒、成功返回 3.25 秒。`0.10` 美元/秒是管理员售卖价格示例，不代表官方价格。

| 本次生效分组倍率 | 提交预扣 | 成功后的实际费用 | 退还差额 |
| --- | --- | --- | --- |
| `1` | `5 × 0.10 = $0.50` | `3.25 × 0.10 = $0.325` | `$0.175` |
| `1.5` | `5 × 0.10 × 1.5 = $0.75` | `3.25 × 0.10 × 1.5 = $0.4875` | `$0.2625` |

小数秒不会先取整。内部额度按“表达式美元费用 × `QuotaPerUnit` × 生效分组倍率”换算并统一舍入。例如站点 `QuotaPerUnit=500000`、倍率为 1 时，对应预扣 `250000`、实际 `162500`、退款 `87500`；站点使用其他换算值时应按本机配置核算。

普通插件路径在同样收到合法 3.25 秒时也得到这笔差额；严格渠道路径另外要求实际秒数和实际费用都不超过冻结上限，且主库中的终态、余额、令牌额度、用户/渠道用量调整在同一事务完成。提交累计的请求次数保持一次。

## 两条路径的用量来源与异常行为

内置插件和渠道自定义响应规则提供不同的用量来源，定价仍使用上述同一个模型或服务方表达式。

| 配置 | 实际秒数来源 | 缺少有效秒数 | 结算方式 |
| --- | --- | --- | --- |
| 未设置 `poll.response.actual_seconds_path` | 插件完成用量；Seedance 读取 `duration` 或帧数换算 | 保留冻结的提交估值 | 沿用插件任务差额结算 |
| 设置 `poll.response.actual_seconds_path` | 冻结路径对应的 JSON 数字，优先于插件 `seconds` | 按轮询失败预算重试，耗尽后全额退款 | 同步预扣上限，终态与差额退款在主库同一事务提交 |

配置路径后，实际秒数必须为 JSON 数字，允许 `3.25`，不接受 `"3.25"`。它覆盖插件同名的 `seconds`；插件返回的 Token、分辨率等其他事实仍可参与冻结表达式。**收取哪些费用只取决于表达式：** 仅引用 `u("seconds")` 时，即使上游报告 Token 也不会另收费；表达式同时含 `u("seconds") * 0.10` 和 `u("tokens") * 10 / 1000000` 时，两项相加后再乘分组倍率。后一项也仅为演示单价。严格路径会检查合计费用是否超过预扣，不能只核对秒数。

| 情况 | 普通 Seedance 插件路径 | 配置 `actual_seconds_path` 的严格路径 |
| --- | --- | --- |
| 实际 `3.25` 秒，提交估值 `5` 秒 | 按 3.25 秒结算差额 | 按 3.25 秒结算并退还差额 |
| 实际时长为数字字符串 `"3.25"` | 插件可转换为 3.25 秒 | 无效用量，计入连续轮询失败 |
| 成功回包缺少时长，且无可用帧数 | 保留提交时长估值 | 无效用量，计入连续轮询失败；不使用插件秒数绕过必填路径 |
| 时长为 `0`、负数、布尔值、非有限值或大于 3600 | 按上述插件字段优先级处理；未得到有效时长时保留提交估值 | 无效用量，计入连续轮询失败 |
| 合法实际时长 `6` 秒，大于冻结的 `5` 秒 | 可按 6 秒补扣差额 | 任务失败、全额退款，不交付结果 |
| 秒数未超限，但其他实际用量使总费用超过预扣或发生额度饱和 | 按现有表达式差额结算及额度安全规则处理 | 任务失败、全额退款，不交付结果 |
| 仅按次常数或纯 Token 表达式，不引用 `u("seconds")` | 可按已保存表达式收费 | 提交前返回 `model_price_error`，不能启用此秒数结算模式 |
| 预扣表达式结果为零，或分组倍率使预扣为零 | 按已有免费模型规则处理 | 提交前返回 `model_price_error`，要求有效正数预扣 |
| 上游明确失败、任务超时 | 走任务失败退款链 | 终态与全额退款原子提交；再次轮询不会重复退款 |

连续轮询失败默认累计 20 次后将任务置为失败并退款，由 `TASK_POLL_MAX_FAILURES` 控制；另有默认 1440 分钟的总超时，由 `TASK_TIMEOUT_MINUTES` 控制。缺失或非法秒数不会在第一次失败时立即退款。上述环境变量设为非正数会关闭对应截止机制，部署时应保留至少一个有效截止机制。

两个来源最终只执行一次结算，重复轮询、终态后下载重试不会再次扣费或退款。跨渠道重试重新计算当前插件价格，切换为旧按次/倍率方式时清除前一渠道的表达式快照；已持久化异步媒体任务继续使用受理时冻结的价格。字段示例与配置入口见[渠道扩展设置](08-渠道扩展设置.md)。

## 货币、分组倍率与服务方价格

- 原始表达式中的金额始终为 USD。可视化编辑器可以选择其他定价货币，界面会换算输入与预览，但保存后的表达式仍以美元执行。
- 基础费用还会乘请求生效的分组倍率。例如秒价 0.10 美元、时长 10 秒、分组倍率 1.5，最终对应费用为 1.50 美元。额度换算与舍入沿用公共计费逻辑。
- 同一模型有多个任务插件服务方时，可在对应服务方页签启用“为此服务方单独设置”。插件专属表达式优先于默认模型表达式；只修改默认页签不会覆盖已有服务方专属价格。
- 模型别名也要确认计费名：宿主先检查该插件与客户端模型的专属表达式，再检查映射模型的专属表达式，随后按现有规则选择模型级表达式。不要把插件复合键当作普通模型名新增。
- 模型级表达式保存在 `billing_setting.billing_expr`，启用模式保存在 `billing_setting.billing_mode`；服务方覆盖保存在 `billing_setting.plugin_billing_expr`，键为 `<pluginKey>::<model>`。普通操作直接使用管理页面即可。

## 管理员验收与错误定位

1. 更新程序并重新加载服务后，确认当前激活的 `doubao` 插件至少为 1.3.0，详情或价格编辑器中存在 `seconds`。管理员上传的覆盖插件需要自行更新，不会被本次内置源码变更自动替换。
2. 选择实际请求中的模型名，检查默认价格与服务方专属价格，配置并保存。
3. 在计算器选择支持的规格，检查每秒单价、Token 单价、固定费用及基础金额。本页示例 5 秒、0.10 美元/秒、其他单价为零，基础费用应为 0.50 美元；另核对测试请求实际使用的分组倍率，不把基础价格预览当成所有用户的最终价格。
4. 受理新任务后记录公开 `task_id`，按同一任务对照提交消费日志与差额日志。提交日志保存估算用量；存在退款/补扣日志时，检查其中 `usage_facts.seconds`、冻结表达式、`pre_consumed_quota` 和 `actual_quota`。本例倍率 1 时，账单净扣应为 0.325 美元，不能把预扣 0.50 美元与实际 0.325 美元相加。没有差额时可能没有额外差额日志，应结合最终任务配额核对。
5. 在隔离测试上游分别返回 3.25、6、缺失时长和 `"3.25"`，按上表验收。重复查询同一终态任务，应只发生一次余额和用量调整；文件下载重试不应重新计费。严格路径的失败任务应全退，用户请求次数仍保留一次。
6. 分别在钱包和订阅来源下核对余额或订阅已用额度、令牌额度、用户/渠道已用额度，并确认日志库单独配置时仍能查到对应日志。若启用 Redis 与批量写库，严格路径的预扣必须已经落主库；缓存不可用或在预扣时发现冷缓存会拒绝本次预扣，不以可能滞后的主库余额放行。

| 现象或错误 | 定位方法 |
| --- | --- |
| 没有“视频生成单价”或保存提示未知 `seconds` | 核对实际激活插件、覆盖插件版本和当前模型的用量 Schema；不要仅根据内置源码版本判断。 |
| 改了默认价，实际仍用旧价格 | 检查实际渠道的服务方专属表达式、客户端模型别名及映射模型，并确认点过“保存模型价格”。 |
| 严格路径提交报 `model_price_error` | 核对 `seconds` 的类型/单位、表达式是否引用 `u("seconds")`、提交估值是否大于 0 且不超过 3600、分组倍率后预扣是否为正。 |
| 秒数路径似乎未生效 | 重新打开渠道确认已点“更新渠道”；检查匹配的是映射后的模型名、`video` 和对应操作；使用新任务验证冻结规则。 |
| 上游成功，本地仍在重试 | 先核对结果 URL、状态映射及字段 JSON 类型，再查实际秒数路径是否存在；严格模式数字字符串不算有效秒数。 |
| 任务失败原因含 `duration exceeded reserved billing limit` | 实际秒数超过提交时冻结的插件 `seconds`；检查请求与插件估算是否覆盖供应商实际输出。 |
| 任务失败原因含 `cost exceeded reserved billing limit` | 核对冻结表达式所有收费项及实际事实，尤其是额外 Token 和分辨率条件；秒数合法不代表总费用未超限。 |
| 重试返回 `task_billing_reservation_invalid` | 本次渠道要求持久化上限预扣，但已有重试会话不能证明满足要求；请求在发送给该上游前被拒绝。检查重试候选渠道是否混用了不同计费路径。 |
| 出现 `quota cache is cold/unavailable` 类预扣错误 | 检查 Redis 连接、缓存和批量写库状态。该保护只针对本次严格预扣发现的缺失/故障；不要删除缓存来强行绕过，也不能据此推断整个历史批量计费架构具有跨节点原子性。 |

没有真正调用供应商的本地回归只验证代码行为，不代表真实账号已完成生成与结算验收。完整渠道 JSON 和接口排错继续见[渠道扩展设置](08-渠道扩展设置.md)。
