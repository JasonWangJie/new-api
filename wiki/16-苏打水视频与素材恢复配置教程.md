# 苏打水视频接入与 Drama 素材恢复配置教程

适用于管理员。本文按本地代码核对，覆盖苏打水任务插件渠道、目录预览、公开模型、平台策略、渠道池、售价，以及旧版 Drama 在混合异步任务中的素材恢复。本文的模型名、价格、域名和凭据均为示例，实际填写时以账号授权和已加载插件的能力为准。

| 目标 | 操作顺序 |
| --- | --- |
| 苏打水标准视频 API | 启用任务插件 → 创建渠道并保存模型能力 → 设置公开模型售价 → 调用 `POST /v1/videos` |
| 苏打水异步工作台或 API | 完成标准渠道配置 → 启用异步运行 → 保存 `sudashui` 平台策略和渠道池 → 提交异步任务 |
| 旧版 Drama 混合视频素材恢复 | 已有可用 Drama 渠道 → 配置 `mixed` 公开模型、池和售价 → 保存一条仅匹配素材下载失败的规则 → 通过样本和新任务核验 |

<a id="sudashui-channel"></a>

## 1. 创建苏打水任务插件渠道

1. 以超级管理员身份打开 **任务插件**（`/task-plugins`），确认插件总开关已启用并已加载 **Sudashui Video**，插件标识为 `sudashui`。标量参考素材的恢复选择器随本地内置版本 `1.0.1` 提供。存在同名站点覆盖插件时，以实际运行的插件源码和版本为准。
2. 打开 `/channels`，点击 **创建渠道**。在 **连接与模型** 选择 **任务插件**（类型 61），再选择 **Sudashui Video**。
3. 填写 **API 基础 URL** 和 **API 密钥**。默认基地址是 `https://api.sudashuiapi.com`。保留基地址形式，插件会拼接提交与轮询路径。此处填写上游账号的 Key，调用本站的客户端使用另一枚本站 API Token。
4. 在 **模型目录地址** 使用默认 `https://catalog.sudashuiapi.com/v1/models` 或该账号实际授权的目录。点击 **从上游获取**，选择要开放的视频模型。目录不可用或缺少型号时，可在模型列表中手动添加精确的型号名。
5. 配好模型能力、映射和分组后，点击 **创建渠道**。编辑已有渠道时，点击 **更新渠道**。目录预览和能力导入只写入当前表单草稿，外层保存才会生效。

### 1.1 已有渠道预览与变更地址

| 操作 | 使用的凭据和连接 |
| --- | --- |
| 新建渠道时预览 | 使用表单填写的 Key、目录和代理。批量密钥输入使用第一条 Key 预览 |
| 已有渠道，沿用已保存的目录和代理 | 使用已有渠道中可用的已保存 Key。相同的默认目录可以留空 |
| 已有渠道，预览尚未保存的新目录或代理 | 管理接口需要显式传入本次预览使用的 Key。当前编辑抽屉不会把编辑中的 Key 随预览发送 |

通过界面操作已有渠道时，可以先确认并保存新连接配置，再重新打开渠道获取目录。需要在保存前测试时，使用有 `channel.sensitive_write` 权限的管理请求调用 `POST /api/channel/fetch_models`，请求体如下。示例渠道 ID、域名及 Key 都要替换。仅临时预览，无需调用渠道保存接口。

```json
{
  "type": 61,
  "task_plugin_key": "sudashui",
  "channel_id": 123,
  "task_plugin_model_source_url": "https://catalog.example.com/v1/models",
  "key": "<本次预览使用的上游 Key>"
}
```

需要临时指定代理时增加 `proxy` 字段。操作权限允许使用已保存渠道时，也可通过 `GET /api/channel/fetch_models/{渠道ID}` 拉取已保存的目录。预览结果中的 `data` 是视频模型名列表，`model_details` 是按模型名分组的目录详情。目录请求可能被地址安全策略拦截，且不会跟随 HTTP 跳转。上游目录给出的价格仅作参考。

### 1.2 填模型能力和公开别名

以公开名 `my-video`、上游精确名 `future-upstream-video` 为例。三个位置各自填写，名称大小写按实际模型保持一致。

| 填写位置 | 示例 |
| --- | --- |
| 渠道模型列表 | `my-video` |
| **路由与映射 → 模型映射** | `{"my-video":"future-upstream-video"}` |
| **连接与模型** 中的苏打水模型能力编辑器 | JSON 对象，键为 `future-upstream-video` |

可以点击 **补充缺失的模型能力** 初始化缺少的条目，查看目录差异后再选择 **采用目录能力**。目录缺失的模式、比例和素材上限须人工补全。以下是一份**渠道模型能力 JSON 对象**，用于展示结构，所列规格和售价示例无关。

```json
{
  "future-upstream-video": {
    "duration": { "min": 4, "max": 12, "step": 1, "default": 6 },
    "resolutions": ["720p"],
    "aspect_ratios": ["16:9", "9:16"],
    "modes": ["text_to_video", "image_to_video", "reference_to_video", "first_last_frame"],
    "references": { "images": 3, "videos": 1, "audios": 0 },
    "billing_mode": "per_second"
  }
}
```

- 只支持固定档位时，用 `"duration":{"values":[5,10],"default":5}` 替换整个时长对象。
- `references` 填每类普通参考素材的实际数量上限。该类不可用时填 `0`。首尾帧由 `first_last_frame` 单独控制，输入时必须成对。
- `per_second` 表示用量为秒，`per_request` 表示每条视频记一次。多个苏打水渠道共用同一公开模型时，应统一计费单位。按秒和按条同时运营时，使用不同的公开别名，分别设置售价。
- 按标签改模型名或模型映射时，所有受影响的苏打水渠道都要有对应的上游能力。缺少配置的批量操作会失败并回滚。已有普通渠道转换为苏打水时，也要检查原来保留的模型与映射。

## 2. 启用异步视频并设置平台和池

1. 打开 **系统设置 → 运营设置 → 媒体设置 → 视频配置**，页面路径为 `/system-settings/operations/images`。在 **异步视频与本地存储** 勾选 **启用异步视频生成**，填写可写的 **本地存储路径** 并保存。使用 **视频就绪检查** 核对运行状态。相关环境配置包括 `REDIS_CONN_STRING`、`TASK_PLUGIN_ENABLED`、`ASYNC_IMAGE_ACTIVE_KEY_ID`、`ASYNC_IMAGE_PAYLOAD_KEYS` 和媒体签名使用的 `CRYPTO_SECRET`。已有环境使用稳定的密钥，详情见[运行依赖与存储配置](05-异步视频与统一媒体任务.md#1-准备运行依赖)。
2. 在 **视频平台策略** 选择供应商 **sudashui**，设置调用 Token 实际使用的分组，例如 `default`。启用平台和异步执行，绑定方式先选 **模型**。在模型能力目录添加公开模型后保存策略。
3. 在 **媒体设置 → 渠道池** 添加同一分组、同一平台、同一公开视频模型的绑定，选择第 1 节保存的渠道。单渠道可用池内权重 `1`。若策略使用 **模型和分辨率**，为对应档位创建绑定。480p 和 720p 对应 1K，1080p 对应 2K，4K 对应 4K。池档位只参与渠道选择，输出规格仍按请求和渠道能力校验。
4. 在本站 API Token 上核对分组、模型白名单和可用额度。使用工作台时，也要选择同一服务方和公开模型。

平台模型目录粘贴的是**数组**。以下例子沿用插件及渠道的能力，用于视频策略的模型能力输入框。

```json
[
  { "id": "my-video", "label": "苏打水示例视频", "media_type": "video" }
]
```

使用 `video_overrides` 可以收窄允许的规格。视频开关、平台策略、渠道池及价格各自保存。

### 2.1 需要混合调度时

在 **视频平台策略** 另行选择 **混合调度（mixed）**，启用异步、声明相同公开模型，再为 `mixed` 建对应分组及模型的池绑定。确认池内实际渠道支持完整请求，包括素材角色、时长、分辨率和比例。请求省略 `provider` 后，才会按已启用且符合条件的混合策略选择渠道。带 `"provider":"sudashui"` 的异步请求走指定供应商策略。

需要按原模型、时长、分辨率改走指定执行渠道时，使用已有的[条件路由配置教程](15-异步视频条件路由配置教程.md)。先让原公开模型和原渠道池可用，再配置额外的条件规则。

<a id="video-price-and-api"></a>

## 3. 保存本站售价

由超级管理员打开 **系统设置 → 计费与支付 → 模型定价 → 模型价格**，页面路径为 `/system-settings/billing/model-pricing`。按**公开模型名**定位条目，使用表达式价格编辑器。需要为共享模型单独设置苏打水价时，选择该模型的苏打水提供方覆盖。

| 渠道计费模式 | 该提供方的数值用量 | USD 售价示例 |
| --- | --- | --- |
| `per_second` | `seconds` | `tier("base", u("seconds") * 0.10)`。6 秒的表达式结果为 0.60 USD |
| `per_request` | `requests`，生成一条为 1 | `tier("base", u("requests") * 0.20)`。一条的表达式结果为 0.20 USD |

两个模式均可用 `u("resolution")` 做条件。最终预扣和结算还需结合本站分组倍率。保存前用用量和分辨率预览一笔。目录返回的 CNY `price` 和 `final_price` 只是上游展示数据。

走 `mixed` 时，在 **视频配置 → 混合视频定价** 核对同名公开模型。混合专用表达式优先，未设置时按公开模型有效表达式继承。苏打水提供方覆盖和随机选中渠道的单位都不会替代混合公开价格。已受理任务按冻结的规格、用量与价格结算。更多算例见[视频计费配置](09-视频计费配置.md#sudashui-video-20261103)。

## 4. 提交与查询

选择与实际渠道能力一致的规格。以下请求中的模型、域名和素材均需替换。苏打水生成接口使用 JSON，参考素材使用可访问的 HTTP(S) URL。普通参考素材可传单个 URL 或数组。工作台的有序 `references` 也可使用。上传文件、data URI、视频编辑和延长不属于该插件的当前生成能力。

| 需求 | 接口及请求字段 | 查询 |
| --- | --- | --- |
| 标准视频协议 | `POST /v1/videos`，JSON 不带 `provider` | 使用返回的本站视频 ID 查询 `GET /v1/videos/{id}` |
| 指定苏打水异步生成 | `POST /v1/videos/generations_async`，带 `"provider":"sudashui"` | 接收 HTTP 202，按 `query_url` 查询 `GET /v1/media/tasks_async/{task_id}` |
| 混合异步生成 | 同一异步入口，省略 `provider` | 使用同一统一任务查询入口 |

异步 JSON 示例，保存为 `video-request.json`。文生视频可去掉 `reference_images`。单图图生用 `image` 或 `input_reference`。首尾帧用 `image` 或 `first_frame` 搭配 `last_frame`，另选开启首尾帧能力的模型。

```json
{
  "provider": "sudashui",
  "model": "my-video",
  "prompt": "保留参考图中的主体外观，镜头平稳推进",
  "seconds": 6,
  "resolution": "720p",
  "aspect_ratio": "16:9",
  "reference_images": "https://cdn.example.com/reference.png"
}
```

```powershell
curl.exe -i "$env:NEW_API_BASE/v1/videos/generations_async" -H "Authorization: Bearer $env:NEW_API_TOKEN" -H 'Content-Type: application/json' --data-binary '@video-request.json'
```

`seconds` 和 `duration` 是时长别名，`resolution` 和 `size` 是分辨率别名。填每组其中一个即可，同时填时两值须一致。苏打水默认比例是 16:9，渠道必须支持该比例才能省略比例字段。已在真实渠道配置的生成请求可能产生上游费用。

## 5. 配置旧版 Drama 的混合视频素材恢复

### 5.1 确认可入队的混合请求

1. 确认已有启用的 Drama 渠道及当前实际插件。按照第 2 节配置 `mixed` 策略及渠道池，按第 3 节核对混合售价。这个兼容分支面向选中**未声明 `videoRetryInputs` 的旧版 Drama** 的混合异步视频。已声明路径的插件以自己的声明为准。
2. 用 `POST /v1/videos/generations_async` 提交时省略 `provider`。填写公开模型，且确保实际命中 Drama 渠道。素材地址应在新任务受理时可记录，并能由本站下载和校验。
3. 优先使用有序 `references`，避免同时在另一字段重复填写同一素材。对 `seedance2.5-A`，提示词按图片、视频、音频各自的顺序写明 `@图1`、`@视频1` 或 `@音频1`。本例仅用一张参考图。

```json
{
  "model": "seedance2.5-A",
  "prompt": "保留 @图1 的角色服装，镜头由近及远",
  "seconds": 6,
  "resolution": "720p",
  "aspect_ratio": "16:9",
  "references": [
    {
      "type": "image",
      "role": "reference",
      "source": { "url": "https://cdn.example.com/drama-reference.png" }
    }
  ]
}
```

旧客户端可以使用插件接受的 `referenceImages`、`image_urls` 等别名。将上述 `references` 整段替换为 `"referenceImages":["https://cdn.example.com/drama-reference.png"]` 可表达同一张参考图。旧版兼容也识别对象 URL 和大写 `HTTPS://`。对象含有效 `url` 时优先使用它，替换仅发生在插件使用的字段。图片、视频和音频的原顺序及角色保留。首尾帧别名只适用于对应型号原本支持的模式，例如旧版 `seedance2.0-A` 的 `first_image`、`last_image`。带参考视频的混合请求会据此记录公开计费条件 `video_input=video`。

### 5.2 添加只匹配明确素材失败的规则

打开 **媒体设置 → 错误与重试规则**。优先从管理员可见的失败样本创建草稿，保留真实样本的供应商、模型、处理阶段和错误短语。手填一条保守规则时可使用下表。

| 字段 | 建议填写 |
| --- | --- |
| 规则名称和启用状态 | `Drama 终态素材下载失败`，启用 |
| 媒体类型 | 视频 `video` |
| 供应商 | `drama`。混合请求的策略是 `mixed`，错误样本记录实际执行插件 |
| 模型、渠道 | 填要试用的公开模型和实际 Drama 渠道 ID，或按站点范围留空 |
| 处理阶段 | `terminal`，只匹配已确认的终态失败 |
| 匹配词 | 使用样本里的具体短语，例如 `素材下载超时` 或 `参考图下载失败`。按界面每行一项填写，避免仅填 `超时` |
| 错误分类 | **参考素材下载失败** `reference_download` |
| 第一步 | **本机下载后原渠道重试** `local_same_channel`，最多 1 次 |
| 耗尽动作 | **人工核对** `manual_review`，便于首次验收 |

**素材下载恢复模板**会填入分类和两步恢复动作。模板第二步是本机下载后换渠道，默认最多 2 次。只验原渠道时删除第二步，再补范围、匹配词和耗尽动作。需要跨渠道时，目标仍需通过当前分组、模型、插件版本和素材能力校验。规则按优先级匹配，确认全局未暂停自动重提后，点击 **保存并生效**。保存冲突时重新加载最新配置再编辑。

在样本测试中核对 **命中规则、下一动作、阻止原因**。用同一范围的普通排队超时或内容审核失败做反例，确认不会命中这条规则。样本测试只验证文字或当前任务事实，实际恢复时才下载素材。对未知提交结果或已有产物的任务，使用现有查询、保存或核对流程。自定义重试仍受全局预算、权限、原请求与预扣、任务期限和实际插件指纹约束。详情见[错误与重试规则](13-异步媒体错误与重试规则.md)。

### 5.3 验收与停止试用

- 用新任务记录本站任务 ID。由上游明确报告素材拉取失败后，管理员任务详情应显示实际插件、命中规则、恢复动作和结果。本站会先校验并保存素材，再以本站签名 URL 替换冻结槽位。真实上游恢复提交需要能访问该签名 URL。
- 核对公网访问入口、签名及文件有效期、存储写权限和原任务期限。提示词中的 URL、私有素材 ID 和内嵌数据不会当作远程 URL 抓取。
- 验收时核对本站任务 ID 和原预扣。恢复沿用同一笔预扣和冻结价格。明确失败按现有退款规则处理，未知上游结果保留核对信息。
- 需要结束这条试用规则时，禁用该规则并保存。其他有效规则仍可能匹配。需要全局停止替代生成时使用 **暂停自动重新提交**，已有任务查询和账务恢复继续运行。改规则不会自动重新派发已经结束的历史任务。

## 6. 常见问题

| 现象 | 先查什么 |
| --- | --- |
| 改了目录地址，点获取提示需要 API Key | 已有渠道编辑抽屉不会发送草稿 Key。确认目录或代理是否仍等于已保存设置，或用第 1.1 节的管理预览请求 |
| 能拉目录，渠道保存报模型缺少能力 | 模型列表用公开名，模型映射指向精确上游名，能力 JSON 的键用上游名。检查目录缺失的时长、模式、比例和上限 |
| 工作台没有模型，或报无可用渠道 | 核对实际插件、视频开关、平台策略、`media_type`、启用渠道、池绑定方式、Token 分组和白名单 |
| 表达式报 `seconds` 或 `requests` 不支持 | 确认实际提供方的 `billing_mode` 与表达式字段。混合价在 mixed 的公开定价处检查 |
| 素材恢复显示 `local_reference_transport_unavailable` | 检查实际插件版本、请求槽位、原任务是否冻结可下载 URL，以及是否混入插件无法替换的素材。旧任务的快照无法靠改规则补齐 |
| 已命中规则，未派发替代任务 | 看管理员详情中的资格检查、余额预扣、运行暂停、重试预算、任务期限和渠道可用性 |
| 提交成功，成品暂时不可下载 | 用本站任务 ID 查看任务状态和文件状态。完成后使用查询结果提供的内容地址，检查过期或下载签名 |

本地验证记录见[11 月台账](14-2026年11月代码变更台账.md#sudashui-drama-config-smoke-20261104)。
