# Drama 视频 A / E / F / G / H3：适用、配置与注意事项

本指南用于在当前 new-api 中接入 **Drama Seedance A / E / F / G 与 minimax-h3 视频渠道**，对应任务插件 `drama` 1.1.3，共 18 个型号。后台配置和[供应商文档](https://drama.dafeiyangapi.top/docs/drama)按 **2026-10-15** 核对；账户实际开通型号、余额和供应商价格仍以其控制台为准。

**已有 E/F/G 渠道，准备追加 A 与 H3：直接按 [第 0.10 节](#drama-add-a-h3) 操作。** 本次新增 `seedance2.0-A`、`seedance2.5-A`、`minimax-h3`，三款均按秒计费。A fast、Mini、A 2.5 首尾帧和 `minimax-h3-2k` 未在本次开放。

**你已经部署新版本、现在正填写后台：从下面第 0 节开始，按顺序做到 0.9。** 这条操作路径使用一个上游账号、一条渠道、一个分组，先开放 E / F / G 各一个型号，第一条只测试 F 的纯文本视频。第 1–10 节用于查其他型号、API 调用和进阶注意事项，无需先读完。

阅读顺序：[已部署后台照填步骤](#drama-backend-setup) → [适用范围](#1-适用范围) → [准备运行环境](#3-准备运行环境) → [配置渠道](#4-配置渠道) → [配置视频策略与渠道池](#5-配置视频策略与渠道池) → [配置价格](#6-配置价格) → [调用与验收](#7-调用与验收) → [配置注意事项](#8-配置注意事项) → [排错表](#9-排错表)。

**E / F / G 完整请求：** [十五条可复制 API 示例](../异步生图API接口文档.md#drama-efg-examples)按系列分别提供文本、参考图 URL、参考视频 URL、参考音频 URL、三者混合。站内 `/guide/async-image-api#image-guide-video` 同步提供五类卡片；G 的音频单独参考示例专用 `seedance2.5-G`，F 的参考视频会切换实际 Token 用量分支。

**定价分辨率按需显示：** `drama` 1.1.3 为全部 A / E / F / G / H3 视频型号统一保留 480p / 720p / 1080p / 4k 四行可视化定价，另保留 F 的 `720px`、站点 H3 2K 的 `2k`；支持的档位设置单价，不支持的设为 0。`seedance2.0-fast-E` 的生成能力包括 720p 和 4k。站点上传覆盖插件需同步其元数据后激活。后台“清空价格”清零整行并保存后，模型广场隐藏该分辨率的零价报价，重新填写非零价格恢复显示。零价 API 仍免费，不能作为禁用开关；具体步骤与服务方覆盖范围见[分辨率报价展示](09-视频计费配置.md#resolution-price-visibility)。

## 模型广场：按型号填写能力与限制

在 `/models/metadata` 选择具体模型，打开“编辑 → 模型元数据”，在“描述”中按行填写限制并保存元数据。描述与价格、渠道绑定分别保存；描述中的数字不会自动改变插件能力或实际售价。视频卡片依据已有 `openai-video` 端点标识显示六行摘要，并保留换行；“详情”展示完整说明。普通模型仍使用两行摘要，继续复用已有模型卡片与详情按钮。

建议把最重要的内容放在前两行：“输出时长与本站分辨率”“各类素材数量与合计上限”；后续再写模式、比例、媒体规格、引用要求和计费口径。

| 具体型号 | 输出时长 | 本站或型号分辨率 | 参考图片 / 视频 / 音频与合计 |
| --- | --- | --- | --- |
| `seedance2.0-A` | 4–15 秒 | 本站 480P / 720P / 1080P；上游另列 4K，本站未开通 | 9 / 3 / 3，合计最多 12 |
| `seedance2.5-A` | 4–30 秒 | 480P / 720P | 30 / 10 / 10，合计最多 50 |
| `seedance2.0-E` | 4–15 秒 | 480P / 720P / 1080P / 4K | 9 / 3 / 3，合计最多 15 |
| `seedance2.0-fast-E` | 4–15 秒 | 720P / 4K | 9 / 3 / 3，合计最多 15 |
| `seedance2.0-Mini-E` | 4–15 秒 | 480P / 720P | 9 / 3 / 3，合计最多 15 |
| `seedance2.5-E` | 4–30 秒 | 480P / 720P / 1080P | 30 / 10 / 10，合计最多 50 |
| `seedance2.0-F` | 4–15 秒 | 请求必须使用 `720px` | 图片最多 9，视频与音频合计最多 3，全部合计最多 12 |
| `seedance2.5-F` | 4–30 秒 | 720P | 图片最多 9，视频与音频合计最多 3，全部合计最多 12 |
| `seedance2.0-G` | 4–15 秒 | 480P / 720P / 1080P / 4K | 9 / 3 / 3，合计最多 15 |
| `seedance2.0-fast-G` / `seedance2.0-mini-G` | 4–15 秒 | 480P / 720P | 9 / 3 / 3，合计最多 15 |
| `seedance2.5-G` | 4–30 秒 | 480P / 720P / 1080P | 30 / 10 / 10，合计最多 50 |
| 站点扩展 `minimax-h3-2k` | 固定 15 秒 | 固定 2K | 9 / 3 / 3，合计最多 10 |

以上分辨率中的“本站”指本次站点激活的覆盖插件限制；其他部署应按自身能力表填写，不能直接复制。本次为上述 13 个新接口型号及 5 个旧分辨率后缀型号录入说明，未重启普通 `minimax-h3` 的上游验收。A fast/Mini 未在本插件接入，不根据上游泛化描述虚构它们的参数。

关键组合限制来自当日[上游文档第 3、4、11、12、13、15 节](https://drama.dafeiyangapi.top/docs/drama)，并与当前激活插件逐项核对：

- A 的每份普通参考素材都必须在提示词中按类型编号引用。A 2.0 成对首尾帧只使用 `Auto`，不能混合普通参考；A 2.5 不开放首尾帧。两款素材均为 HTTPS，单文件最多 100MB；2.0 的参考视频/音频累计分别最多 15 秒，2.5 为 30 秒。
- 新 E 与 F 使用普通参考，不支持首尾帧和 Auto。F 2.5 的素材数量仍为 9 图、视频与音频合计 3 条，不能照抄 A/E/G 2.5 的 30/10/10。E 按条；F 上游无参考视频按秒、有参考视频按实际 Token，本站实际报价由管理员表达式决定。
- 新 G 支持首帧和首尾帧，但不能混合普通参考。G 2.0/fast/mini 的音频还需图片或视频；仅 G 2.5 允许纯音频参考。G 2.5 的首帧、首尾帧、编辑和延长须使用 adaptive；视频编辑或向后延长还需源视频。
- G 图片单张小于 30MB，视频单段最多 200MB、24–60 FPS，音频单段最多 15MB；2.0 的视频和音频各累计最多 15 秒，2.5 为 30 秒。完整格式、像素范围和素材角色写入具体模型说明。
- H3 2K 每条参考视频都要填写真实 `duration_seconds > 0`，多条视频总时长最多 15 秒；输出固定 15 秒，比例仅 16:9、9:16、1:1，提示词 1–6000 字符，不支持首尾帧。该型号属于站点覆盖插件，不能据此推断仓库内置 18 型号目录也含有它。

只有具备可用渠道与分组的模型会进入当前模型广场。预先录入 F/G 元数据不会自动给渠道追加模型、开通路由或配置售价；启用相应渠道后使用已保存说明。此次元数据更新保留原价格、路由和模型开放状态。

## 0. 已部署新版本：照着填写后台

### 0.1 先确定本次要填的值

本节以 **`default` 分组、渠道名 `Drama-EFG`、三个型号全部测试 720p** 为完整实例。`default` 只是实例值：在自己的“API 密钥”页面选定一把测试 Key，查看其主分组，选择一个当前用户可用的具体分组。若实际使用 `vip`，下面**渠道分组、视频平台策略分组、渠道池分组、测试 Key 主分组**四处全部改为 `vip`。

首次排查使用具体分组，先不要引入 `auto` 的跨组选择；可以单独创建测试 Key，保留已有业务 Key 的配置。Token 主分组留空时会跟随用户分组，不要把空值误认为 `default`。图片专用的 OpenAI / Gemini 分组设置不需要为 Drama 单独填写。

| 需要准备的值 | 本例用什么 | 你自己要怎么换 |
| --- | --- | --- |
| 本站地址 | `https://your-new-api.example` | 换成你现在登录后台的本站地址；后文菜单路径接在这个地址后面 |
| 本站测试分组 | `default` | 换成测试用户与 Key 有权使用的具体分组，四处保持一致 |
| 上游账号密钥 | Drama 账户创建的用户令牌 | 只在第 0.3 步的渠道密钥框填写，不发给本站用户 |
| 本站测试 Key | 本站 `/keys` 中的一把 API Key | 在工作台选择它；通过 API 调用时使用其密钥 |
| 渠道名称 | `Drama-EFG` | 可原样用，也可以用自己的名称；创建后记住实际渠道编号 |

本例先开放下列三个型号，每个系列一个：

| 系列 | 渠道、策略、价格中都用这个完整型号 | 第一次测试参数 |
| --- | --- | --- |
| E | `seedance2.0-E` | 8 秒、720p、16:9、纯文本 |
| F | `seedance2.5-F` | 8 秒、720p、16:9、纯文本 |
| G | `seedance2.5-G` | 8 秒、720p、adaptive、纯文本 |

三个型号都必须已在你的 Drama 上游账号开通。若只开通 F，下面渠道模型、平台策略 JSON、渠道池和价格都只保留 F；不需要为未开通型号填写无效配置。

本次会用到的页面如下。地址栏只更换路径，保留你自己的站点域名：

| 要做什么 | 后台菜单或地址 | 进入后还要点什么 |
| --- | --- | --- |
| 检查插件 | 管理区 → 任务插件，`/task-plugins` | 已安装；右上角“启用任务插件” |
| 添加上游账号 | 管理区 → 渠道，`/channels` | 创建渠道 → 搜索 `drama` |
| 开视频与配策略 | 系统设置 → 运维 → 媒体设置，`/system-settings/operations/images` | 页面内的“视频配置”选项卡 |
| 配渠道池 | 同一个媒体设置页面 | 页面内另一个“渠道池”选项卡 |

### 0.2 任务插件页面：确认 drama 可用

1. 打开本站 `/task-plugins`，进入“已安装”。
2. 右上角 **“启用任务插件”**保持开启。若关闭，打开后应出现“任务插件设置已更新”，这是即时保存，不需要另找页面底部保存按钮。
3. 找到 **Drama Video A / E / F / G / H3**，查看 key 为 `drama`、激活版本为 `1.1.0`。
4. 出厂插件不能单独停用，不需要再为它找一个单独启用开关。若有自定义覆盖版本，确认实际激活的是你要用的版本。

**本步完成标志：**列表能看到 `drama`，任务插件总开关开启。已部署包含它的版本时，不必再上传一次源文件，也不必仅为开启总开关而修改服务器环境变量。

找不到该插件时先检查实际运行版本；不要继续创建其他类型的渠道代替。版本和上传兼容要求见第 3.1 节。

### 0.3 渠道页面：一条渠道放入 E / F / G

1. 打开 `/channels`，点击 **“创建渠道”**。
2. 新版首先显示供应商选择页面。在搜索框输入 `drama`，点击 **Drama Video A / E / F / G / H3** 卡片；也可先切换“插件”分类再找它。选择后会自动绑定任务插件类型 61 和 key `drama`，**不需要在新版页面寻找一个填写数字 61 的输入框**。
3. 进入 **“连接与模型”**，按下表填写。不同屏幕可能需要向下滚动，模型和分组也在这个选项卡里。

| 看到的字段或区域 | 本例填写 | 具体操作 |
| --- | --- | --- |
| 名称 | `Drama-EFG` | 只是本站渠道名称，不是模型名 |
| API 地址 / Base URL | `https://drama.dafeiyangapi.top` | 即使插件已自动填入也核对一次；不要带 `/v1` 或文档路径 |
| API 密钥 | 你的 Drama 上游用户令牌本体 | 不加 `Bearer ` 前缀；首次只用一个账号的一把令牌 |
| 模型 | `seedance2.0-E`、`seedance2.5-F`、`seedance2.5-G` | 这里是**多选框**，不是 JSON 输入框；选择插件时可能已自动加入 18 项，首次只保留本次要开的三项 |
| 分组 | 勾选 `default` | 如使用其他实际分组，改成第 0.1 节确定的那个；这是多选区域，确保目标分组被选中 |

如模型多选框没有某一项，输入其完整型号后使用“添加自定义模型”选项加入。不要在这里粘贴第 0.5 节的 JSON，也不要填写 `drama:seedance2.5-F` 这种拼接值。

新建专用渠道的 **“路由与映射”**先保留默认：无需增加模型映射、参数覆盖或“上游异步任务”规则。插件已经处理此上游的异步协议。若是在改已有渠道，按第 4.2 节检查匹配规则，保留其他业务的配置。

4. 点击抽屉底部 **“创建渠道”**；编辑现有渠道时按钮为 **“更新渠道”**。
5. 返回列表找到 `Drama-EFG`，确认渠道启用，记下实际编号，例如 `123`。这个 `123` 仅是举例，后面在池内选择你真实创建的那条。
6. 重新编辑一次，确认地址、三个模型和分组都已保存。密钥可能隐藏显示，无需为了核对而重新粘贴或公开它。

**本步完成标志：**渠道列表存在一条启用的 Drama 渠道，模型与分组正确。插件详情中的型号清单不能代替这条渠道；仅启用插件还没有配置上游账号。

### 0.4 视频配置页面：先开全局视频，再看就绪检查

打开 `/system-settings/operations/images`，点击顶部 **“视频配置”**。页面有三块：上方“视频就绪检查”、中间“异步视频与本地存储”、下方“视频平台策略”。

先填写中间的 **“异步视频与本地存储”**：

| 页面字段 | 已有可用配置时 | 第一次配置时的填写参考 |
| --- | --- | --- |
| 启用异步视频生成 | 保持勾选 | 勾选 |
| 本地存储路径 | 保留正在使用的持久化目录 | 仓库 Docker 部署、容器持久化挂载为 `/data` 时填 `/data/media`；其他部署按第 3.3 节确认路径 |
| 视频保留时间（天） | 沿用现值 | `90` |
| 链接有效期（秒） | 沿用现值 | `3600` |
| 视频单文件大小上限（字节） | 沿用现值 | `1073741824` |
| 视频下载时限（秒） | 沿用现值 | `900` |
| 视频下载并发数 | 沿用现值 | `2` |
| 存储重试次数 | 沿用现值 | `5` |

点击**这张存储卡片里的“保存”**，然后看上方“视频就绪检查”。保存前全局视频开关为红色是正常的，不要还没开开关就反复改插件或渠道。

| 仍然未通过的检查项 | 现在做什么 |
| --- | --- |
| 全局视频开关 | 确认刚才勾选并保存了“启用异步视频生成” |
| 视频任务插件 | 回第 0.2 步，检查总开关、激活插件和实际服务版本 |
| Redis 队列 | 这是服务运行依赖问题，按第 3.2 节处理 Redis；不在策略 JSON 填连接地址 |
| 载荷加密密钥 | 按第 3.2 节检查 `ASYNC_IMAGE_*`；已有图片异步可用时先核对现有密钥，保留旧键 |
| 媒体签名密钥 | 按第 3.2 节核对服务已有稳定签名密钥；不在渠道 API 密钥中填写它 |

**本步完成标志：**这五项都通过。已部署新版本不等于视频总开关自动打开；就绪全通过也不等于后续分组、池和价格已经保存。

另外核对 `/system-settings/site/system-info` 的站点访问地址 `ServerAddress` 是你自己的外部访问地址，例如 `https://your-new-api.example`，不是 Drama 上游地址。已有正确值保持不变；否则任务查询和结果链接可能指向错误域名。

### 0.5 同一页面下方：保存视频平台策略

仍在 **“视频配置”**选项卡，向下找到 **“视频平台策略”**，按下表填写：

| 实际字段名称 | 本例选值 |
| --- | --- |
| 分组 | `default`，或第 0.1 节确定的实际分组 |
| 提供商 | **Drama Video A / E / F / G / H3 · drama** |
| 渠道池绑定 | **模型与分辨率** |
| 启用媒体平台 | 勾选 |
| 使用异步执行 | 勾选 |
| 图片与视频联合模型目录 | 在这一个大文本框粘贴下面的 JSON 数组 |

**先选好分组和 Drama 提供商，再改目录与勾选项**；切换分组或提供商会加载其已保存配置，未保存输入可能被替换。首次创建该分组的 Drama 策略时，可整段粘贴：

```json
[
  {
    "id": "seedance2.0-E",
    "label": "Drama E 2.0",
    "media_type": "video",
    "video_overrides": {}
  },
  {
    "id": "seedance2.5-F",
    "label": "Drama F 2.5",
    "media_type": "video",
    "video_overrides": {}
  },
  {
    "id": "seedance2.5-G",
    "label": "Drama G 2.5",
    "media_type": "video",
    "video_overrides": {}
  }
]
```

只复制 `[` 到 `]`，不复制代码围栏；已有 Drama 策略包含其他需要保留的条目时，把这三项合并进去，不要覆盖整份已有目录。`label` 是用户看到的名称，`id` 才是必须与渠道和请求一致的型号。

点击该卡片底部 **“保存视频策略”**。它与上一步存储卡片的“保存”是两个按钮，必须分别点击。刷新页面后重新选择同一分组、同一 Drama 提供商，确认两个复选框仍勾选、三条目录仍在。

**本步完成标志：**`default + drama`（或实际分组）的策略已保存。暂时不要点“导入 drama 视频模型”，它会把插件声明的更多型号加进目录；也不要用旁边“视频配置示例”弹窗中的 xAI / Doubao 样例替换这份配置。

第一条按下表操作：

### 0.7 模型价格页面：每个型号分别保存 Drama 售价

打开 `/system-settings/billing/model-pricing`。下面数字仅为**本站售卖 USD 示例**，不是上游报价；正式开放前将 `0.50`、`0.10`、`10` 换成自己确定的售卖单价。

每个型号按同一套步骤配置一次：

1. 搜索完整型号，例如 `seedance2.5-F`；打开其编辑器。若列表没有，点“添加模型定价”，模型名称准确填 `seedance2.5-F`。
2. 货币先选 **USD**。
3. 编辑器上方应有 **“默认” / “Drama Video A / E / F / G / H3”**服务方页签，本例选择 **Drama**，打开 **“为此服务方单独设置”**。这样明确给 `drama` 保存价格，不依赖其他服务方或旧默认价。
4. 在任务定价的 **“编辑器模式”**选择 **“表达式编辑器”**，将对应表达式粘贴到 **“计费表达式”**大文本框。不要粘到请求规则里；不要选“按 Token（已弃用）”或“按次（已弃用）”。
5. 点击价格抽屉底部 **“保存模型价格”**。换型号前先保存，三种型号需要保存三次。

| 模型名称 | 复制这一行表达式 | 本例如何收费 |
| --- | --- | --- |
| `seedance2.0-E` | `tier("video", u("requests") * 0.50)` | 每条 0.50 USD，时长不乘单价 |
| `seedance2.5-F` | `u("video_input") == "video" ? tier("tokens", u("tokens") * 10 / 1000000) : tier("seconds", u("seconds") * 0.10)` | 无视频参考 0.10 USD/秒；有视频参考 10 USD/百万实际 Token |

**本步完成标志：**重新打开同一型号的 Drama 价格，专属开关仍开、表达式与刚才填写一致。选 USD，在“费用试算”检查：E 的 `requests=1` 为 0.50；F 的 `video_input=none, seconds=8` 为 0.80；F 的 `video_input=video, tokens=600037` 为 6.00037；G 的 `tokens=432900` 为 4.329。试算不包含分组倍率；实际扣费还会应用生效倍率。

#### 第一步：确认插件实际激活为 1.1.0

首次连通测试可在三个模型的“计费表达式原文”中分别保存以下表达式：


这是 **USD 0.10 / 秒的演示售价**，不是供应商报价，不会自动写入；请按自己的实际售价修改 `0.10`。4 秒试算为 USD 0.40，8 秒为 USD 0.80，实际扣费还会应用分组倍率。每个模型都要独立保存，保存一个不会自动配置另外两个。

#### 第六步：更新本站测试 Key，并逐款首次验收

1. 打开 `/keys`，编辑本站测试 Key，确认实际分组一致、未过期、余额与额度足够。
2. 如果“高级设置 → 模型限制”已启用，在允许列表中追加三项，保留原来的模型；点击“保存更改”。这里使用本站 Key，不是渠道里的上游令牌。
3. 打开 `/image-workbench` → “视频”，先选这把 Key，再分别选择三个 Drama 型号。
4. 首次均选“文生视频”、4 秒、720p、16:9；提示词填“海面日出，镜头缓慢前移”，不加图片、视频、音频。H3 可将音频开关关闭。
5. 每款分别提交一次，记录**本站**任务号。在任务中心确认 `queued/running` 最终变为 `succeeded`、计费和保存成功，播放或下载 `data[].url` 中的本站结果。HTTP 202 只表示接收。

通过 API 验收时，三款都可以用下面的 PowerShell，**每款单独执行，按实际测试修改 `$model`**。它会对同一个本站任务最多查询 120 次、每 10 秒一次，失败立即停止；查询达到上限时保留任务号，不自动重新生成：

```powershell
$base = 'https://your-new-api.example'
$model = 'seedance2.0-A' # 另两款：seedance2.5-A、minimax-h3
$headers = @{
  Authorization = "Bearer $env:NEW_API_TOKEN"
  'Idempotency-Key' = [guid]::NewGuid().ToString()
}
$body = @{
  provider = 'drama'
  model = $model
  prompt = '海面日出，镜头缓慢前移'
  seconds = 4
  resolution = '720p'
  aspect_ratio = '16:9'
}
if ($model -eq 'minimax-h3') { $body.generate_audio = $false }
$created = Invoke-RestMethod -Method Post -Uri "$base/v1/videos/generations_async" `
  -Headers $headers -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes(($body | ConvertTo-Json -Depth 8)))
$taskId = $created.task_id
if (-not $taskId) { throw '未收到本站 task_id，请检查受理回包' }
Write-Output "本站任务号：$taskId"
for ($attempt = 0; $attempt -lt 120; $attempt++) {
  $task = Invoke-RestMethod -Uri "$base/v1/media/tasks_async/$taskId" -Headers $headers
  if ($task.status -eq 'failed') { throw $task.fail_reason }
  if ($task.status -eq 'succeeded') {
    $url = $task.data[0].url
    if (-not $url) { throw '任务成功但没有结果 URL，请查看保存状态' }
    $downloadHeaders = @{}
    if (([uri]$url).GetLeftPart([UriPartial]::Authority) -eq ([uri]$base).GetLeftPart([UriPartial]::Authority)) {
      $downloadHeaders.Authorization = $headers.Authorization
    }
    Invoke-WebRequest -Uri $url -Headers $downloadHeaders -OutFile './drama-result.mp4'
    break
  }
  Start-Sleep -Seconds 10
}
if ($task.status -ne 'succeeded') { throw "查询次数已达上限，保留任务号继续查询：$taskId" }
```

把 `$base` 改为本站地址，先在本机设置环境变量 `NEW_API_TOKEN` 为本站测试 Key。脚本中的任务状态是本站持久化状态，不能替换为上游 `completed`。同一请求重试需复用原幂等键；重新运行整段会创建新键，属于新的付费生成。参考素材请求见[接口文档示例 D7–D10](../异步生图API接口文档.md#drama-a-h3-examples)。

#### 新三款的常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 工作台没有新型号 | 依次检查激活插件 1.1.0、渠道模型、多模型策略目录、Key 分组和允许列表；刷新模型能力 |
| `model_price_error` 或价格编辑器只有 Token 字段 | 确认选中 Drama 的准确型号及专属价；新三款用 `u("seconds")`，不是 `u("tokens")` |
| A 素材索引 / 未引用错误 | 每类数组从 1 编号；`@图1` 与 `@图片1` 等价；每个普通素材都要引用，不能用 `@图01`、越界编号 |
| 单张 `image` 调 A 2.0 失败 | `image` 表示首帧，必须同时提供 `last_frame`，比例为 `Auto`；普通单图用 `reference_images` 并在 prompt 写 `@图1` |
| A 2.5 的首尾帧或 1080p 被拒绝 | 当前接入只开放文生、普通参考、480p/720p；不能沿用 G 2.5 的参数 |
| H3 的 2k 或首尾帧被拒绝 | 本次只接 `minimax-h3`，不含 `minimax-h3-2k`；普通图片放在 `reference_images` |
| 上游返回素材下载或格式错误 | URL 应指向真实媒体文件，且上游服务端无需登录即可读取；素材文件大小、MIME、像素和时长还由上游检查 |

## 1. 适用范围

### 1.1 适用场景

- 通过本站视频工作台调用已开通的 E / F / G 型号。
- 通过同一 `drama` 渠道调用 `seedance2.0-A`、`seedance2.5-A`、`minimax-h3`，按秒设置售价；A 普通参考使用编号提示词，A 2.0 可用成对首尾帧。
- 通过本站持久化异步接口提交视频任务，由本站后台完成上游提交、轮询、结算、下载和保存。
- 现有 OpenAI 视频客户端使用本站 `/v1/videos`、对应查询和下载接口。
- `seedance2.5-G` 的首帧、首尾帧、视频编辑和向后延长。

本插件接入的是 **视频任务**，不处理聊天、图片生成或其他尚未声明的型号。新 E/F 使用普通参考素材；新 G 支持首帧和首尾帧，A 2.0 另支持成对首尾帧。素材库方面只支持引用已有 G `asset://ID`，本次没有增加素材上传、素材组或素材管理 API。

### 1.2 两个地址、两把令牌要分清

| 内容 | 用在哪里 | 示例或来源 |
| --- | --- | --- |
| 上游 API 地址 | 本站渠道的 API 地址 | `https://drama.dafeiyangapi.top` |
| 上游用户令牌 | 本站渠道的密钥 | 在 Drama 上游账户中创建；由本站服务端向上游使用 |
| 本站访问地址 | 工作台访问、客户端请求、对外查询与结果链接 | `https://your-new-api.example`，换成自己的站点 |
| 本站 API Token | 客户端调用本站接口 | 在本站令牌管理中创建；属于有权限调用视频的用户和分组 |

客户端向**本站地址**发送**本站 Token**。上游令牌只填渠道密钥，不放入用户请求 JSON、平台策略、价格表达式或公开示例。

### 1.3 本站接口与上游接口的关系

| 操作 | 客户端调用本站 | 本站后台调用上游 |
| --- | --- | --- |
| 持久化生成 | `POST /v1/videos/generations_async` | 根据型号选择 `POST /v1/videos` 或 `POST /v1/video/generations` |
| 查询持久化任务 | `GET /v1/media/tasks_async/{本地任务号}` | 使用已保存的上游任务号查询 |
| 获取成片 | 读取本站查询回包中的 `data[].url` | `GET /v1/videos/{上游任务号}/content`，附带渠道令牌 |
| G 2.5 视频编辑 | `POST /v1/videos/edits_async` | `POST /v1/videos`，插件转换编辑参数 |
| G 2.5 向后延长 | `POST /v1/videos/extensions_async` | `POST /v1/videos`，插件转换延长参数 |

上游也是异步任务不需要额外再搭一套轮询服务。对外持久化接口返回的 `task_id` 是**本站任务号**，不能替换成上游 `id`。标准 `/v1/videos` 的任务对象与持久化 `_async` 回包也不同，不要混用两套查询 URL 或状态值。

### 2.3 素材数量与选项

| 型号组 | 图片上限 | 视频上限 | 音频上限 | 额外限制 |
| --- | ---: | ---: | ---: | --- |
| 新 E 2.0 系列 | 9 | 3 | 3 | 普通参考，不接受首尾帧 |
| 新 E 2.5 | 30 | 10 | 10 | 同上 |
| 新 F 两个型号 | 9 | 3 | 3 | **视频与音频合计最多 3 个**，不接受首尾帧 |
| 新 G 2.0 系列 | 9 | 3 | 3 | 仅音频参考时还必须提供图片或视频 |
| 新 G 2.5 | 30 | 10 | 10 | 支持纯音频参考；编辑主视频也占视频数量 |
| 旧 E / G | 9 | 3 | 3 | 普通参考 |
| 旧 F | 9 | 0 | 3 | 普通参考 |

本表的 E/F/G 中，`generate_audio` 仅新 F / G 接受；新增 H3 也接受该字段。`watermark`、`return_last_frame` 仅新 G 接受。显式 `false` 会保留。A、E 与旧型号即使传 `generate_audio: false` 也会因不支持该字段而拒绝，不能只修改音频请求的模型名就提交。

### 2.4 新 A 与 H3 型号（1.1.0）

| 型号 | 时长 | 分辨率 | 比例 | 素材与模式 |
| --- | --- | --- | --- | --- |
| `seedance2.0-A` | 4–15 秒 | 480p、720p、1080p、4k | 六种固定比例及 `Auto`；默认 16:9 | 文生、普通参考、成对首尾帧 |
| `seedance2.5-A` | 4–30 秒 | 480p、720p | 六种固定比例；默认 16:9 | 文生、普通参考 |
| `minimax-h3` | 4–15 秒 | 480p、720p、1080p | 16:9、9:16；默认 16:9 | 文生、普通参考；可用 `generate_audio` |

三款默认 4 秒、480p；`seconds` 和 `duration` 可兼容使用，但同时填写必须一致。新型号只按 `seconds`、`resolution` 提供计价用量，不提供 Token。A 2.0 的 `Auto` 可兼容小写 `auto`，不能照搬 G 的 `adaptive`；首尾帧省略比例时自动使用 `Auto`。六种固定比例为 16:9、4:3、1:1、3:4、9:16、21:9。

| 型号 | 图片 | 视频 | 音频 | 总量与其他限制 |
| --- | ---: | ---: | ---: | --- |
| A 2.0 | 9 | 3 | 3 | 合计 ≤12；普通参考必须逐项在 prompt 引用 |
| A 2.5 | 30 | 10 | 10 | 合计 ≤50；同上；本次不开放首尾帧 |
| H3 | 9 | 3 | 3 | 视频与音频合计 ≤3，总量 ≤12；不支持首尾帧；不强制编号引用 |

素材只接收 JSON 中的公网 HTTPS URL，不支持上传文件、Data URI、`asset://` 或本机路径。同一请求中不能重复 URL。A 2.0 单个 `image`/`input_reference` 表示首帧，必须配 `last_frame`；`first_image`/`last_image` 为首尾帧兼容别名，不能与对应的标准字段重复填写。普通单图统一用 `reference_images: ["https://..."]`，避免混淆。A 的普通参考编号按每类素材出现顺序分别计算，`@图片1` 和 `@图1` 等价。

插件校验 URL 形式、数量、角色、时长参数和 A 普通素材编号，不下载参考素材来测量时长、像素或文件大小。上游仍会校验真实媒体；按其当前文档，A 2.0 参考视频总时长最多 15 秒、A 2.5 最多 30 秒；H3 参考视频总时长建议不超过 15 秒。准确文件规格以供应商文档与账号能力为准。

## 3. 准备运行环境

### 3.1 插件与部署版本

在 `/task-plugins` 检查插件 key 为 `drama`、激活版本为 1.1.0，并能看到本指南的 18 个型号。

- 使用包含本次代码的服务二进制或镜像：插件已内置，启用后可绑定渠道。
- 使用已有服务上传插件：从仓库选择 [`plugins/tasks/drama/plugin.js`](../plugins/tasks/drama/plugin.js)，通过任务插件管理导入并启用。宿主必须支持当前 Task Plugin API v1 的 `usageProfiles`、`videoProfiles` 和视频编辑/延长能力；较老宿主可能拒绝元数据，应先升级宿主。
- 存在同名上传覆盖插件时，核对**实际激活来源与版本**。仅看到内置文件或覆盖文件已保存，不代表本次版本正在执行。

上传只选择插件源文件，不要把本 Markdown、完整文件夹或其他供应商插件作为 `drama` 导入。

### 3.2 视频就绪检查

进入 `/system-settings/operations/images` → **视频配置**，先查看视频就绪状态：

| 检查项 | 配置或预期 |
| --- | --- |
| 视频总开关 | 勾选启用异步视频生成并保存 |
| 视频任务插件 | `/task-plugins` 的“启用任务插件”总开关开启，且 `drama` 实际激活；这是后台可保存设置 |
| Redis | `REDIS_CONN_STRING` 指向可访问 Redis；健康检查通过 |
| 载荷加密 | `ASYNC_IMAGE_ACTIVE_KEY_ID` 与 `ASYNC_IMAGE_PAYLOAD_KEYS` 中键名匹配；密钥 Base64 解码后恰好 32 字节 |
| 媒体签名 | 已有稳定的 `CRYPTO_SECRET`，或当前宿主使用的稳定 `SESSION_SECRET` 回退 |

`ASYNC_IMAGE_*` 虽保留图片命名，视频请求载荷也使用它们。已有环境不要随意更换密钥；多实例需保持一致，轮换时保留仍用于在途任务的旧键。具体生成方法与部署注入示例见[准备运行依赖](05-异步视频与统一媒体任务.md#1-准备运行依赖)。

任务插件总开关可以在后台直接修改并即时生效。`TASK_PLUGIN_ENABLED` 只是启动默认值来源，当前代码默认 `true`；已有的后台持久化设置会覆盖这个默认值。排查时以后台总开关和就绪检查为准，不要仅看到环境变量为 `true` 就认为插件已开启。

`REDIS_CONN_STRING`、`ASYNC_IMAGE_*` 和签名密钥属于**服务进程环境变量**，不填写到平台策略 JSON。确需修改这些运行依赖时，直接运行需重启进程；Compose `.env` 中的变量还必须在服务的 `environment` 引用，更新容器环境需要重建服务，单纯 `restart` 不会重新注入。就绪已通过的现有部署不需要为了照抄示例重新生成或替换密钥。

就绪全部通过，只证明运行依赖满足，不代表渠道令牌可用、型号已开通、分组可访问或价格已配置。

### 3.3 存储与对外地址

在视频配置的“异步视频与本地存储”卡片保存以下内容，初次可沿用默认限制：

| 字段 | 初始参考值 | 说明 |
| --- | --- | --- |
| 启用异步视频 | 开启 | 默认关闭 |
| 本地媒体目录 | 直接运行可用 `data/media` | 相对于服务进程工作目录，须有读写权限 |
| 保留天数 | 90 天 | 控制任务和结果保留，不是单条签名有效期 |
| 签名有效期 | 3600 秒 | 已过期的签名地址应重新查询获取有效链接 |
| 单对象大小 | 1073741824 字节 | 1 GiB |
| 下载超时 / 并发 / 重试 | 900 秒 / 2 / 5 | 重试针对已生成文件保存，不是重新生成次数 |

仓库 Dockerfile 的工作目录为 `/data`。若部署已将宿主 `./data` 挂载到容器 `/data`，页面明确填 `/data/media`，对应宿主 `./data/media`；相对值 `data/media` 则会落在容器 `/data/data/media`。多实例处理同一批媒体任务时，保存与读取路径也必须对有关实例可访问。

目录必须持久化；更换新目录不会自动迁移旧结果。保留旧目录供历史结果与在途任务访问。图片存储表单与此视频本地存储表单分开配置。

在 `/system-settings/site/system-info` 保存自己的 `ServerAddress`，例如 `https://your-new-api.example`。这里填写本站外部可访问地址，不能填写 Drama 上游地址或仅容器内可达地址。

## 4. 配置渠道

在 `/channels` 新建渠道，按下表填写并点击外层“创建渠道”或“更新渠道”：

| 字段 | 应填内容 | 注意事项 |
| --- | --- | --- |
| 渠道类型 | **任务插件**，类型 61 | 不选普通 OpenAI、Sora 或官方 Doubao 渠道来代替 |
| 任务插件 | `drama` | 显示名称为 Drama Video A / E / F / G / H3 |
| API 地址 | `https://drama.dafeiyangapi.top` | 填站点根地址，不追加 `/docs/drama`、`/v1`、`/v1/videos` 或查询参数 |
| 密钥 | 上游 Drama 用户令牌 | 填令牌本体，由插件构造 Bearer 请求头；不要填本站 Token 或在字段中重复写 `Bearer ` |
| 分组 | 实际提供服务的分组，例如 `default` | 与后续策略、渠道池及本站 Token 的有效分组一致 |
| 模型列表 | 只添加当前账户开通的型号 | 首次可只添加 `seedance2.5-F` |
| 状态 | 启用 | 保存后重新打开，核对绑定、模型、分组与地址 |

本指南的 `default` 是示例分组。自己的配置使用其他分组时，后文所有对应位置一起替换。不要只在模型列表填写名字、却忘记保存插件绑定或渠道启用状态。

### 4.1 模型别名

可对用户显示别名，例如客户端模型 `my-drama-f25` 映射到上游 `seedance2.5-F`。此时：

- 渠道提供的客户端模型、视频策略 `id`、渠道池模型、本站请求模型均使用 `my-drama-f25`。
- 渠道模型映射目标为 `seedance2.5-F`；实际能力仍由这个已声明型号决定。
- 本站日志和用户看到的是客户端名称，发送给上游的是映射目标。
- 价格保存后检查别名对应的实际生效值，不要误以为给原始型号设置价格就必然覆盖别名或服务方专属价格。

首次验收建议先用原始型号，确认整条链路正常后再配置别名。任意新名字、未知映射目标不会因为写进渠道模型列表而自动注册能力。

### 4.2 上游异步规则怎么处理

本插件已经负责提交、任务号、轮询、状态、用量和鉴权下载，**通常不需要配置渠道 `upstream_async`**。上游本身异步并不意味着必须再打开“配置上游异步”。

如果此渠道已有其他模型的规则，只检查并移除或调整**会匹配本次 Drama 型号和操作的规则**，保留无关配置。命中的规则会覆盖插件的任务号、轮询、状态和主结果解析，可能绕开本指南描述的完成用量等待逻辑。

不要给新 E 填 `actual_seconds_path`：E 的 Schema 没有 `seconds`，按条价格也不需要该模式。F / G 的 `seconds` 有时是字符串，不能直接当作要求 JSON 数字的 `actual_seconds_path`；该模式还要求最终费用不超过预扣上限，不适合拿来替代这里的 Token 差额结算。需要改造特殊响应时，另按[渠道扩展设置](08-渠道扩展设置.md)核对完整规则，而非直接套用其他供应商示例。

## 5. 配置视频策略与渠道池

### 5.1 视频平台策略

进入 `/system-settings/operations/images` → **视频配置** → **视频平台策略**：

1. 分组填与渠道、Token 相同的有效分组，例如 `default`。
2. “提供商”选 **Drama Video A / E / F / G / H3 · drama**。
3. 渠道池绑定方式首次可选“模型与分辨率”（`model_resolution`）。
4. 勾选“启用媒体平台”和异步执行。
5. 在 **“图片与视频联合模型目录”**文本框填写 [第 0.5 节的 JSON 数组](#05-同一页面下方保存视频平台策略)，或点击“导入 drama 视频模型”后只保留自己要开放的型号。
6. 点击 **“保存视频策略”**，成功后重新选择同一分组、提供商核对回显。

第 0.5 节的三项覆盖 E / F / G 各一个型号。只接 F 时仅保留中间一项；补充新项时保留该策略已有的其他有效条目。不要把数组粘贴到渠道扩展设置、视频存储或价格表达式中。空 `video_overrides` 表示继承插件能力；添加覆盖只能收紧，不能给 F 增加首尾帧、扩大时长或开放插件没有的分辨率。

当前通用“视频配置示例”弹窗仍提供 xAI / Doubao 示例，未提供 Drama 专用内容。**Drama 配置使用本页示例或“导入 drama 视频模型”**；不要复制该弹窗中的其他插件模型名、官方 Doubao 参数或延长方向。

### 5.2 渠道池

进入同一页面的“渠道池”。有明确账号选择、权重或分辨率隔离要求时，新增对应绑定：

| 字段 | 首次 F 验收示例 |
| --- | --- |
| 分组 | `default` |
| 平台 | `drama` |
| 模型 | `seedance2.5-F` |
| 分辨率 | `1K`（渠道池路由档位） |
| 渠道 | 选择第 4 节实际创建的渠道 |
| 权重 | 例如 `1` |

视频池中的尺寸是**路由档位**，不是要发给上游的输出分辨率：

| 请求输出分辨率 | 池尺寸档位 |
| --- | --- |
| 480p、720p、F 的 720px | `1K` |
| 1080p | `2K` |
| 4k | `4K` |

720px 只是该 F 型号的上游取值，不是 720p 的全局别名；不能因此修改其他型号的请求分辨率。

没有显式池绑定时沿用可用渠道的自动选择；已保存的空渠道绑定可用于关闭该绑定，不等于“自动选择”。创建池后要保存并重新打开核对，模型或渠道选不到时先检查插件身份、启用状态、分组和模型列表。

池内多个账号按相对权重分配，不能保证固定选择某个账号。引用 `asset://ID` 时，素材应属于最终选中渠道的上游账户；需要用固定账户素材时，将该模型/档位的可用渠道限定到对应账号，避免被分配到不拥有素材的另一账号。

## 6. 配置价格

### 6.1 在哪里保存

具有模型定价管理权限的账号进入 `/system-settings/billing/model-pricing` → **模型价格**：

1. 搜索客户端实际使用的型号或别名，没有价格的型号在未设置价格列表中查找或新增。
2. 确认编辑“默认”价格还是 `drama` 服务方专属价格。存在服务方覆盖时，修改默认价不会覆盖它。
3. 使用任务定价的“编辑器模式”选择“可视化编辑器”或“表达式编辑器”；首次示例选择 **USD**，便于核对原始金额。Drama 专属价的开关与粘贴位置见[第 0.7 节](#07-模型价格页面每个型号分别保存-drama-售价)。
4. 点击“保存模型价格”，再重新打开同一型号和服务方确认回显。
5. 对不同分辨率、参考视频条件逐项预览，确认实际开放组合都有正确价格。

以下价格都是**本站售卖价格示例，不是上游官方报价**。任务表达式直接返回美元费用，最后再应用本站生效分组倍率；人民币展示不改变原始表达式单位。不能将上游人民币单价、示例折扣或 `metadata.billing.quota` 原样当作本站价格。

### 6.2 用量字段选哪一组

| 型号组 | 可用 `u()` 字段 | 推荐方式 |
| --- | --- | --- |
| 新 A 与 H3 | `seconds`、`resolution` | 按秒；可按本型号支持的分辨率设置每秒售价，不要求 Token |
| 新 E | `requests`、`resolution` | 每条或按分辨率每条收费，`requests` 固定 1 |
| 新 F | `seconds`、`tokens`、`resolution`、`video_input` | 无视频参考按秒，有视频参考按实际 Token |
| 新 G | 同新 F | 按实际 Token，必要时按分辨率、参考视频分档 |
| 旧后缀型号 | `seconds`、`resolution`、`video_input` | 按秒或明确固定费用，不支持引用 `tokens` |

`video_input` 只有 `none`、`video` 两种值。原始 Token 表达式需要显式除以 `1000000`；秒数和按条项不需要。任务表达式按条使用普通常数或 `requests`，不要使用普通 HTTP 请求定价的 `fixed()`。

### 6.3 E：按条

粘贴到新 E 型号的原始表达式输入框，**只复制代码块里的表达式**：

```text
tier("video", u("requests") * 0.50)
```

分组倍率为 1 时，合法的 5 秒和 15 秒任务均收 0.50 美元。需要按分辨率分别设置单价时，在可视化编辑器中填对应行，或对支持这些档位的 E 型号使用：

```text
u("resolution") == "4k" ? tier("4k", u("requests") * 1.50) : u("resolution") == "1080p" ? tier("1080p", u("requests") * 1.00) : tier("standard", u("requests") * 0.50)
```

这不会给不支持 4k 的型号新增 4k 能力。新 E 没有 `u("seconds")` 或 `u("tokens")`，不要直接粘贴其他视频插件的秒价、Token 价格。

### 6.4 F：区分按秒和实际 Token

适用于新 F 两个型号：

```text
u("video_input") == "video" ? tier("tokens", u("tokens") * 10 / 1000000) : tier("seconds", u("seconds") * 0.10)
```

分组倍率为 1：无视频参考的 8 秒任务收 0.80 美元；带视频参考、最终用量 600037 Token 的任务收 6.00037 美元。可视化填写时，`none` 条件行只填秒价，`video` 条件行只填 Token 单价，避免两项同时相加。

无视频参考的 F 不保证返回实际 Token。不要将所有 F 请求都只配置为 Token 收费，否则无视频参考时可能保留估算用量。本站也可以自选按秒售卖，但上游仍可能按 Token 收费，成本与售价应分别核对。

### 6.5 G：按实际 Token

适用于新 G 型号：

```text
tier("tokens", u("tokens") * 10 / 1000000)
```

分组倍率为 1、最终 432900 Token 时收费 4.329 美元。提交时用分辨率、输出时长及参考视频时长上限估算 Token；这个估值只用于预扣，不是上游最终报价。最终有效总 Token 替换估值，差额可能补扣或退款。余额应能覆盖最终结算；补扣不足时依照宿主资金规则处理，不保证仍交付成功结果。

G 和带视频参考的 F 在上游账单 `pending` 或实际 Token 尚未给出时继续查询；非法 Token 进入轮询失败预算，显式零 Token 保留。即使把本站售价改成固定费用，这个上游完成用量校验仍执行。上游独立账单中的金额、折扣和 quota 不用于直接扣本站用户余额。

价格、请求条件和分组倍率按任务受理时冻结；修改价格只影响后续新任务，不会重新定价已经受理的任务。更多操作见[视频计费配置](09-视频计费配置.md)。

## 7. 调用与验收

### 7.1 工作台

进入 `/image-workbench` → 视频工作区，选择 Drama 型号；按模式填写时长、分辨率、比例和参考素材。首次使用 `seedance2.5-F`、8 秒、720p、16:9、纯文本，确认能在任务中心看到状态和最终视频。

工作台“附加 JSON”遵守当前型号字段规则，不用于覆盖已选择的模型、模式或结构化素材。新 E 不添加音频开关，新 F 不添加首尾帧或 G 专属参数。

### 7.2 PowerShell：提交、查询、下载

先换成自己的本站地址与本站 Token，再执行。此示例会真实创建一个付费生成任务；同一请求超时重试时保留原幂等键，确实要新建另一条时改用新键。

```powershell
$gatewayBase = 'https://your-new-api.example'
$gatewayToken = 'sk-your-local-api-token'
$submitHeaders = @{
  Authorization = "Bearer $gatewayToken"
  'Idempotency-Key' = 'drama-f25-example-001'
}
$videoBody = @{
  provider = 'drama'
  model = 'seedance2.5-F'
  prompt = '清晨海边，镜头缓慢推进，电影感自然光'
  seconds = 8
  resolution = '720p'
  aspect_ratio = '16:9'
  generate_audio = $false
} | ConvertTo-Json -Depth 8
$accepted = Invoke-RestMethod -Method Post `
  -Uri "$gatewayBase/v1/videos/generations_async" `
  -Headers $submitHeaders -ContentType 'application/json; charset=utf-8' `
  -Body $videoBody
$accepted
```

预期 HTTP 202，回包形状如下；这是本地受理，不表示上游已经完成：

```json
{
  "task_id": "task_example_local_id",
  "query_url": "https://your-new-api.example/v1/media/tasks_async/task_example_local_id"
}
```

保留 `$accepted`，用**提交时同一个本站 Token**查询：

```powershell
$queryHeaders = @{ Authorization = "Bearer $gatewayToken" }
$taskView = Invoke-RestMethod -Method Get `
  -Uri $accepted.query_url -Headers $queryHeaders
$taskView | ConvertTo-Json -Depth 12
```

间隔几秒重复查询，直到 `status` 为 `succeeded` 并且 `data` 有结果。此处是本站状态，不能按上游的 `completed` 判断。成功回包摘录：

```json
{
  "task_id": "task_example_local_id",
  "media_type": "video",
  "status": "succeeded",
  "stage": "completed",
  "billing_status": "settled",
  "storage_status": "succeeded",
  "result_count": 1,
  "data": [
    {
      "key": "video",
      "url": "https://your-new-api.example/v1/media/objects/example-object?expires=示例时间&access=示例签名",
      "content_type": "video/mp4"
    }
  ]
}
```

使用真实返回的结果链接下载，不要拼接示例签名：

```powershell
if ($taskView.status -eq 'succeeded' -and $taskView.data.Count -gt 0) {
  Invoke-WebRequest -Uri $taskView.data[0].url -OutFile '.\drama-result.mp4'
}
```

结果链接自带本站签名或由宿主按既有恢复规则返回；不需要附带上游令牌。若查询尚未成功，先等待或查看错误，不要为下载再次提交生成。

### 7.3 带参考素材的请求体

Drama 当前不接收 multipart 文件上传。手里是本地图片时，先上传到自己的公网可读对象存储或图床，再把所得 HTTPS 直链按下表填写；Gemini SC 上传接口不能当作通用视频上传步骤。

| 你要什么效果 | 规范字段 | URL 格式 |
| --- | --- | --- |
| E / F 普通参考图 | `reference_images` | `["https://cdn.example.com/a.png", "https://cdn.example.com/b.png"]`，数组中的每一项是一张图 |
| G 首帧 | `image` | `"https://cdn.example.com/first.png"` 或 `{"url":"https://cdn.example.com/first.png"}` |
| G 首尾帧 | `image` 和 `last_frame` | 分别填写首帧、尾帧 URL；G 2.5 比例必须为 `adaptive` |

URL 前不加 `@`，不写本地文件路径，也不把多个 URL 用逗号拼成一个字符串。地址应直接返回图片内容，不能依赖浏览器登录或额外请求头。本站工作台的多图输入框每行粘贴一个 URL，不粘完整 JSON；通过 API 调用时才使用下面的 JSON 数组。

下面是**只有参考图、没有参考视频**的 F 请求，可替换第 7.2 节的生成请求体。实际素材地址须能由上游读取。图片用于普通参考，不是 F 的首帧模式：

```json
{
  "provider": "drama",
  "model": "seedance2.5-F",
  "prompt": "@图1 中的人物自然挥手",
  "seconds": 8,
  "resolution": "720p",
  "aspect_ratio": "16:9",
  "reference_images": ["https://cdn.example.com/character.png"]
}
```

此示例没有视频输入，按第 6.4 节的售价表达式进入按秒分支。确需参考动作视频时，再增加 `"reference_videos": ["https://cdn.example.com/motion.mp4"]` 并修改提示词；这才会进入 F 的参考视频 Token 计费分支。所有 `cdn.example.com` 都只是示意地址，不能原样用于真实生成。相同素材不要同时出现在 `references` 和 `reference_images` 等别名字段中。

其他供应商的文件上传、xAI 的 multipart URL 文本字段和完整对照命令见[接口文档参考图格式](../异步生图API接口文档.md#511-参考图文件和-url-到底怎么写)。

### 7.4 G 2.5：首尾帧、编辑、延长

以下都是请求体，使用本站 Token、`Content-Type: application/json`，每条新任务使用独立的 `Idempotency-Key`。

首尾帧发送到 `POST /v1/videos/generations_async`：

```json
{
  "provider": "drama",
  "model": "seedance2.5-G",
  "prompt": "从首帧平稳过渡到尾帧",
  "seconds": 5,
  "resolution": "720p",
  "aspect_ratio": "adaptive",
  "image": "https://cdn.example.com/first.png",
  "last_frame": "https://cdn.example.com/last.png"
}
```

不能只给尾帧，也不能再混入普通参考图、视频或音频。直接写上游 `references` 格式时，G 的每个素材必须有匹配类型的显式角色，例如 `reference_image`、`reference_video`、`reference_audio`、`first_frame`、`last_frame`；E / F 普通参考则使用 `reference`。

视频编辑发送到 `POST /v1/videos/edits_async`：

```json
{
  "provider": "drama",
  "model": "seedance2.5-G",
  "prompt": "将视频人物的外套改成红色，保持原有动作",
  "video": "https://cdn.example.com/source.mp4",
  "resolution": "720p",
  "aspect_ratio": "adaptive"
}
```

编辑示例不传 `seconds` 或 `duration`，插件向上游转换为自动时长 `-1`。提交时按最大 30 秒输出与参考视频上限估算 Token，完成后用实际 Token 结算；上游只回显 `-1` 时，不将它作为负秒数计费。

向后延长发送到 `POST /v1/videos/extensions_async`：

```json
{
  "provider": "drama",
  "model": "seedance2.5-G",
  "prompt": "镜头继续向前移动，展示远处城市",
  "video": "https://cdn.example.com/source.mp4",
  "seconds": 8,
  "resolution": "720p",
  "aspect_ratio": "adaptive",
  "extension_direction": "backward"
}
```

这里的 8 秒是本次延长用量；不会拿含原片的最终整片时长覆盖它。当前插件只声明 `backward`，不要复制其他供应商的 `forward` 示例。

## 8. 配置注意事项

### 8.1 每处配置都有独立保存

| 配置内容 | 保存位置 | 保存后怎么确认 |
| --- | --- | --- |
| 渠道、地址、令牌、分组、模型 | 渠道编辑页 | 重新打开渠道看绑定和回显 |
| 视频全局开关、媒体目录与限制 | 视频配置的存储卡片 | 保存成功并查看就绪检查 |
| `drama` 平台策略与模型能力 | 视频平台策略卡片 | 重新选择同分组、同服务方查看条目 |
| 渠道池与权重 | 渠道池绑定 | 重新打开对应模型/档位检查选中渠道 |
| 默认价或 `drama` 服务方覆盖 | 模型价格编辑器 | 重新打开同一模型、同一价格来源核对 |
| 进程环境变量 | 部署配置与进程/容器 | 使服务重新读取环境并检查就绪状态 |

关闭弹窗、只导入模板或只改某一张卡片，不等于整套配置已保存。已有配置不要被示例整段覆盖，尤其保留其他平台策略、渠道设置和已使用的密钥。

### 8.2 素材与字段

- 新 E / F 使用公网 HTTPS 素材；新 G 另支持当前账号已有的 `asset://ID`。HTTP、本地路径和裸 Base64 不接受。只有旧后缀型号额外支持完整 Data URI；当前插件不接收 multipart 文件上传。
- 插件检查类型、来源格式、角色、数量和重复地址；具体文件格式、大小、像素、FPS、时长与内容审核还会由上游执行。地址在浏览器能打开，不表示上游服务器有权读取；避免依赖浏览器 Cookie、本站私有登录态或过短有效期。
- `seconds`、`duration` 统一选一个；本指南使用 `seconds`。`aspect_ratio`、`ratio` 等别名也不要填写互相冲突的值。
- `n`、未知 `seed`/`quality` 等字段不会无条件透传；不能用 `metadata.seconds`、`metadata.model` 或附加 JSON 绕过已校验时长、模型和素材限制。
- G 的 `return_last_frame` 可让插件声明额外的尾帧图片制品；它不同于作为输入的 `last_frame`。持久化视频任务主结果仍以视频为准，当前视频落盘流程只保存视频，不能把该选项理解为尾帧图片会自动归档到图库。

### 8.3 任务、重试与账单

- HTTP 202 只表示本站受理；生成、实际用量结算和本地保存可能仍未完成。查询以本站 `status`、`billing_status`、`storage_status` 和结果列表共同判断。
- 相同本站 Token、相同请求和相同幂等键重试会复用本地任务；同键改了请求会返回 409。换一把 Token、换一个键或改变请求不能当作原任务重试。
- 使用提交时同一把本站 API Token 查询；同一用户换另一把 Key 也不等于拥有该 API 查询范围。不要把上游令牌用于本站查询。
- 已拿到上游任务号后，后台轮询和下载恢复复用原任务。`execution_unknown` 表示无法确认上游是否已接单，应先核实原任务与上游账单，不能直接重复创建。
- 明确生成失败按宿主规则退款；`storage_failed` 表示保存问题，不等同生成失败，也不保证自动退费。已成功生成后应优先恢复下载/保存，不要再次生成来“修复下载”。
- 本站模型价格、分组倍率与上游账户报价是独立账本。修改售价不会改变上游扣费，`cost` 是本站任务费用，不是对上游账单金额的直接转发。
- 生成任务保留期、媒体文件保留期、签名 URL 有效期及上游素材/结果链接有效期是不同概念。签名过期先重新查询；对象或任务真正过期后，不保证仍可恢复结果。

## 9. 排错表

| 现象或错误 | 先检查 | 处理方向 |
| --- | --- | --- |
| 插件列表没有 `drama` | 实际运行服务是否包含新版本或完成插件导入 | 核对激活版本和总开关，较老宿主先升级 |
| 视频就绪检查未全部通过 | 视频开关、插件、Redis、载荷密钥、签名密钥 | 按第 3 节修复对应项，再重新检查 |
| 策略或工作台找不到型号 | 插件是否声明该型号、策略是否保存、型号是否被覆盖收紧 | 核对 `drama` 模板、客户端名称和渠道模型列表 |
| `unsupported_model` / `unsupported_provider` | 插件 key 与型号归属 | 使用本指南声明型号，别名目标必须可识别 |
| `No authorized video channel is available` / `provider_unavailable` | Token 有效分组、渠道启用/分组/模型、插件绑定、策略、池的选中渠道 | 逐项保持一致；已保存的空池不能提供渠道 |
| `model_price_error` / 价格无法保存 | 型号/别名实际生效价格、服务方覆盖、`u()` 字段 | E 不引用 seconds/tokens，旧型号不引用 tokens；检查默认价是否被覆盖 |
| `seedance2.0-F` 分辨率被拒绝 | 是否误填 `720p` | 新 F 2.0 用 `720px`，其他型号按表选值 |
| E 或旧型号提示不支持 `generate_audio` | 是否照搬 F 示例中的音频字段 | 删除该字段，false 也不能用于声明不支持的字段 |
| G 2.5 首尾帧或编辑比例错误 | 是否为 `adaptive` | 修改比例，并检查是否混入普通参考素材 |
| 素材数量、重复、角色或来源错误 | 第 2.3 节限制、是否同一素材重复放入多组字段、G 是否明确 role | 修正请求；F 视频与音频合计最多 3 个 |
| 上游 401/403 | 渠道上游令牌、余额、型号与分组权限 | 先分清本站鉴权错误与上游账户错误，不改用另一类 Token 乱试 |
| 上游显示 completed，本地仍处理中 | G / 视频参考 F 是否已有有效实际 Token、上游账单是否仍 pending | 查询原任务，检查用量；不要配置假 Token 或用异步规则强制标成功 |
| `storage_failed` / 视频保存失败 | 本地磁盘、权限、挂载、大小上限、网络和上游下载接口 | 在任务详情恢复原结果，核对已结算状态，避免重提生成 |
| 同幂等键返回 409 | 是否修改过请求体或复用旧键提交新任务 | 原任务保留原请求和键；新任务用新键 |
| 查任务 404 | 本地 task_id、本站地址、是否用同一把提交 Token、任务是否过期 | 使用受理回包的 query_url；不要使用上游任务号 |
| 返回链接是内网或错误域名 | 本站 `ServerAddress` | 保存外部可访问的本站地址，重新获取结果链接 |

## 10. 验收与验证边界

上线前逐项人工验收：插件激活版本正确；渠道和分组一致；就绪检查通过；价格已保存且有预览；一条纯文本 F 任务能受理、查询并下载；该任务只创建一次生成且本站费用正确。随后再分别验证 E 不同时长同档按条价、F 参考视频实际 Token、新 G 实际 Token，以及确实要开放的首尾帧或编辑能力。

追加新三款时，再按第 0.10 节分别验收纯文本 A 2.0、A 2.5、H3；检查按秒扣费和保存结果，再测试 A 普通参考编号、A 2.0 成对首尾帧和 H3 关闭音频。当前变更已完成本地插件、宿主路由、相关结算退款及指南测试和构建；真实上游付费生成与线上后台操作**未测试**，本次没有可用部署会话或测试令牌。详细本地验证记录见[当月台账](10-2026年10月代码变更台账.md#drama-a-h3-change)。

仓库已有本地插件、宿主适配器和模拟 HTTP 回归，覆盖提交、轮询、素材限制、用量与鉴权下载；它们不代表真实上游账户已开通、真实视频文件已验收或已部署。编写本指南没有执行上述真实付费示例，也没有修改运行环境、密钥或线上渠道。
