# 企业开票申请与历史补开

本页记录提交 `4ddaa904351d6b78c6370f817849d278de582b10` 引入的企业开票功能。完整提交清单见 [2026 年 9 月变更记录](02-2026年09月代码变更台账.md)。

## 功能范围

企业开票功能面向人民币易支付充值订单，提供用户申请、管理员人工处理和历史补开台账。邮箱用于管理员线下发送发票；系统当前不自动开票、不上传发票附件，也不自动发送邮件。

## 用户流程

入口：`/wallet/invoices`

### 申请开票

1. 系统列出当前登录用户全部可开票的充值订单。
2. 用户可以按充值订单号搜索、分页浏览并跨页勾选。全选只影响当前页，改变搜索条件会清空已选订单。
3. 页面显示已选订单数量、人民币合计和当前最低开票金额。
4. 用户填写企业名称、企业税号和发票接收邮箱后提交。
5. 服务端重新读取订单、计算金额并检查提交时的最低金额配置，不采信客户端金额。
6. 请求失败时保留企业资料；订单状态发生冲突时刷新可选订单。

只有功能开关启用时用户才能提交新申请。关闭功能后，历史记录仍然可以查看，管理员仍可处理已有申请和进行历史补开。

### 开票记录

记录包含：

- 状态：待处理、已完成或已拒绝。
- 企业名称、企业税号和邮箱。
- 开票金额及关联充值订单快照。
- 申请时间、处理时间、操作人。
- 拒绝原因或历史补开备注。

申请被拒绝后，只释放该申请占用的充值订单。旧申请和拒绝原因永久保留，用户可以重新选择这些订单，也可以与其他订单合并后再次申请。

## 管理员流程

入口：`/admin/invoices`

### 申请记录

- 可按用户 ID、用户名、显示名称、用户邮箱、企业资料或充值订单号搜索。
- 可按申请状态筛选，并查看企业资料和订单明细。
- 待处理申请只能从 `pending` 转为 `completed` 或 `rejected`。
- 拒绝时必须填写原因；完成后订单继续保持占用。
- 处理结果、操作人 ID、操作人用户名快照和操作时间与业务记录在同一事务中保存，然后写入现有审计日志。

### 历史补开

1. 管理员通过用户 ID、用户名、显示名称或邮箱搜索并明确选定用户。
2. 系统列出该用户全部历史可开票订单；切换用户会清空选择。
3. 管理员跨页勾选订单，可填写备注并确认标记已开票。
4. 系统直接创建来源为 `admin_history`、状态为 `completed` 的记录。

历史补开不要求企业资料，不受最低开票金额限制，并会出现在用户的开票记录中。

## 订单资格与金额

一笔订单必须同时满足以下条件：

- 属于目标用户。
- 充值状态为支付成功。
- 明确标记为易支付充值，或支付渠道为空且订单号符合旧版 `USR{用户ID}NO{6 位字母数字}{10 位时间戳}` 规则。
- 不属于订阅购买。
- 保存的支付金额有效且大于零。
- 没有被待处理或已完成的开票记录占用。

每笔金额沿用充值订单保存的易支付人民币金额，格式化为两位小数后精确转换为整数分。合计过程检查整数溢出，任一订单无效或发生冲突时整批事务回滚。

大量跨页选择会分批执行数据库查询和写入，业务上不设置 100 单上限。

## 状态和数据表

### 状态流转

```text
pending ──> completed
   │
   └──────> rejected ──> 释放订单占用，可创建新申请
```

已完成和已拒绝记录不能再次变更状态。

### 数据表

- `invoice_requests`：申请或补开主记录，保存来源、企业资料、金额、状态、时间、拒绝原因、备注和操作人快照。
- `invoice_request_items`：保存每批充值订单的订单号、金额和时间快照。
- `invoice_order_claims`：以充值订单 ID 为主键建立唯一占用，防止用户申请与管理员补录重复开票。

开票功能不会修改充值支付状态或用户余额。

## 配置与权限

计费设置包含：

- `payment_setting.invoice_enabled`：用户新申请开关，默认 `false`。
- `payment_setting.invoice_min_amount_cents`：最低开票金额，单位为人民币分，默认 `0`。

前端按人民币元展示和输入最低金额，支持两位小数。配置写入沿用超级管理员权限。

管理员接口使用以下权限：

- `invoice.read`：查看全站记录、详情和指定用户可开票订单。
- `invoice.manage`：完成、拒绝申请和创建历史补开记录。

两个权限默认授予管理员角色。

## API

### 用户接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/invoice/config` | 读取开关和最低金额 |
| `GET` | `/api/invoice/orders` | 查询本人可开票订单 |
| `POST` | `/api/invoice/requests` | 创建开票申请 |
| `GET` | `/api/invoice/requests` | 查询本人开票记录 |
| `GET` | `/api/invoice/requests/:id` | 查询本人记录详情 |

### 管理接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/invoice/admin/requests` | 查询全站开票记录 |
| `GET` | `/api/invoice/admin/requests/:id` | 查询记录详情 |
| `GET` | `/api/invoice/admin/orders` | 查询指定用户可开票订单 |
| `POST` | `/api/invoice/admin/requests/:id/complete` | 标记申请完成 |
| `POST` | `/api/invoice/admin/requests/:id/reject` | 拒绝申请 |
| `POST` | `/api/invoice/admin/history` | 创建历史补开记录 |

所有金额字段统一使用整数分。用户接口只使用当前登录用户身份，管理接口需要管理员身份及相应开票权限。

- 金额舍入、低于及等于门槛。
- 越权订单、无效订单和订阅订单排除。

- 操作人、操作时间和拒绝原因留存。
- SQLite 3.50.4 新建、升级、重复迁移、原数据保留和唯一约束。
- 前端跨页及移动端勾选、字段校验、失败保留输入、冲突刷新和拒绝原因展示。
