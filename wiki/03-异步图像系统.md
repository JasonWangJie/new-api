## 单次超时换账号与全部冷却时的调度

2026-10-17 本地增量变更（提交日期、提交哈希待提交，基线 `6795b32deedb52dc95b33d2891a703f52bd68754`）。本节记录本次新版本的超时处理规则，集中回归与适用的真实三库验证已通过，服务器隔离候选镜像健康检查通过，线上切换仍待完成。下文既有章节中“派发后结果未知不自动重提”和“全部账号冷却则等待”的规则，遇到本节明确允许的单次超时时以本节为准；其他未知执行仍保留原核对边界。

### 何时换号、何时结束

- 仅当一次生成请求已派发、明确发生单次上游超时、没有上游任务号且没有已保存成功结果时，才将该次账号尝试保留为未知，任务继续串行选择其他账号。纯超时链默认初次加额外换号 2 次，最多提交给 3 个不同凭据；每次超时换号退避 5–10 秒，同时受原总重试预算和任务整体期限约束。其他故障仍受既有分类预算与总预算控制，混合故障路径不等同于全任务最多使用 3 个账号。
- 超时凭据在本任务内永久排除，避免 `A → B → A`；同一凭据即使重复配置到不同渠道也视为同一个账号。账号默认冷却 60 秒，影响后续任务的优先选择，不解除本任务的永久排除。没有其他合格账号、换号预算耗尽或整体期限届满后，结束本任务，不退回已超时凭据重新生成。
- 如果所有仍有资格的账号都处于账号冷却，则按原退避继续调度，优先选冷却最早结束的候选，不额外等待账号冷却到期。这个回退仅作用于账号冷却：禁用渠道、渠道熔断、并发已满、不兼容及被本任务排除的凭据仍不能派发。被永久排除的账号不算“仍有资格”，只有这些账号可用时不能用全部冷却回退绕过排除。
- 已有上游任务号时只继续查询原任务，查询超时不直接发起新生成；已有成功输出或成功里程碑时只恢复保存、下载或结算。无法确认额度预留或结算结果、服务停机取消及执行租约失效不作为超时换号依据。缺少新策略标记的旧任务保留原恢复逻辑，历史 `execution_unknown` 不因升级自动重新提交。

| JSON 字段 | 默认值 | 用途 |

| `upstream_timeout_max_retries` | `2` | 明确单次超时后的额外换号次数；纯超时链默认初次加额外 2 次，最多调用 3 个不同凭据。 |

所有尝试复用同一任务、冻结价格和已确认预扣，不因换号反复退款和重新扣款；成功后仅接受一份最终结果并结算一次。最终没有可交付结果且预扣状态已确认时，任务失败并幂等退回本地预扣；额度状态不确定仍转核对流程。超时未知尝试及所用账号记录保留供管理员与供应商对账。取消本地等待不能保证供应商已停止生成，可能产生多次上游费用，这部分额外成本由站点承担，不对用户重复收费。

### 额度、本地等待与执行期限

- 尚未派发且明确确认钱包或 Token 缓存缺失时，任务以 `quota_cache_unavailable` 等待本地依赖恢复；不重建可能落后于批量扣费的数据库余额。已有预留可继续保留，等待不代表额度为零或一定未扣费。
- Redis 预留命令、补偿操作或数据库提交的确认结果丢失时，任务进入 `quota_cache_uncertain` 并停止派发，不能作为普通缓存缺失自动等待重试。只补偿已确认成功的缓存扣减，不盲目补偿未确认的命令或重复投影；管理员应核对实际缓存、持久化账本及普通请求的批量记账后再处理。
- 路由先从兼容渠道中选取仍有空余调用槽的候选，再按原优先级和权重选择；worker 派发前仍原子抢占调用槽，避免并发竞争绕过上限。全部候选或全局容量已满、账号冷却、路由容量读取或供应商重试控制暂不可用时，保留原请求和已持久化预留，等待不增加生图总重试数，也不增加真实上游提交次数。最后一条当前渠道的未派发尝试可记录本地等待原因并收尾，历史已完成尝试保持原值。实际再次提交仍受总预算、分类预算和整体期限约束。
- 单次等待与退避的下一次时间不会越过任务整体期限。恢复扫描也检查已开始的排队任务：期限已到且确认尚未派发时标记 `expired`、幂等释放已提交的预留；已派发或已有上游任务时保持 `execution_unknown` 并保留资金核查边界。尚未开始执行的排队任务不因此误过期。
- 已有上游任务号时，连接中断或读取/解析失败只允许继续查询原任务；没有任务号且派发后结果不明时禁止自动重新生成。输出已有成功里程碑时，恢复复用既有输出和冻结账单，保存或计费失败不重新生图。
- 后处理保留脱敏的实际原因，例如声明 MIME 与检测格式不一致。结算补扣、补偿或提交确认不明时使用 `billing_quota_uncertain` / `609`，记录 `manual_recovery` 与 `quota_confirmation_unknown` 并停止自动重试，提示管理员核对预留；不能把该异常当作普通存储故障重复生成或反复补扣。
- `billing_quota_uncertain` 不允许普通恢复，普通用户不显示恢复按钮，直接调用或伪造确认也不能恢复。管理员应先核实并校正缓存与持久化账本，再在任务详情选择“恢复”并确认已对账；管理请求必须携带 `confirm_quota_reconciled: true`。确认本身不自动修复额度，后续只继续原输出和账单处理，重复结算遵循原账单幂等边界。

请求经过 Token 验证、Token 图像平台权限、协议识别、能力校验、渠道路由、计费预处理和异步任务持久化。任务 worker 使用租约避免多个实例重复处理，并记录重试、失败和结算状态。

#### 当日任务统计

`GET /v1/images/tasks_async/stats` 返回 `async_image.stats`，按 API Key 所属用户汇总服务器当地当天创建的全部持久化图片任务，包括工作台及该用户其他 Key 提交的任务。`GET /v1/videos/tasks_async/stats` 读取持久化视频统计，`GET /v1/media/tasks_async/stats` 汇总图片与视频。通用任务表中的独立旧视频、音乐等任务不在统计范围，视频关联的上游记录不重复计数。

仅接受 `Authorization: Bearer <API_KEY>`；额度耗尽仍允许查询，过期、禁用、删除、所属用户不可用及 Key 的 IP 限制继续生效。任务统计直接读取主库，不依赖提交开关或 worker。服务器 `TZ` 优先于本地时区，以任务创建时间落在当天零点至次日零点前为准；客户端日期、时区和用户筛选参数不改变范围。

响应包含 `date`、`timezone`、用户钱包 `balance`、`today_requests`、`success_count`、`failure_count` 和 `success_rate`，并设置 `Cache-Control: no-store`。处理中任务计入请求数；`execution_unknown`、存储失败、计费失败和 `expired` 计入失败，恢复后按新状态统计。成功率仅以成功与失败任务之和为分母，没有此类任务时为 `0`。余额读取当前额度账本并按 `QuotaPerUnit` 换算，不是 Key 剩余额度；优先使用有效的 Redis 实时额度，Redis 未启用时读取主库。Redis 与批量更新同时开启时，额度缓存缺失或不可用返回 `500`；未开启批量更新时可回退读取主库。本接口不重建或写入额度缓存。完整请求、响应与错误格式见[异步生图 API 接口文档第 10 节](../异步生图API接口文档.md#10-当日异步生图统计与异步视频扩展)。

#### 队列与上游轮询

- 新任务在数据库中与 event/outbox 同事务落库，outbox dispatcher 以 1 秒节拍投递可执行命令；正常空闲时不再等待默认 30 秒恢复扫描。
- `queued` 仅表示尚未被 worker 抢占或容量闸门已满。worker 抢占且选定渠道后对外显示“处理中”。
- Alibaba、Replicate 等先返回上游任务 ID 的渠道，在上游已接单后持续显示“处理中”。每次查询完成后释放数据库执行租约，按任务的 `next_attempt_at` 再投递，不会被默认 120 秒租约挡住。
- Redis 队列仍然是可重建的投递层；周期恢复扫描保留，用于 Redis 数据丢失、进程中断或临时连接失败后的收敛。

#### 错误分类、换号与成功结果恢复

- `reference image fetch`、`Reference image download failed`、参考图国内下载中转失败等明确网络诊断归为 `602`，启用 `passthrough_fallback_local` 时复用既有本地传输回退。安全审核、数量、缺图、尺寸及参数错误优先保持原分类；未知 `400`、`403` 和普通 timeout 不按文案一概重试。
- `605/606` 提交失败优先避开刚失败的账号，健康兼容备用账号存在时实际换号；池内只有原账号时仍按原瞬时失败和总预算有限退避。参考图 `A/A/A/B` 硬排除规则及 Gemini 最大换号次数保留；达到换号上限只允许原账号重试。无可用账号归为 `603` 等待容量或冷却恢复。
- 上游明确返回终态 `FAILURE` 后，只有可恢复错误且账单仍为 `reserved`、没有成功结果里程碑时才允许重新提交。任务 ID、原请求、冻结价格、资金预留、累计预算和整体期限保留，旧上游任务号记入管理员账号尝试，再解除旧渠道/任务绑定；安全审核或无法确认的执行不会进入此路径。
- 已接单任务的 `429/5xx` 查询错误继续对原任务退避轮询，不占提交或换号预算；合法 pending 响应清零连续失败计数。整体期限届满或查询无法恢复时进入 `execution_unknown`，保留资金预留供管理员核实，不以查询失败自动退款。
- 同步返回结果的异步图片调用也冻结所用渠道。拿到成功响应和用量后，将私有 completion 写入既有 `request_cipher` 加密信封，再下载、校验和准备账单；租约失效或管理员终止后，旧 worker 无法写入或复活任务。没有新增数据库表、列或迁移。
- 上游 HTTP 的单号期限只对异步图片作用域生效，覆盖等待响应头和读取响应体。成功后的本地处理使用独立且有期限的上下文，并随 worker 租约取消；全局及渠道调用槽随真实调用续期，已失去的槽不会被续期脚本重新创建。
- completion 恢复直接消费已保存响应，使用原模型、真实 usage、冻结价格及首次成功时刻计算时间条件。下载和账单准备分别使用存储/账单预算，不消耗提交预算；缺少真实用量的已完成上游任务可重新查询原任务补足用量，仍不重提。
- 本地预算耗尽分别显示 `storage_failed` / `billing_failed`，保留响应和预留，可通过既有“恢复”继续处理。已有输出受本地校验限制时停止自动重复，保留人工恢复或终止入口；未完成计费前不公开结果。
- 加密恢复信封上限为 **32 MiB**；MySQL 同时受当前会话 `max_allowed_packet` 一半的限制，兼容小 packet 配置并给传输编码留余量。响应 JSON 按原结构保存，避免再次 Base64 膨胀。超过恢复上限的合法大响应仍在当前调用中完成下载、账单与落地；没有持久化证据且处理失败时保留未知执行边界，不重新生成。原上游响应内存限制不由这个恢复上限替代。
- 历史已失败任务的请求密文通常已清除，历史结果也不会因代码升级自动重新生成、收费或退款。当前单账号渠道池需要另外配置兼容备用账号才能实际换号；本次本地修改不变更线上渠道池。
- 明确的 `reference image fetch` 等参考图拉取失败归 `602`。HTTP 400 不再要求额外的 Google `INVALID_ARGUMENT` 或数值 `code` 字段；配置本机回退且本轮确实发送远程 `fileData` 时，至少允许一次原账号本机下载重试，即使参考图通用重试预算为零。仍受总预算限制，其他输入错误不会触发这条回退。
- `prompt cannot exceed`、`prompt_too_long` 等明确提示词长度拒绝归 `604`，保留上游报告的限制说明。网关原有 64 KiB 请求边界与供应商字符数限制分别生效；收到该供应商的 10000 字符拒绝时，应减少实际发送的提示词或使用支持更长输入的渠道，系统不会自动截断提示词或修改其语义。
- 发出上游请求前的未知准备错误保留脱敏原始原因，内部错误标记为 `request_preparation_failed`；真实上下文超时或网络超时归 `606` 并受有限预算约束。没有明确临时故障或账号失败证据的未知错误不自动扩大到所有账号。旧版本已清除的请求和未记录的原始准备错误无法从升级代码重建。

##### 1. 查看为什么重试或停止

1. 打开 `/admin/async-image-tasks`，在“搜索任务”填写任务号，设置包含任务提交日期的时间范围，点击“应用筛选”。
2. 点击该行的“查看”，或点击任务 ID 打开“媒体任务详情”。
3. 查看“重试决策”中的动作、决策原因、重试预算、总重试次数、下次重试和执行期限。这部分无需额外打开记录开关。
4. 需要比较多次执行时，在“账号尝试与对账”展开“尝试历史”，比较各次渠道、账号槽位、错误码、参考图配置/实际传输及对应重试决策。

任务详情中的“重试决策”显示实际动作、原因、已用预算、总预算、下次执行时间和执行期限。包括原账号重试、实际换号、本机参考图回退、容量/冷却/供应商预算等待、继续查询原任务、恢复已有结果、预算耗尽、输入/政策拒绝、未知执行待核实和管理员终止。新尝试保留对应决策及实际参考图传输方式；普通用户只获得安全的决策说明，账号和供应商诊断沿用管理员权限。决策随状态转换持久化，派发标记与尝试记录一并提交，进程中断后仍能区分准备失败与已派发请求。

历史任务只显示当时已经保存的数据。旧版本缺少决策时，升级不会推测或补造“当时为什么没有重试”。界面“重试预算”显示“—”时，应结合动作及期限判断：原任务轮询按执行期限约束，不能把“—”解释为无限重试。阶段、规则及完整供应商诊断可通过下方管理员任务详情接口读取。

打开 `/system-settings/operations/images`，选中“图片运行配置”，将“失败请求保留时间（小时）”填为 `24`，点击本卡片底部“保存”。出现“已保存”后刷新页面，确认读回值仍为 `24`。填 `0` 可关闭新失败请求的保留；其他值须为 `0–168` 的整数。

##### 四个新增运行参数的填写方式

图片运行设置中的新增参数如下；高级 JSON 与普通表单均可配置。旧配置省略这些字段时继承默认值，显式 `0` 保留关闭语义。

| 中文输入框 | JSON 字段 | 默认值 | 可配置范围与含义 |
| --- | --- | --- | --- |
| 失败请求保留时间（小时） | `failed_request_retention_hours` | `24` | `0–168` 小时；`0` 关闭新失败请求保留 |
| 账号冷却时间（秒） | `account_cooldown_seconds` | `60` | `0–3600` 秒；`0` 关闭账号冷却 |
| 供应商重试容量 | `supplier_retry_capacity` | `10` | `0–1000` 个令牌；`0` 关闭供应商重提交预算 |
| 供应商重试补充周期（秒） | `supplier_retry_window_seconds` | `60` | `1–3600` 秒；令牌桶在该时段补满容量，不能填 `0` |

只调整这四个字段时直接使用普通输入框即可。使用 JSON 的入口是同一卡片的“高级运行设置”→“完整运行配置”；展开后保留已有完整配置，仅修改对应字段，最后点击“保存”。以下是**需要合并的字段片段**，不能用它整体替换完整运行配置，也不能只用它作为运行配置更新接口的请求体：

```json
{
  "failed_request_retention_hours": 24,
  "account_cooldown_seconds": 60,
  "supplier_retry_capacity": 10,
  "supplier_retry_window_seconds": 60
}
```

高级区域的“运行时字段说明”可核对当前 JSON 值和字段含义。编辑器只接受严格 JSON，不支持注释；在展开 JSON 后再次编辑普通输入框会退出当前 JSON 草稿，因此一次保存选择一种编辑方式。保存值写入数据库的图片运行配置，后续任务执行读取新值；正在执行的这一轮仍使用已经读取的配置。四个字段省略时继承默认值，不代表关闭。

**失败请求诊断。** 新进入 `failed`、`expired` 或 `execution_unknown` 的任务在开启保留时继续保存既有请求密文，写入独立截止时间。沿用 `ASYNC_IMAGE_PAYLOAD_KEYS` / `ASYNC_IMAGE_ACTIVE_KEY_ID` 的认证加密信封和 `task:<task_id>` 绑定，不新增明文请求日志。成功和管理员终止继续立即清除请求；已经丢失请求的历史任务不会补造内容或自动复活。`storage_failed` / `billing_failed` 保存的已成功结果用于恢复，不受失败请求短期清理误删。

管理员在详情中展开“查看保留请求”才访问 `GET /api/admin/async-image-tasks/:task_id/request`，要求既有异步图像任务读取权限。返回只读白名单：脱敏提示词、模型、基本规格、参考图数量以及原始提示词字符数/字节数；最多展示 65536 个提示词字符，并注明是否截断。不会返回参考图 URL、内嵌图片、原生请求体、渠道凭据、计费快照或完成响应。响应禁止缓存；达到短期截止时间或正常任务过期时间立即拒绝读取，之后的清理批次移除密文，账务与审计记录保留。关闭保留仅影响新终态任务，已经记录的截止时间仍生效；旧加密密钥需保留到其请求及现有恢复记录不再需要解密。

| 继承全局设置 | 空值，保存时省略该字段 | 采用当前平台的默认模式；适合统一管理 |
| 上游拉取 URL | `passthrough` | 把外部参考图 URL 交给上游读取；适用于供应商要求 URL 或其拉取能力正常的渠道 |
| 服务器下载 | `local` | 网关先下载校验，再以内嵌数据/文件传输；适用于上游拉取经常失败且网关能访问图片的渠道 |
| 上游拉取失败后转服务器下载 | `passthrough_fallback_local` | 先交给上游拉取，可恢复的参考图故障触发既有本机回退规则；适用于需要保留正常透传并处理拉取超时的渠道 |

要把“上游参考图拉取超时后转本机下载”限定在某个渠道，直接在该渠道选择“上游拉取失败后转服务器下载”。要统一修改平台默认值，进入 `/system-settings/operations/images` → “图片运行配置”，修改 `openai · 参考图传输方式` 或 `gemini · 参考图传输方式` 并保存。代码默认 OpenAI 为 `passthrough_fallback_local`，Gemini 为 `passthrough`；已经保存的自定义值优先。渠道显式选择模式优先于平台默认值。

排查 JSON 时，这个字段位于渠道的 **`setting`（单数）** 对象中；接口中该对象采用 JSON 字符串存放，其他已有字段需保留。下面是该对象中的字段片段，不是完整渠道更新请求：

```json
{
  "image_reference_transport_mode": "passthrough_fallback_local"
}
```

**按渠道传输参考图。** `/channels` → 编辑 → 路由与映射 → 参考图传输，对应 `ChannelSettings.image_reference_transport_mode`：空字符串/未填写继承平台全局设置，`passthrough` 让上游拉取外部 URL，`local` 在网关下载校验后发送内嵌数据，`passthrough_fallback_local` 先透传并在既有回退规则内切换本机下载。SC 输入、内嵌图片、所有权校验、公网下载限制和 multipart 文件传输保留。Gemini 自定义提交模板的 `{request.image_urls}` 使用转换后的数据；本机回退后不会重新取原始 URL。尝试同时记录配置模式和实际 `remote` / `local` / `mixed` 传输；存在任意参数覆盖或自定义请求体时，实际传输保守标记为 `unknown`，避免把配置值当作已发送证据。

回退模式仍受总期限、总重试、参考图重试和换号约束；单图格式、大小、所有权或提示词错误不会通过反复下载修复。本机下载也必须能访问参考图，并通过公网地址及图片校验。要确认真实使用了本机数据，查看新任务的“尝试历史”中实际传输记录，不能仅看所选配置模式。

##### 4. 设置账号冷却和供应商重试预算

打开 `/system-settings/operations/images` → “图片运行配置”，填写“账号冷却时间（秒）”=`60`、“供应商重试容量”=`10`、“供应商重试补充周期（秒）”=`60`，点击“保存”，刷新确认。三项都在全局图片运行页配置；账号身份和供应商分组根据实际渠道自动产生。

**账号冷却与供应商重提交预算。** 已派发的新提交遇到明确 `605/606`，或已受理任务明确终态可恢复失败时，账号进入冷却；普通查询失败不会封锁新提交账号。冷却与渠道熔断独立，时长取配置与有界 `Retry-After` 较大者，并发较短失败不会缩短既有冷却。账号身份沿用渠道 ID 与密钥指纹；同一凭据重复配置到不同渠道时仍属于不同账号身份。存在兼容未冷却备用账号时优先选择备用，全部可选账号冷却时等待最早恢复时点。

同一供应商标识及 Base URL 来源（协议、主机、有效端口）的渠道共享 Redis 令牌桶，与密钥、模型、URL 路径和签名查询参数无关。默认最多存有 10 个重提交令牌，每 60 秒补满，使用 Redis 时间与原子脚本协调多个网关。首次提交不消耗供应商预算；只有历史已有实际派发后的新提交消耗，准备阶段未越过派发屏障会返还令牌。轮询原任务、下载结果及计费恢复均不消耗。预算不足或账号冷却时持久化等待原因，保留原请求和预扣款，不增加尝试次数/重试计数；等待继续受原生成总期限约束。原参考图、瞬时、总重试与 Gemini 换号上限同时有效。

例如，两个渠道都指向同一个供应商的 `https://images.example.com`，即使密钥、模型或 URL 路径不同，也共用这组重提交令牌；换到另一个来源或供应商标识才是另一个桶。`10/60` 表示容量 10、每秒补充约 `10/60` 个令牌，约 6 秒可补一个，60 秒可从空补满；这是允许初始突发的令牌桶，不是每个任务最多重试 10 次或固定一分钟内绝对只能重试 10 次。

要真正换号，还需在 `/channels` 建立启用的兼容备用账号，再在 `/system-settings/operations/images` → “渠道池”将其放入任务对应分组、平台、模型/分辨率的有效绑定；平台“图片策略”也须允许该请求。备用账号要支持实际模型、操作及参考图数量。高级运行设置中的 `total_max_retries`、`upstream_transient_max_retries`、`reference_fetch_max_retries`、`gemini_async_max_account_switches` 仍限制单任务提交；供应商预算不会提高这些上限。保留现有任务预算即可先观察新增控制效果。

账号冷却与“启用图片熔断”是独立控制；既有 `cooldown_seconds` 是渠道熔断冷却时间，新增 `account_cooldown_seconds` 是账号冷却时间，二者分别生效。全部兼容账号冷却或令牌不足时，在任务“重试决策”查看等待原因与下次执行时间；等待继续占用原生成期限。已有上游任务号的任务继续查询原任务，不会为绕开预算另行生成。

##### 5. 查看优化实际收益

1. 打开 `/admin/async-image-tasks`，选择任务提交日期范围，例如查看最近两天就填写对应开始/结束日期；区间不超过 31 天。
2. 查看整体效果时将“状态”设为“全部”；可按平台、模型或渠道缩小范围，并点击“应用筛选”。只筛“失败”时，统计也只覆盖失败子集。
3. 展开列表上方的“生图重试挽回统计”。它统计全部符合已应用条件的图片任务，不受当前页或每页条数影响；“更多筛选”中的媒体类型为“视频”时不显示该面板。
4. 同时查看百分比和括号中的成功数/已结束样本数，并核对完整记录覆盖率、未知执行、待处理、结果处理中及人工终止数量。分组表显示供应商、模型和最后实际派发渠道。
5. 更改筛选后再次点击“应用筛选”。“自动刷新”开启且面板展开时每 30 秒刷新；默认关闭自动刷新时，可等统计缓存满 30 秒后收起再展开以重新取数。页面顶部“刷新”当前更新任务列表和平台选项，统计有自己的查询缓存。

**恢复收益。** 管理员任务中心展开“生图重试挽回统计”，通过 `GET /api/admin/async-image-tasks/reliability` 读取完整筛选范围，忽略列表分页；时间区间必须完整且不超过 31 天，查询按批读取并有 10 秒期限。按供应商、模型和最后实际派发渠道分组，等待时清空当前渠道不会改变已派发样本的归属。

| 指标 | 分子 / 分母 |
| --- | --- |
| 已确定结果成功率 | `succeeded` /（`succeeded` + `failed` + `expired`） |
| 首轮提交成功率 | 仅实际派发一次且成功 / 有实际派发的已结束完整审计任务 |
| 重试挽回率 | 多次实际派发后成功 / 多次实际派发的已结束完整审计任务 |
| 换号挽回率 | 实际更换账号后成功 / 实际更换账号的已结束完整审计任务 |
| 本机下载挽回率 | 实际本机回退后成功 / 实际本机回退的已结束完整审计任务 |

未知执行、处理中、本地结果恢复中、管理员终止分别展示，不计入已结束成功率的分母。无样本显示“—”，接口返回 `percent: null`。精确恢复指标要求所有尝试具有新审计版本及账号指纹；旧任务仍计入总数和最终状态，不能靠历史配置猜测恢复效果。本机回退还要求之前存在远程参考图失败及本轮实际 `local` 派发；自定义请求体造成的 `unknown` 不纳入本机回退指标。准备失败后首次实际派发成功仍属于首次提交样本，不虚构额外供应商调用。页面显示审计覆盖及各恢复指标的样本数，这些是观察到的恢复结果，不能直接证明相对旧版本的因果提升或供应商费用节省；本地测试不代表线上成功率已提高。

这个面板与页面顶部综合任务成功率的分母不同。观察“换号是否有收益”时，先确认有新版本的完整尝试记录，再看“换号挽回率”；例如 `4/6` 表示 6 个已结束的实际换号样本里有 4 个最终成功，不表示全站成功率提高了 4 个百分点。

##### 入口或功能没有出现时怎么排查

| 现象 | 核对步骤 |
| --- | --- |
| 找不到四个新增输入框或统计展开入口 | 确认使用了包含本次修改的前后端版本；当前工作区修改尚未部署。然后按入口表打开对应页面 |
| 运行参数不能保存、渠道下拉框置灰或接口 403 | 核对超级管理员/图片配置权限、管理员任务读取权限、渠道敏感写权限；按上方数值范围填写 |
| “查看保留的失败请求”按钮没有出现 | 核对任务是否属于失败/过期/未知执行，失败时保留是否开启、密文是否仍存在、短期和正常保留期是否已到；历史已清除请求不会恢复 |
| 已配置回退，仍没有本机下载 | 查看该任务“重试决策”和实际传输；确认渠道没有显式覆盖为纯透传、错误属于可回退故障且预算/期限仍可用。内嵌图和绑定图原本就采用本机读取 |
| 失败后没有换号 | 核对有效渠道池是否有支持同一平台/模型/分组/参考图数量的备用账号，以及账号冷却、Gemini 换号上限和总预算；未知执行和输入/政策错误不会自动重生 |
| 提示 `Your prompt cannot exceed 10000 characters` | 新版本按输入错误 `604` 处理；在保留诊断里检查原提示词字符数/字节数，按该上游限制减少实际提示词。系统不自动截断提示词，换同限制账号不能解决输入长度 |
| 挽回率是“—”或完整记录覆盖很低 | 当前筛选内可能没有已结束的重试/换号/本机回退样本，或多为旧审计；核对日期、状态及新任务记录。不能用没有样本的指标证明效果 |
| 等待时间较长 | 在“重试决策”核对账号冷却或供应商预算等待和下次执行时间；四个全局控制不会取消原总期限或释放仍待执行的预扣款 |

##### 对应管理接口与配置落点

浏览器页面路径和 `/api/...` 管理接口是不同入口。日常操作使用前面的页面表；需要核对后端返回时，接口如下，认证及权限沿用现有管理接口。

| 方法与接口 | 用途 | 请求/响应位置 |
| --- | --- | --- |
| `GET /api/option/images` | 读取图片运行、存储、策略和池配置 | 四个新增运行值在 `data.runtime` |
| `PUT /api/option/images/runtime` | 保存图片运行配置 | 请求体为修改后的完整 runtime 对象，保留其他字段，不包外层 `runtime` |
| `GET /api/admin/async-image-tasks/:task_id` | 读取管理员图片任务详情 | `data.task.retry_decision`、`data.task.attempt_history`、保留可用性及截止时间；渠道和供应商诊断仅管理员可见 |
| `GET /api/user/async-image-tasks/:task_id` | 读取当前用户自己的图片任务详情 | 安全的 `data.task.retry_decision`，不提供管理员保留请求入口 |
| `GET /api/admin/async-image-tasks/:task_id/request` | 读取保留请求诊断 | `data.request` 为只读脱敏白名单，`data.retain_until` 为截止时间；过期/不可用返回 404，解密失败返回 503 |
| `GET /api/admin/async-image-tasks/reliability` | 读取完整范围收益统计 | `data.totals`、`data.groups`；使用与任务列表相同的日期和业务条件，不使用分页 |

例如要核对 2026-10-12 至 2026-10-13 提交的图片任务，管理员统计请求路径为：

```text
/api/admin/async-image-tasks/reliability?start_date=2026-10-12&end_date=2026-10-13&timezone=Asia%2FShanghai
```

启动迁移仅为 `async_image_tasks` 添加可空 `retry_decision` 文本、`request_retain_until` 整数及保留期索引，不新增请求表。历史记录截止时间为空/零，不改变既有状态、账务和幂等唯一性。真实 SQLite、MySQL、PostgreSQL 的新建、基线升级、重复迁移和诊断查询验证详见 [2026 年 10 月变更台账](10-2026年10月代码变更台账.md#2026-10-13重试审计与恢复收益优化)。

#### 渠道级上游异步解析

- 渠道 `settings` 可选配置 `upstream_async.profiles`，按图片类型、映射后的上游模型和 `generate`/`edit` 操作选择唯一规则。模型数组为空代表该渠道全部上游模型；重叠选择器、图片 `extend`、非法受限 GJSON 路径或超过 32 条规则会在保存时拒绝。
- 首次提交默认仍由原图片适配器构造请求并执行计费准备。若命中规则配置了 `submit.request`，可改用同源 POST 路径、查询参数、请求头和 JSON 模板提交；宿主随后从 `submit.task_id_path` 提取字符串或数字任务号并立即持久化。后续 Worker 只查询同一上游任务，不会重新发起生成；`execution_unknown` 仍作为禁止自动重提的屏障。
- worker 在实际发出提交请求后会更新任务版本；收到上游任务号时，保存操作会读取当前租约中的最新任务版本，避免旧版本快照导致数据库拒绝任务号持久化。重复返回同一任务号保持幂等，不同任务号会被拒绝。
- 带参考图但从公开 `generations_async` 提交的请求，即使内部适配器使用图片编辑路径，也保持 `generate` 操作选择渠道规则；公开 `edits_async` 仍选择 `edit`。
- 已保存成功响应的图片任务在下载结果时遇到网络或读取中断，按独立存储预算恢复下载，不会重新提交生成；无效图片或不合法结果 URL 停止自动重复，保留恢复和终止入口。
- 查询支持同一渠道 Base URL 下的 GET/POST、查询参数、JSON 请求体和请求头模板，占位符限于 `{task_id}`、`{model}`、`{upstream_model}`、`{api_key}`。状态值按 JSON 字符串、数字、布尔类型精确匹配；未知或缺失状态进入既有轮询失败计数，不会默认为处理中。
- 查询 HTTP 跳转只允许与渠道 Base URL 相同的协议、主机和有效端口，并继续执行原 HTTP 客户端的跳转限制；跨源目标、含用户信息或片段的目标不会被请求，渠道凭据不会随跳转发出。同源跳转最多 10 次。提交、查询及下载头的模板值按一次替换写入，值中恰好出现 `{model}` 等文字时保留为原值，不再次解释。
- 成功结果可从一个字符串或字符串数组读取，最多 `dto.MaxImageN` 张。优先按现有安全下载、校验、staging 和存储链路落盘，成功落盘后公开任务返回本地结果 URL；配置了凭据下载头时结果必须与渠道同源，跨域地址只能匿名下载。
- 结果下载的连接中断、响应体读取中断、HTTP 408、429 和 5xx 在独立存储预算内消费已保存响应并再次下载，不重复生成。HTTP 403/404、图片格式损坏、超出大小或像素限制不会作为瞬时网络错误重试。已有成功响应不再受生成提交预算或生成总期限限制，本地处理仍有单次期限。下载重试耗尽后按下面的公网直链条件决定是否完成任务。
- 当结果 URL 是渠道同源且配置了下载凭据时，可跟随其 HTTP 跳转到公网 CDN；跨域请求会移除下载头，并按公网地址与重定向限制重新校验。动态上游图片的可重试下载故障耗尽存储预算（兼容旧任务的瞬时/总预算计数），且该规则未配置下载头、全部结果均为公网匿名 HTTP(S) URL 时，以原上游链接进入正常结算。结算和消费日志完成后任务为 `succeeded`，公开查询返回 `data[].url` 和 `result_source: "upstream"`；统一媒体查询另返回 `storage_status: "upstream"`，任务详情的产物标记 `source: "upstream"`。
- 公网直链回退使用原任务冻结的价格与分组倍率，按实际返回的链接张数结算。按 Token 计价时只使用有效实际用量，缺失用量仍按既有规则失败；按规格的表达式使用原请求尺寸/清晰度，不虚构无法下载验证的实际宽高。账单和消费日志注明 `result_source: "upstream"`、`image_billing_specification_source: "request"`。显式零价任务成功后为 `billing_status: "not_billable"`。
- 余额不足、缓存刷新失败或消费日志失败时进入原有计费恢复流程，结算完成前查询和详情不公开结果链接。恢复复用已固定的产物清单和账单，不重新调用上游生成，也不会再次增加已成功扣除的费用。回退结果不创建本站存储对象或自动归档；图库仍要求落盘并校验，下载成功时优先返回本站签名链接。
- 上游已接单后的重复轮询不再逐次追加 `claimed`、`channel_selected`、`upstream_pending` 等阶段事件或同一渠道尝试；收到结果只创建一条 `upstream_result_received` 记录，再次得到结果时原位更新 URL，详情不显示其中的原始链接文本。已投递的旧轮询 outbox 命令在生成下一条命令时删除，避免长期轮询持续扩大表大小。历史任务的重复阶段仅在详情展示时折叠，历史数据库记录不自动清除。
- 已结束且超过 `expires_at` 的图片任务，用户和管理员详情均不再返回上游回退 URL；公开查询继续返回 404。上游 URL 自身的可用期与本站任务保留期分别生效，处理中任务保持原有访问规则。
- `usage_paths` 只能映射到现有 Usage 数值字段及 token detail 字段。按次或按张计费可沿用冻结估值；Token 计费必须在最终响应得到有效实际用量，否则在独立账单预算内重查已完成的原上游任务，不泄露结果、不重新提交，仍缺失时以 `billing_usage_missing` 暂停为 `billing_failed`，保留预留和恢复入口。
- 命中规则的渠道只参与 `/v1/images/generations_async`、`/v1/images/edits_async` 和统一媒体异步入口；同步图片接口会排除这些异步专用匹配，避免把任务号回执解释为图片结果。未匹配规则的渠道行为完全不变。

成功回退新增 `async_image_tasks.result_source` 可空字符串列，由正常启动迁移创建。历史本地产物任务保持空值及原存储链路；历史已失败且未结算任务不自动改为成功或补扣。结果 URL 继续保存在单条既有结果里程碑中，结算完成前隐藏原始链接，轮询不增加结果事件行。

#### Gemini 上游失败诊断

- Gemini 异步请求遇到非 200 响应时，在通用兼容错误归一化前读取有界的原始错误对象；任务公开失败说明保留经过 URL、凭证和长度处理后的 `error.message`，不再把详细的 HTTP 400 一律替换为 `Invalid request` 或固定概述。
- 611、612、613 分类同时使用脱敏消息、供应商 `error.code` 和 Gemini canonical status，分别识别参考图数量超限、缺少参考图以及提示词或输入图无法处理；未知 400 仍保持 610 兜底。
- 每次失败尝试在既有任务尝试快照中保存 HTTP 状态、脱敏错误、供应商 code/status 和上游 request ID；结构化诊断只进入管理员任务详情，普通用户不会获得渠道、账号或上游 request ID。

#### 参考图传输、校验与重试

- OpenAI 异步入口对新提交的 multipart 编辑请求保存输入格式；当渠道没有指定其他编辑格式时，执行阶段继续发送 multipart 文件。同步可用的文件上传格式不再被异步链路强制替换为 JSON/data URL。文件扩展名和 MIME 与实际 PNG、JPEG、WebP 内容一致，mask 与图片分开传递。历史已排队任务没有保存输入格式，升级不会反推原始格式；需要保留 multipart 的旧任务应重新提交。
- `_oa` multipart 中的 `watermark=false` 保留布尔类型；掩码不计入参考图数量限制，因此达到最大参考图数量时，mask 放在图片前后具有相同校验结果。JSON 参考图仍规范化为 `images[].image_url`；“上游拉取 URL”模式保留外部 URL 及查询参数，不会自动变成本地下载。
- OpenAI 兼容渠道的异步非成功 HTTP 响应现在与 Gemini 共用有界、脱敏的错误读取逻辑。公开失败说明保留有效 `error.message`；管理员详情接口的 `attempt_history` 保存实际 HTTP 状态、供应商 code/status 和 request ID。渠道配置的状态码映射继续影响重试分类，但不覆盖记录的真实 HTTP 状态；正文无法解析时保留通用错误，不公开原始 HTML 或完整响应体。现有前端尝试列表尚未展示全部诊断字段，可通过管理员详情接口查看。
- Gemini 的 `passthrough_fallback_local` 在首次执行时把普通外部 HTTPS URL 作为 `fileData.fileUri` 交给上游拉取，不会先在本服务器下载。SC 输入、`data:` 内嵌图和显式 `local` 模式仍由服务器读取。上游明确返回参考图拉取失败时会进入本地下载重试；对于部分 Gemini 兼容渠道返回的模糊 `400 / INVALID_ARGUMENT`，仅当首次请求确实含远程 `fileData`、错误分类为安全策略/未知错误/输入无法处理且总重试预算仍可用时，额外允许一次本地传输回退。数量超限、缺图和参数错误不会触发该回退，原始脱敏 provider code、status 和错误说明仍保存在尝试审计中；若本地重试成功，任务顶层的旧错误码和错误说明会被清空。
- 参考图合计字节数和合计像素数不再单独设限；每张图仍受 `download_max_bytes`、`download_max_pixels` 约束，请求仍受 `max_reference_images` 约束。这意味着任意一张超过单图上限的图片仍会被拒绝。
- PNG、JPEG、WebP 必须具有可完整解析的容器并能再次完整解码。终止标记后的尾随数据只有不超过 4 KiB 时才会被裁剪，后续哈希、缓存和上游内嵌传输均使用裁剪后的规范数据；更大的尾随区或损坏容器继续拒绝，不会直接放开 trailing data。
- 本地下载或校验错误使用从 1 开始的参考图序号，例如 `Reference image 3`，错误文本不包含原始签名 URL。图片格式、容器、MIME、单图字节数或单图像素数错误归为不可重试输入错误，避免同一坏图重复下载；网络、临时 HTTP 和读取失败仍可按参考图重试策略收敛。

- 查询区仅常显“搜索任务”“平台”“状态”和“日期范围”，桌面宽屏排列为一行，手机端按两列紧凑排列。日期摘要与起止日期统一在同一个日期范围控件中，点击即可选择日期或今天、近 7 天、本周、近 30 天、本月；日期不再散落在高级查询及操作行。起始日期晚于结束日期时不能确认。日期和其他查询条件先保留为草稿，点击“应用筛选”才更新列表；“重置”清空附加条件并恢复当天日期。

- “平台”下拉框常显在桌面查询区域，折叠高级条件时仍可操作；手机端直接放在搜索表单中，不必打开筛选弹窗。选项来自现有渠道模型声明的图像能力和已绑定的视频插件，自动去重，不限于 Gemini / OpenAI；没有配置渠道的平台不显示，已停用但仍保留配置的渠道仍列出，便于筛选历史任务。选项独立加载，不受当前页任务、日期、状态或关键词限制，点击“刷新”会重新读取渠道配置。

- “搜索任务”支持输入完整或部分任务 ID、模型名称、图像规格（请求分辨率、请求尺寸、实际尺寸、宽高比）或提示词；例如 `2K`、`1024`、`16:9`。管理员页面另支持渠道名称模糊匹配，普通用户只查询自己的任务且不参与渠道名称匹配。图像、视频任务的模型及任务 ID 均支持部分匹配，高级筛选的模型名称也使用模糊搜索。搜索忽略英文大小写、去除首尾空白，将 `%`、`_`、`!` 作为普通字符。日期、状态等条件仍共同生效，默认日期范围为当天；查询历史任务时需调整日期范围。搜索结果、分页总数和统计使用相同条件。

- 手机端搜索、统计和任务列表共同滚动，查询条件不再固定占据列表上方。点击“更多筛选”在弹窗中设置附加条件，字段单独滚动，关闭、重置及应用按钮保持可操作；应用后自动关闭弹窗并回到第一页，关闭后再次打开会保留未应用的草稿。手机端使用精简的上一页、下一页分页；桌面端继续使用筛选面板和表格滚动。

- 手动“刷新”显示转动图标，并在任务列表和平台选项请求期间禁用，避免重复点击；两个请求成功或失败结束后都恢复按钮。

### 从零配置异步图片

按以下顺序配置，每一步单独保存。图片和视频共用“媒体设置”页面，但有各自的运行开关与存储表单。

| 顺序 | 菜单与页面 | 填写和保存方式 |
| --- | --- | --- |
| 1 | 部署环境 | 配置可用 Redis、稳定的 `ASYNC_IMAGE_PAYLOAD_KEYS`、匹配的 `ASYNC_IMAGE_ACTIVE_KEY_ID` 和媒体签名密钥 `CRYPTO_SECRET`。环境变量格式、32 字节 Base64 密钥生成、Compose 注入和重启方式见[视频页的运行依赖](05-异步视频与统一媒体任务.md#1-准备运行依赖)，图片使用同一套依赖；仅图片原生适配器不要求启用视频任务插件。 |
| 2 | 渠道管理 `/channels` → 新建或编辑 | 选择实际图片供应商对应渠道类型，填写 Base URL、API Key、允许的模型与分组并保存。模型别名同时配置映射；不要把示例渠道 ID 或域名当真实配置。 |
| 3 | 系统设置 → 运营设置 → 媒体设置 `/system-settings/operations/images` → 图片运行 | 启用异步图片，设置 worker 数、图像并发、租约、执行期限、参考图上限及重试预算，点击本卡片保存。高级配置只接受标准 JSON，字段解释在编辑器外部。 |
| 4 | 同页 → 图片存储 | 配置用于图片的存储档案并启用所需用途。选择本地目录时确保实例可读写且容器目录有持久卷；对象存储按实际 endpoint、bucket 和凭据配置。图片存储与“视频配置”中的 `local_path` 分开保存，多实例须能读取实际处理节点生成的产物。 |
| 5 | 同页 → 图片策略 | 为请求实际使用的分组和平台启用平台策略及异步能力。按平台“模型能力”示例填写真实模型 ID、输出张数、参考图数量、尺寸等能力后保存；模板只供参考，不能扩大上游支持范围。 |
| 6 | 同页 → 渠道池 | 使用同一分组、平台、模型和策略指定的绑定方式，从联动选项选择可用渠道后保存。采用“模型和分辨率”时逐项覆盖需要售卖的档位；空渠道列表表示关闭绑定。 |
| 7 | 系统设置 → 计费与支付 → 模型定价 `/system-settings/billing/model-pricing` → 模型价格 | 由超级管理员配置该客户端模型的图片价格并保存。图片适配器表达式与视频任务的 `u("seconds")` 语法不同，以该模型编辑器的字段为准。核对分组倍率、张数和尺寸/清晰度倍率；已有服务方专属价格时检查它是否覆盖默认价。 |
| 8 | API 令牌与图像工作台 `/image-workbench` | 令牌的分组、模型和图片平台权限须覆盖上述配置；用户钱包或订阅及令牌额度应足以预留本次费用。先提交一张图，使用返回的任务 ID 查询到完成，再检查实际账单与产物。 |

标准供应商的内置异步解析能工作时，不必填写渠道级上游规则。非标准接口再进入“渠道管理 → 编辑 → 路由与映射 → 上游异步任务 → 配置上游异步”，媒体类型选“图片”，模型填**映射后的上游名**，操作选生成或编辑，完整配置提交任务号、轮询、状态及结果路径。自定义首次请求同时适用于 Gemini 原生图片；不填写 `submit.request` 则保留内置请求。弹窗“保存更改”只更新草稿，还须点击渠道页“更新渠道”。完整图片单结果、多结果和 Mai Token 示例见[渠道扩展设置](08-渠道扩展设置.md)。

### 删除图片策略与渠道池绑定

| --- | --- | --- |
| 图片策略 → 删除 | 该分组与平台的一整条策略，包括模型能力目录 | 保留渠道池绑定和实际渠道。OpenAI / Gemini 对应策略缺失时，该分组不再提供这条平台策略的模型能力；其他供应商可能按既有规则继承所属协议平台的策略。后续能力查询使用最新配置 |

#### 前端配置示例：preview 与 nano-banana

以下使用分组 `default`、平台 `gemini`，并假设没有模型映射。实际使用 `nanobanana` 等其他分组时，替换为该分组并分别保存对应策略和渠道池；不能只配置 `default` 后期待其他分组自动继承。

1. **确认渠道已启用。** 在 `/channels` 的 Gemini 渠道中加入 `gemini-2.5-flash-image-preview` 和 `gemini-nano-banana-2.1`，确认渠道属于实际使用的分组，保存渠道。
2. **保存 Gemini 图片模型声明。** 打开 `/system-settings/models` → Gemini，在“支持的 Imagine 模型”中保留已有需要的名称，补入这两个名称，点击保存。该字段是 JSON 字符串数组，不是逗号分隔文本。下面示例保留代码默认的七项，再加入两个目标名称；如果当前配置还有其他自定义模型，也要保留。

   ```json
   [
     "gemini-2.0-flash-exp-image-generation",
     "gemini-2.0-flash-exp",
     "gemini-3-pro-image-preview",
     "gemini-3-pro-image",
     "gemini-2.5-flash-image",
     "gemini-3.1-flash-image",
     "gemini-3.1-flash-image-preview",
     "gemini-2.5-flash-image-preview",
     "gemini-nano-banana-2.1"
   ]
   ```

   这只是配置格式与名称示例，不表示供应商实际提供所有列出的模型。

3. **核对图片策略的准确 ID。** 打开 `/system-settings/operations/images` → 图片策略，编辑 `default` / `gemini` 的现有策略，在“模型能力”中检查两个模型。若原条目写的是不带后缀的名称，按下表修改后保存；已有 `gemini-nano-banana-2.1` 条目可保留，不要重复添加。如果两个 2.5 名称都是实际需要提供的模型，则保留原条目，另加 preview 条目。

   | 字段 | 原条目示例 | 本次目标名称 |
   | --- | --- | --- |
   | `id` | `gemini-2.5-flash-image` | `gemini-2.5-flash-image-preview` |
   | `label` | `gemini-2.5-flash-image` | `gemini-2.5-flash-image-preview` |

   筛选依据是 `id`；`label` 是显示名称，单改 `label` 无法放行模型。按供应商实际支持保留或调整分辨率、输出张数、参考图数量等属性，不能把通用示例中的规格直接视为供应商支持范围。启用平台策略与异步能力；本例策略的渠道池模式使用“模型与分辨率”。

4. **重新加载并保存渠道池绑定。** 保存上面两处配置后，刷新或重新进入媒体设置，在“渠道池”选择同一分组 `default`、平台 `gemini`、绑定方式“模型与分辨率”。分别选择目标模型、上游实际支持的分辨率和提供该模型的 Gemini 渠道，然后保存绑定。本次排查对应渠道为 `#15`，其他部署应选择自己的实际渠道；需要多个规格时逐项绑定。空渠道列表表示显式关闭绑定，不能用它代替选择渠道。
5. **刷新工作台并核对 Token。** 重新打开 `/image-workbench`，选择 Gemini 平台分组为 `default` 的 Token；其模型权限须允许这两个模型。使用其他分组时，Token 的 Gemini 平台分组须与该分组的策略和渠道池对应。

使用模型别名时，图片策略填写请求使用的模型 ID，“支持的 Imagine 模型”填写映射后的上游模型名称，渠道能力也按映射后的上游名称判断；不要把显示标签当作模型映射。

### 额度预留、重试与人工核实

- 没有上游任务号时，首次执行和明确安全的重试均重新检查当前权限、渠道池、可用密钥、重试排除与熔断状态，选择的实际账号重新写入加密快照。录入后禁用或移除的密钥不会继续用于新提交；价格和分组倍率仍使用受理时的冻结账单。
- 已保存上游任务号后，只用原提交账号及冻结配置轮询同一任务。后续关闭图片策略、调整 Token IP 限制、禁用用户或软删除 Token，不会把已接单任务直接判失败退款；内部继续核实结果与结算，公开接口仍执行现行访问权限。全局或渠道容量暂满时延后轮询，不消耗生成重试次数；缺失账务预留、请求解密失败或冻结账号不可用时保留任务供核实。既有执行期限和人工终止规则仍适用。
- worker 发出生成请求前，将本次冻结估值同时写入预留账单并扣减资金源和令牌可用额度；并发任务不能重复占用同一笔可用额度。后续轮询和已知任务重试复用原预留，成功后按固定账单结算差额。上游回退链接也必须先完成结算，才对用户公开。
- 上游明确失败、已确认安全的终止或到期时，未结算预留走退款事务；已结算账单不会因后续管理终止而自动退款。账单防重，恢复与重复处理不会二次返还。订阅在预留后已重置时，旧周期预留不返还到新周期，令牌额度与累计用量仍按最终账单调整。
- 首次提交收到 HTTP 成功响应但响应体截断、过大或不可解析时，不能证明上游没有接单，任务进入 `execution_unknown`，保留预留且不自动再发生成请求。已知上游任务号的查询错误继续查询同一任务。
- 管理员进入“管理任务中心” `/admin/async-image-tasks`，核对任务详情与供应商记录，确认需要放弃本地交付后执行终止并释放预留；此操作不会撤回上游任务，也不会向供应商申请退款。普通用户不能自行释放未知执行的预留。仅因为等待较久，不应重新提交一份生成请求。
- 自动化调用管理员终止接口时，未知执行任务还须提交 JSON `{"confirm_upstream_checked": true}`；页面核实确认后会自动携带此字段。缺少确认返回冲突，防止打开普通终止弹窗后任务变为未知状态时意外释放预留。
- Alibaba `z-image` 的 `prompt_extend` 倍率使用首次提交冻结的事实；本地产物和上游链接回退保持同样的倍率，不会在最终结算时按默认 `false` 少收费。
- Redis 与批量余额更新同时启用时，预留依赖有效的热余额缓存；缓存缺失或不可用时保守拒绝，不能拿可能尚未同步的数据库余额重新放行。数据库和 Redis 不构成分布式事务，进程在缓存操作与提交之间中断时仍须核对预留账单和余额；不要直接删除余额缓存作为恢复方法。

统一 `/v1/images/generations_async` 的图片数量别名包括 `n`、`create_count`、`batch_size`、`num_outputs`、`input.num_outputs`、`parameters.n` 和 `sequential_image_generation_options.max_images`。每个显式数量均须为 `1..MaxImageN` 的整数；同时提交的别名必须相同，包括显式 `1`，不再因字段遍历顺序接受冲突值。能力限制继续按所选模型校验。

统一接口指定 `provider: "gemini"` 时按 Gemini 规则解析 `resolution: "0.5K"` 或 `size: "0.5K"`；省略 provider 时也可通过模型目录和渠道能力自动选择支持半 K 的渠道，不会在选渠道前按 OpenAI 规则拒绝。`ratio` 可作为宽高比别名。参考图、数量和原生字段继续保留，最终仍检查模型能力。SC 临时上传先验证和规范化图片，再按实际保存的字节数预留空间、建立上传意图及确认对象；可接受的短尾随数据不计入存储空间。幂等指纹仍覆盖原始上传内容、MIME 与文件名，重放须保持原始请求一致。

更新后启动迁移为既有图片账单表增加预留金额、预留令牌额度、预留时间、订阅周期标记和退款尝试时间。退款失败会由扫描轮转重试，单条坏账不会一直占据队首。历史没有预留标记的固定/已结算账单按兼容路径处理，不自动重复扣费。升级前备份主库，先完成迁移再启动新 worker；不要混跑不识别预留账单的旧版本 worker。

平台策略页会根据当前选择的平台展示模型能力 JSON 示例入口。弹窗中的模板覆盖 OpenAI、Gemini、Vertex AI 及其他已注册图片供应商；动态注册且没有内置模板的平台使用带平台名的占位模型。Gemini 原生模型示例固定 `max_output_images` 为 `1`，Imagen 示例固定 `max_reference_images` 为 `0`。管理员应把模型 ID、可选能力和数量限制调整为渠道实际上游支持的值，再一键复制到“模型能力”输入框；示例只用于参考，不会自动覆盖当前表单。

渠道编辑页的“路由策略”可设置“最大参考图数量”。未设置的历史渠道按 8 张兼容；异步任务包含超过 8 张参考图时，自动平台策略解析会先比较渠道容量，最终渠道选择则在硬性能力、账号和熔断过滤之后优先保留容量覆盖本次请求的候选，再按池内权重抽选；没有显式渠道池时按渠道全局优先级和权重选择。若当前候选没有任何渠道覆盖该数量，则保留原有候选继续调度而不是直接拒绝。图像运行配置的全局默认 `max_reference_images` 与平台策略中的参考图模型能力示例均调整为 14；模型自身能力仍会在接入校验阶段独立限制请求。

渠道编辑页同时提供“上游异步任务”入口。结构化视图覆盖媒体类型、模型、操作、任务号路径、查询请求、状态集合、进度、失败原因、结果和用量路径，高级 JSON 视图可编辑完整配置；页面会显示“内置解析”或“渠道覆盖”，并提供图片多结果与视频单结果示例。保存仍写入原有渠道 `settings` JSON，不新增数据库字段或迁移。

提交请求新增“默认 / 自定义”选择。自定义模式可配置 POST 路径、查询参数、鉴权头和 JSON 请求体，并提供 Mai Token 生图示例：`media_type` 保持 `image`，上游提交路径为 `/v1/videos`，查询结果的 `video_url` 按图片结果处理。其请求体示例将已校验的图片数量映射至 `create_count`，把参考图 URL 数组映射至 `image_urls`；供应商要求可访问的外部 URL 时，应使用上游可拉取的图片地址。详细配置见 [渠道扩展设置](08-渠道扩展设置.md)。

`ChannelOtherSettings` 顶层字段、`upstream_async` 各子字段、状态值规则、Usage 路径和完整可复制示例见 [渠道扩展设置](08-渠道扩展设置.md)。

全局 `max_reference_images` 已显示在图像运行设置的普通数字表单中，范围为 1–128，不再要求管理员打开高级 JSON 才能修改。工作台能力接口返回模型策略上限与全局上限的较小值，避免页面允许选择的数量在提交时又被全局配置拒绝；请求解析也不再根据模型名把 Flash 图片模型隐藏地硬编码为 3 张，具体模型上限以平台策略为准。高级运行设置使用带格式化与合法性状态的严格 JSON 编辑器：标准 JSON 不支持 `//`、`/* ... */` 或字段后注释，加入这些注释会导致保存解析失败。编辑器下方提供可折叠的“运行时字段说明”，逐项显示全部运行字段、用途和当前值；说明位于 JSON 外部，因此不会破坏配置语法，并已同步 en、zh、zh-TW、fr、ja、ru、vi 七种语言。

渠道池不再要求管理员手工填写模型名或逗号分隔的渠道 ID。设置页通过 `/api/option/images/pool/options`，按当前分组和平台列出平台策略允许、渠道能力支持且状态已启用的模型与渠道；选择模型后渠道列表进一步收窄，并以“渠道 ID + 渠道名称”展示。点击已有绑定的“编辑”会自动回填分组、平台、绑定方式、模型、分辨率、渠道和权重；已经失效的旧值仍会标记为不可用，必须改成有效选择后才能保存。保存接口会再次校验模型是否属于当前分组和平台，并逐一校验渠道与模型是否匹配，避免绕过前端写入无效绑定；空渠道列表仍表示显式关闭有效绑定。

相关权限包括：

- 异步图像任务读取和管理。
- 图像内容审核读取和管理。
- 图像配置读取和管理。

前端为新增功能补齐 en、zh、zh-TW、fr、ja、ru、vi 七种语言。
