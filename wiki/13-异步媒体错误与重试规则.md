# 异步媒体错误与重试规则

变更日期：2026-11-01（Asia/Shanghai）；提交日期、提交哈希：待提交；实现基线 `9a3d86e5b34e8437e188b92dd6260893717b5066`。本次只在本地实现和验证，未发布、激活生产插件或修改线上配置。

## 后台使用

入口：系统设置 → 运营设置 → 错误与重试规则，路径 `/system-settings/operations/retry-policy`。规则管理、错误样本、版本记录在同一配置中心切换，沿用媒体配置读写权限。

1. 从管理员任务详情的当前错误或某次尝试选择“以此错误创建规则”，生成限定媒体类型、插件、模型和阶段的草稿。
2. 输入规则名称、分类、包含关键词和排除关键词；需要时设置 HTTP 状态、上游错误码、正则及源渠道范围。
3. 按顺序设置动作、次数、等待时间与退避方式。目标允许／排除渠道用于执行选路，与错误来源渠道条件分开。
4. 测试当前草稿，核对命中及阻止原因；保存成功后生效。版本冲突保留草稿，重新加载必须由管理员主动操作。

例如：参考素材读取失败 → 本机下载后原渠道一次 → 本机下载后换渠道两次 → 转人工核对。新的失败会重新匹配当次错误；第一次素材错误不会把后来的参数错误也当成素材问题。

## 匹配与预算

条件之间为“且”；关键词支持任意包含、全部包含；排除优先，默认忽略英文大小写。自定义规则按显示顺序取第一条命中，未命中继续现有内置策略。命中规则耗尽后执行结束动作，不尝试低优先级规则绕过预算。分类只是展示标签，不能改变已受理、结果未知、已获得产物等事实。

关键词只匹配脱敏错误诊断，不扫描请求正文、提示词或签名素材链接。高级正则由 Go 正则实现执行，保存时校验表达式、数量和大小，不支持脚本。

规则与步骤具有稳定 ID。编辑、排序、停用后重新启用和版本回滚都保留任务累计用量；复制规则具有新 ID，但仍受任务总次数、期限、原预扣、渠道权限和供应商容量限制。排队不等于已发送，实际动作开始时才累计步骤次数。

## 动作与保护

| 动作 | 含义 |
| --- | --- |
| 原渠道重试 | 固定当前失败渠道，按现有规则选择可用账号 |
| 换渠道重试 | 排除当前失败渠道，在当前有权限的兼容池中选择 |
| 本机下载后原渠道／换渠道 | 下载并验证参考素材后提交，后续步骤复用任务保留的素材 |
| 继续查询原任务 | 使用已有上游任务号查询，不创建新生成 |
| 重试下载／保存 | 只处理已成功产物 |
| 重试结算 | 只恢复已有产物的账务确认 |
| 停止／转人工 | 已确认失败可停止；未知受理和已成功产物保留核对或恢复边界 |

新规则不能把超时、断线、HTTP 文本命中当作“未受理”证明。有任务号时查询原任务，无法确认时保留预扣并转人工；已经有结果的任务不会重新生成。不支持的动作记录阻止原因。

首次迁移保存已启用的旧超时兼容范围和预算，管理员可以查看和关闭。之后新建的范围不会自动继承该例外。“暂停自动重新提交”仅暂停新的替代生成；原任务查询和必要的账务恢复继续进行。关闭单条规则意味着重新评估其他有效策略，不等于全局暂停。

## 即时生效与记录

每次错误判断和实际重提交前读取主库当前配置，仅缓存编译结果。运行中任务下一次判断使用新版本；已发送请求继续执行；已经失败、完成的历史任务不被自动重启。主库配置不可读时阻止新的重提交。

保存携带 `revision`，缺版本或过期版本明确拒绝。当前配置与完整版本快照在同一事务内提交；回滚生成新版本。通用 option 接口不能直接改写该配置绕过校验。

错误样本按脱敏指纹聚合，支持媒体、插件、模型、渠道、阶段、分类和是否命中筛选。展示出现次数、涉及任务、执行次数及后续任务结果；“后续成功”是观察结果，不表示每次成功都由规则造成。任务内部诊断仅管理员可见。

测试与真实执行共用决策器，不调用供应商、不扣款。只有错误文本时仅说明文字命中，不能据此承诺动作可执行。样本测试使用记录的执行事实，并合并任务当前累计用量、权限与候选渠道；同一次尚未派发的预留次数不会在预览中重复扣算。当前内置策略与历史实际动作分开展示；早期没有宿主协议证据的记录不根据错误文字重建受理事实。批量测试展示当前筛选页样本的覆盖及逐条决策，可检查典型误匹配。

决策事件与任务状态变更在主库事务内记录，唯一事件标识用于去重。事件默认保留 90 天，配置版本长期保留；清理事件不删除任务自身的预算及恢复状态。

## 视频与参考素材

视频换渠道保留公共任务 ID，每次尝试分别记录执行渠道、上游 ID 和代次。候选必须通过同插件、版本、请求能力、模型映射及冻结计费条件检查；旧轮询和迟到结果不能覆盖新尝试。

计费归属固定为原预扣渠道，价格沿用冻结快照；执行渠道可以变化。消费、退款和渠道累计用量统一使用原计费归属，最终账务幂等，重试不产生第二次预扣。

视频响应同时出现“失败”和成片、受理状态或其他任务 ID 时，按矛盾结果核对原任务；即使原请求密文已不可恢复，也不因此重新生成或自动失败退款。派发前重新检查用户、Token、自动分组、模型和渠道权限。视频结算恢复通过查询原任务取得已确认用量，不创建新的生成任务。

插件可通过可选 `meta.videoRetryInputs` 声明规范化请求中的 URL 素材槽和类型；宿主冻结槽位上下文中的角色，下载后只替换指定位置。数组槽位保留顺序；私有文件 ID、无法重放的上传等场景明确受限。下载继续执行原地址、重定向、大小及有效期校验。

图片本地参考素材逐槽保存在任务的加密请求中，部分下载完成后中断也可复用；换渠道不会退回原始远程链接。继续检查绑定所有权、素材有效期及任务期限，并受图片待处理容量、加密请求大小上限和 MySQL `max_allowed_packet` 限制。视频素材保留原槽位及角色，已适配仓库内 14 个支持 URL 素材的视频插件。
